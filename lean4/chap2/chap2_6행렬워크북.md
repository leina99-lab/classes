# I — 행렬의 언어

## 행렬의 정의

먼저 가장 단순한 정의부터 본다.

> **정의 1.** 행렬(matrix)이란 숫자를 직사각형으로 배열한 것이다. m개의 행(row)과 n개의 열(column)을 가진 행렬을 m × n 행렬이라 한다.

구체 예로 본다.

```
     ⎡ 1    9   −13 ⎤
     ⎣ 20   5    −6 ⎦
```

이것은 2 × 3 행렬이다. 2행 × 3열이다. 행의 수를 먼저, 열의 수를 나중에 말한다는 약속이 있다. "**2 × 3**"이지 "**3 × 2**"가 아니다. 이것이 행렬의 크기를 말하는 표준 방식이다.

각 숫자를 **성분**(entry)이라 부른다. i행 j열의 성분을 aᵢⱼ라 적는다. 첫 번째 아래첨자가 행, 두 번째 아래첨자가 열이다. 위 행렬에서 a₁₁ = 1, a₁₂ = 9, a₁₃ = −13, a₂₁ = 20, a₂₂ = 5, a₂₃ = −6이다.

인덱스의 순서가 "**행 먼저, 열 나중**"이라는 것이 자주 헷갈리는 부분이다. 영어로 "**row first, column second**"라고 외워두면 좋다.

## 행렬은 사실 함수이다

오늘 강의 전체의 핵심 관점이 여기에 있다. 행렬을 "**숫자의 격자**"로 보는 대신, "**함수**"로 본다. 이 관점 하나가 오늘 강의의 모든 것을 결정한다.

### 초보의 관점

행렬은 "**숫자의 직사각형 배열**"이다. 계산하는 규칙이 몇 가지 있다. 덧셈은 성분별로 하고, 곱셈은 복잡한 공식이 있고, 전치는 행과 열을 뒤바꾸는 것이다. 이 관점에서 행렬은 "**복잡한 계산 규칙의 집합**"이다.

이 관점에 머물러 있으면 행렬을 외울 것이 많은 주제라고 느끼게 된다. "**곱셈의 공식이 왜 그렇게 생겼는가?**"라는 질문에 답할 수 없다. "**왜 A × B ≠ B × A인가?**"라는 질문에도 답할 수 없다. 규칙을 외우는 것으로 그칠 뿐이다.

### 오늘의 관점

**m × n 행렬 A는 ℝⁿ에서 ℝᵐ으로 가는 선형 함수이다.**

이 한 줄이 오늘 강의의 핵심이다. 풀어서 말하면 다음과 같다. m × n 행렬 A가 주어지면, n차원 벡터 x를 받아 m차원 벡터 Ax를 돌려주는 함수가 정의된다.

A: ℝⁿ → ℝᵐ,    x ↦ Ax

여기서 "**선형**"이라는 말은 두 가지 성질을 의미한다. A(x + y) = Ax + Ay이고, A(cx) = c(Ax)이다. 즉 벡터의 덧셈과 스칼라 곱을 "**보존하는**" 함수이다. 이것이 선형 함수의 정의이다.

왜 이 관점이 중요한가? 왜 행렬을 "**함수**"로 보는가? 세 가지 이유가 있다.

첫째, 행렬 곱의 복잡한 공식이 갑자기 자연스러워진다. 두 선형 함수를 합성하는 것이 곧 두 행렬을 곱하는 것이다. (f ∘ g)(x) = f(g(x))의 공식이 행렬 곱의 공식과 정확히 일치한다. 복잡한 덧셈의 합 공식이 단순히 "**g를 먼저 적용하고 f를 나중에 적용한 결과**"를 나타낸다는 것을 알게 된다.

둘째, 행렬 곱이 비가환적인 이유가 분명해진다. 함수 합성은 일반적으로 비가환적이다. (f ∘ g)(x)와 (g ∘ f)(x)는 다르다. 양말을 먼저 신고 신발을 신는 것과, 신발을 먼저 신고 양말을 신는 것이 다르다. 행렬 곱도 같은 이유로 비가환적이다. 이 사실이 이전 강의에서 함수의 합성을 배웠을 때 이미 손에 쥔 도구였음을 알게 된다.

셋째, 행렬이 현실 세계에 무엇을 의미하는지가 보이기 시작한다. 회전은 함수이다. 확대와 축소도 함수이다. 양자역학의 측정도 함수이다. 이 모든 것이 행렬로 표현된다. 행렬을 "**함수**"로 보면 수학의 이 모든 영역이 한 언어로 연결된다.

### Q1. 행렬의 크기와 성분

다음 행렬의 크기와 두 성분을 확인한다.

```
A = ⎡ 3   −1   4 ⎤
    ⎣ 0    2   7 ⎦
```

빈칸을 채워라.

> A의 크기: **_____** × **_____**
>
> a₁₂ = **_____**     a₂₃ = **_____**

힌트: 먼저 행의 수를 세고, 다음으로 열의 수를 센다. aᵢⱼ에서 i는 행 번호, j는 열 번호이다. 따라서 a₁₂는 "**1행 2열**"의 성분, a₂₃는 "**2행 3열**"의 성분이다.

이 빈칸을 채우면 행렬의 기본 표기법을 손에 쥔 것이다.

## 행렬의 덧셈

덧셈은 단순하다. 같은 자리의 성분을 더한다. 단, 두 행렬의 크기가 같아야 한다.

> **정의 2.** A = [aᵢⱼ]와 B = [bᵢⱼ]가 모두 m × n 행렬이면, A + B는 m × n 행렬이며 각 성분이 aᵢⱼ + bᵢⱼ이다.

구체 예로 본다.

```
⎡ 1   3 ⎤   ⎡ 2   0 ⎤     ⎡ 3   3 ⎤
⎣ 2   5 ⎦ + ⎣ 4   1 ⎦  =  ⎣ 6   6 ⎦
```

각 자리의 숫자를 그대로 더한다. 1 + 2 = 3, 3 + 0 = 3, 2 + 4 = 6, 5 + 1 = 6. 끝.

두 행렬의 크기가 다르면 덧셈 자체가 정의되지 않는다. 2 × 3 행렬과 3 × 2 행렬은 더할 수 없다. 같은 자리가 없기 때문이다.

덧셈은 일반 덧셈의 모든 성질을 그대로 가진다. 결합법칙 A + (B + C) = (A + B) + C가 성립하고, 교환법칙 A + B = B + A도 성립한다. 영행렬 O를 더해도 바뀌지 않는다. A + O = A이다. 즉 덧셈은 "**예상한 대로 작동한다**".

곧 보게 될 것처럼 곱셈은 예상한 대로 작동하지 않는다. 교환법칙이 성립하지 않는다. 이 차이가 강의의 정점이 된다.

## I 정리

이 단계에서 손에 쥔 것은 다음 네 가지이다.

| 기호 | 의미 |
|---|---|
| m × n | m행 n열의 직사각형 숫자 배열 |
| aᵢⱼ | i행 j열의 성분 (순서: 행 먼저, 열 나중) |
| A + B | 성분별 덧셈, 크기가 같아야 함 |
| A: ℝⁿ → ℝᵐ | 행렬은 사실 선형 함수이다 |

가장 중요한 마지막 한 줄을 손에 쥐고 다음 단계로 간다. **행렬은 수의 격자가 아니라, ℝⁿ에서 ℝᵐ으로 가는 함수이다.** 이 한 줄이 다음 단계에서 행렬 곱을 이해하는 열쇠가 된다.

두 단계로 넘어가서 행렬 곱을 만난다. 여기서 결정적 발견이 기다린다.

# II — 행렬 곱과 비가환성

이 단계가 오늘 강의의 정점이다. 행렬 곱의 정의를 본 뒤, 2×2 구체 행렬로 A × B와 B × A가 다름을 자기 손으로 확인하고, 같은 사실을 Lean 4 형식 증명 언어로 닫는다.

## 행렬 곱의 정의

행렬 곱은 덧셈보다 훨씬 복잡하다. 정의부터 본다.

> **정의 3.** A가 m × k 행렬이고 B가 k × n 행렬이면, AB는 m × n 행렬이며
>
> (AB)ᵢⱼ = aᵢ₁b₁ⱼ + aᵢ₂b₂ⱼ + ⋯ + aᵢₖbₖⱼ = Σₗ aᵢₗ bₗⱼ
>
> 즉, (i, j) 성분은 A의 i번째 행과 B의 j번째 열의 **내적**이다.

이 정의를 처음 보면 "**왜 이렇게 복잡한가?**"라는 의문이 자연스럽게 든다. 덧셈은 성분별 덧셈이라는 가장 단순한 규칙이었는데, 곱셈은 왜 행과 열을 따로 보고, 내적을 계산하고, 복잡한 합을 쓰는가?

한 가지 제약을 먼저 확인한다. **A의 열 개수 = B의 행 개수**여야 한다. 이 조건이 성립하지 않으면 곱 자체가 정의되지 않는다. 2 × 3 행렬과 3 × 4 행렬은 곱할 수 있다. A의 열 개수 3과 B의 행 개수 3이 같기 때문이다. 결과는 2 × 4 행렬이다. 그러나 2 × 3 행렬과 2 × 3 행렬은 곱할 수 없다. A의 열 개수 3과 B의 행 개수 2가 다르기 때문이다.

(AB)ᵢⱼ의 계산 방식은 다음과 같이 기억하면 쉽다. "**A의 i행을 가로로, B의 j열을 세로로 놓고, 같은 위치의 성분끼리 곱해서 모두 더한다**". 이것이 두 벡터의 내적이다. 그래서 "**(AB)ᵢⱼ는 A의 i행과 B의 j열의 내적이다**"라는 표현이 나온다.

## 왜 이렇게 복잡한가 — 함수 합성이기 때문이다

이 복잡한 정의가 사실 매우 자연스럽다. "**행렬은 함수이다**"라는 관점에서 보면 분명해진다.

A가 ℝᵏ → ℝᵐ 선형 함수이고 B가 ℝⁿ → ℝᵏ 선형 함수라고 하자. 그러면 두 함수를 차례로 적용하는 합성 함수 A ∘ B를 생각할 수 있다. 이것은 "**B를 먼저 적용하고, 그 결과에 A를 적용한다**"는 행위이다. 기호로 (A ∘ B)(x) = A(B(x))이다. 이 합성 함수도 선형 함수이며, ℝⁿ에서 ℝᵐ으로 간다.

놀라운 사실은 이것이다. **합성 함수 A ∘ B에 대응하는 행렬이 바로 행렬 곱 AB이다.** 즉 우리가 정의 3에서 본 복잡한 곱셈 공식은 사실 "**두 선형 함수를 합성할 때의 자연스러운 결과**"이다. 행과 열의 내적이 등장하는 이유는 행렬이 벡터에 어떻게 작용하는지를 추적하다 보면 자연스럽게 그 공식이 나오기 때문이다.

이 관점이 왜 중요한가. 함수 합성은 일반적으로 순서가 중요하다. 이전 강의의 합성 함수에서 f ∘ g ≠ g ∘ f였던 것을 기억할 것이다. 양말을 신고 신발을 신는 것과, 신발을 신고 양말을 신는 것이 다르다. 마찬가지로 두 선형 함수를 어떤 순서로 합성하는지도 일반적으로 다르다. 그래서 **행렬 곱도 순서가 중요하다**. 이것이 오늘의 결정적 발견의 뿌리이다.

### Q3. 행렬 곱 한 성분 계산

큰 계산으로 넘어가기 전에, 한 성분만 먼저 계산해 보자. 감을 익히는 자리이다.

```
A = ⎡ 1   2 ⎤       B = ⎡ 5   6 ⎤
    ⎣ 3   4 ⎦           ⎣ 7   8 ⎦
```

(AB)₁₁을 계산한다. 이것은 "**A의 1행과 B의 1열의 내적**"이다. A의 1행은 (1, 2)이고, B의 1열은 (5, 7)이다. 두 벡터를 내적하면 다음과 같다.

> (AB)₁₁ = 1 × **____** + 2 × **____**
>
>        = **____**

이 빈칸을 채우면 행렬 곱의 한 자리를 손으로 계산한 것이다. 나머지 세 자리도 같은 방식으로 계산할 수 있다. (AB)₁₂는 A의 1행 (1, 2)와 B의 2열 (6, 8)의 내적, (AB)₂₁은 A의 2행 (3, 4)와 B의 1열 (5, 7)의 내적, (AB)₂₂는 A의 2행 (3, 4)와 B의 2열 (6, 8)의 내적이다.

**[Python] Q3 — 행렬 곱 한 성분 (AB)₁₁**

```python
import numpy as np

A = np.array([[1, 2],
              [3, 4]])

B = np.array([[5, 6],
              [7, 8]])

row1_A = A[0, :]          # A의 1행
col1_B = B[:, 0]          # B의 1열
ab11   = np.dot(row1_A, col1_B)   # 내적

print(f"A의 1행 = {row1_A}")
print(f"B의 1열 = {col1_B}")
print(f"(AB)₁₁ = {row1_A[0]}×{col1_B[0]} + {row1_A[1]}×{col1_B[1]}")
print(f"       = {row1_A[0]*col1_B[0]} + {row1_A[1]*col1_B[1]}")
print(f"       = {ab11}")
```

출력:
```
A의 1행 = [1 2]
B의 1열 = [5 7]
(AB)₁₁ = 1×5 + 2×7
       = 5 + 14
       = 19
```

## A × B ≠ B × A — 순서가 중요하다

방금 손으로 확인한 사실이 오늘 강의의 핵심이다. 행렬 곱은 일반적으로 교환법칙이 성립하지 않는다. 즉 A × B ≠ B × A가 "**일반적**"이다. 두 곱이 같은 경우는 매우 특수한 상황이다. 예를 들어 A나 B 중 하나가 항등 행렬이거나, 두 행렬이 서로 역행렬 관계이거나, 두 행렬이 모두 대각 행렬인 경우 등이다. 일반적인 두 행렬은 순서를 바꾸면 완전히 다른 결과가 나온다.

한 쌍의 반례만 있으면 충분하다. 우리가 방금 계산한 한 쌍의 2 × 2 행렬이 "**일반적으로 비가환**"이라는 사실을 보인다. 수학에서 "**일반적으로 성질 P가 성립하지 않는다**"를 증명하기 위해서는 반례 하나만 제시하면 된다. 그리고 우리는 방금 그 반례를 손으로 만들었다.

이 비가환성이 왜 중요한가? 앞서 본 이유와 같다. **함수 합성은 순서가 중요하다.** 행렬이 함수이고 행렬 곱이 함수 합성이므로, 행렬 곱도 순서가 중요할 수밖에 없다. 양말 신고 신발 신는 것과 신발 신고 양말 신는 것이 다른 것처럼, 행렬 A와 B를 어떤 순서로 적용하는지가 결과를 완전히 바꾼다.

이것이 단순한 수학의 규칙이 아니라 세상의 본질을 담은 한 가지 깊은 사실임을 마지막 단계의 새로운 시각에서 보게 된다. 양자역학의 하이젠베르크 불확정성 원리가 사실 "**A × B ≠ B × A**"라는 한 줄에서 출발한다.

## Lean 4로 A × B ≠ B × A 증명하기

같은 사실을 Lean 4 형식 증명 언어로 닫는다. 수학에서는 "**손으로 계산했더니 달라요**"라고 말하면 되지만, 형식 증명 언어에서는 모든 단계를 컴퓨터가 검증할 수 있어야 한다. 14줄이다.

```lean
def A : Matrix (Fin 2) (Fin 2) Int := !![1, 2; 3, 4]
def B : Matrix (Fin 2) (Fin 2) Int := !![5, 6; 7, 8]

example : A * B ≠ B * A := by
  intro h
  have h00 : (A * B) 0 0 = (B * A) 0 0 := by rw [h]
  simp [A, B, Matrix.mul_apply, Fin.sum_univ_two] at h00
  -- h00 : 19 = 23,  즉 모순
  -- omega로 닫거나, exact absurd h00 (by decide)도 가능
```

코드를 한 줄씩 풀어 본다.

**첫 두 줄**은 A와 B를 정의한다. `Matrix (Fin 2) (Fin 2) Int`는 "**2 × 2 정수 행렬 타입**"이다. `Fin 2`는 "**{0, 1}이라는 두 원소의 집합**"이고, 이것이 행과 열의 인덱스가 된다. `!![1, 2; 3, 4]`는 "**행렬 리터럴**" 표기이며, 세미콜론으로 행을 구분하고 쉼표로 열을 구분한다. 즉 `!![1, 2; 3, 4]`는 첫째 행이 (1, 2), 둘째 행이 (3, 4)인 행렬이다.

**넷째 줄** `example : A * B ≠ B * A := by`는 정리의 진술이다. "**A × B는 B × A와 같지 않다**"를 증명하겠다는 선언이다.

**다섯째 줄** `intro h`는 모순법의 출발이다. "**A × B = B × A라고 가정하자. 그 가정을 h라 부르겠다**"라는 뜻이다. 목표는 이 가정에서 모순을 이끌어 내는 것이다.

**여섯째 줄** `have h00 : (A * B) 0 0 = (B * A) 0 0 := by rw [h]`은 "**가정 h가 성립한다면 양변의 (0, 0) 성분도 같아야 한다**"라는 사실을 h00이라는 새 이름으로 저장한다. `rw [h]`는 "**h를 이용해 다시 쓴다**"는 의미이며, h가 A × B = B × A라는 등식이므로 양변 어디에도 적용할 수 있다.

**일곱째와 여덟째 줄**은 핵심이다. `simp [A, B, Matrix.mul_apply, Fin.sum_univ_two] at h00`은 h00에 네 가지 간소화 규칙을 적용하라는 명령이다. 첫째, A의 정의를 풀어 성분을 드러낸다. 둘째, B의 정의도 푼다. 셋째, `Matrix.mul_apply`로 행렬 곱의 정의를 적용한다. 즉 (A * B) 0 0이 Σₗ A 0 l × B l 0로 풀린다. 넷째, `Fin.sum_univ_two`로 이 합을 "**l = 0일 때와 l = 1일 때**"의 두 항으로 풀어 쓴다. 이 마지막 규칙이 핵심이다. 단순히 `Fin.sum_univ_succ`만 쓰면 한 단계밖에 풀리지 않아 합 표현이 남는데, `Fin.sum_univ_two`는 2원소 Fin 집합에 대한 합을 한 번에 완전히 풀어낸다.

이 네 간소화 규칙이 모두 적용되면 h00은 "**19 = 23**"이라는 명백히 거짓인 등식이 된다. 마지막으로 `omega` 또는 `exact absurd h00 (by decide)`로 이 모순을 닫는다. omega는 정수의 1차 등식과 부등식을 자동으로 닫는 전술이고, decide는 "**명백히 계산 가능한 거짓을 직접 판단하여 닫는다**"는 전술이다. 두 방법 모두 19 ≠ 23이라는 사실에서 모순을 이끌어 낸다.

이 14줄이 수학의 "**손으로 계산했더니 달라요**"를 형식적으로 정확히 옮긴 것이다. Lean 4는 이 14줄을 한 줄씩 검증하여 "**증명 완료**"라고 답한다. 수학과 형식 증명 언어는 다른 언어가 아니라 같은 사고의 두 표기이다.

## II 정리 — 행렬 곱의 본질

이 단계가 끝난다. 손에 쥔 것을 정리하자.

행렬 곱의 정의는 복잡하지만, 사실 "**함수 합성**"이라는 단순한 개념의 구체적 표현이다. (AB)ᵢⱼ가 "**A의 i행과 B의 j열의 내적**"이라는 공식이 자연스러운 이유는, 이것이 두 선형 함수를 차례로 적용한 결과를 추적한 것이기 때문이다.

그리고 결정적 발견은 이것이다. **A × B ≠ B × A** — 행렬 곱은 일반적으로 교환법칙이 성립하지 않는다. 이것은 단순한 규칙의 차이가 아니라 "**함수 합성은 순서가 중요하다**"는 더 깊은 원리의 표현이다. 양말과 신발의 순서가 결과를 바꾸듯, 두 선형 함수의 적용 순서가 결과를 바꾼다.

이 비가환성이 세상의 본질에 어떤 의미를 가지는지는 강의 끝에서 다시 본다. 양자역학의 하이젠베르크 불확정성 원리가 사실 "**A × B ≠ B × A**"라는 한 줄에서 출발한다.

# III — 전치와 부울 행렬

이 마지막 단계에서 행렬의 두 가지 얼굴을 더 본다. 하나는 "**전치**"라는 고전적 연산이며 대칭 행렬의 정의로 이어진다. 다른 하나는 "**영-일 행렬**"이라는 특별한 행렬과 그 위의 부울 연산이며, 다음 강의의 관계와 그래프로 가는 다리이다.

## 전치 — 행과 열을 뒤바꾼다

전치는 행렬의 행과 열을 뒤바꾸는 연산이다. 정의는 단순하다.

> **정의 4.** A = [aᵢⱼ]가 m × n 행렬이면, 전치(transpose) Aᵀ는 n × m 행렬이며 (Aᵀ)ᵢⱼ = aⱼᵢ이다. 즉 A의 i행이 Aᵀ의 i열이 된다.

구체적인 예로 본다.

```
A = ⎡ 1   2   3 ⎤         Aᵀ = ⎡ 1   4 ⎤
    ⎣ 4   5   6 ⎦              ⎢ 2   5 ⎥
                                ⎣ 3   6 ⎦
```

A는 2 × 3 행렬이고 Aᵀ는 3 × 2 행렬이다. A의 첫째 행 (1, 2, 3)이 Aᵀ의 첫째 열이 되었고, A의 둘째 행 (4, 5, 6)이 Aᵀ의 둘째 열이 되었다. 즉 "**행이 세로로 선다**". 또는 동등하게 "**열이 가로로 눕는다**". 어느 쪽으로 생각해도 같다.

전치의 성질 몇 가지를 기억하면 좋다. 첫째, (Aᵀ)ᵀ = A이다. 두 번 뒤집으면 원래로 돌아온다. 둘째, (A + B)ᵀ = Aᵀ + Bᵀ이다. 덧셈과 전치는 순서를 바꿔도 된다. 셋째, 이것이 미묘한 부분인데, (AB)ᵀ = BᵀAᵀ이다. "**곱의 전치는 순서를 뒤집은 전치의 곱**"이다. 이 마지막 성질은 곱셈의 비가환성과 맞물려 있어 직관에 어긋나 보일 수 있다.

## 대칭 행렬 — 전치와 같은 행렬

전치와 원래 행렬이 같아지는 특별한 경우를 **대칭 행렬**이라 한다.

> **정의 5.** 정사각 행렬 A가 Aᵀ = A를 만족하면 A를 **대칭 행렬**(symmetric matrix)이라 한다. 이는 모든 (i, j)에 대해 aᵢⱼ = aⱼᵢ임과 동등하다.

대칭의 직관적인 그림은 "**주대각선을 거울로 두었을 때 양쪽이 같다**"는 것이다. 주대각선(왼쪽 위에서 오른쪽 아래로 내려가는 대각선)의 위쪽 성분과 아래쪽 성분이 거울상처럼 일치해야 한다.

몇 가지 예로 확인한다.

```
⎡ 1   2 ⎤      대칭인가? 예
⎣ 2   3 ⎦      a₁₂ = a₂₁ = 2
```

```
⎡ 1   2 ⎤      대칭인가? 아니오
⎣ 3   4 ⎦      a₁₂ = 2, a₂₁ = 3 (다름)
```

```
⎡ 5   0 ⎤      대칭인가? 예
⎣ 0   7 ⎦      대각 행렬은 항상 대칭
```

마지막 예에 주목하라. 대각 행렬(주대각선 외 모든 성분이 0인 행렬)은 항상 대칭이다. 주대각선 바깥의 모든 성분이 0이므로, 자연히 a₁₂ = 0 = a₂₁ 같은 대칭 조건이 저절로 성립한다.

대칭 행렬이 왜 중요한가. 고유값이 모두 실수라는 깊은 성질이 있다. 공분산 행렬, 관성 행렬, 양자역학의 관측 가능량(observable)에 대응하는 에르미트 행렬의 실수 경우 등 수많은 응용에서 대칭 행렬이 나타난다. 대칭이라는 단순한 조건 하나가 "**계산이 안정적이고, 고유값 분해가 깔끔하게 되는**" 좋은 성질을 부여한다.

### Q6. 대칭 행렬 판별

다음 세 행렬 중 어느 것이 대칭 행렬인가? 각각에 "**예**" 또는 "**아니오**"로 답하라.

```
A = ⎡ 1   2 ⎤      B = ⎡ 1   2 ⎤      C = ⎡ 5   0 ⎤
    ⎣ 2   3 ⎦          ⎣ 3   4 ⎦          ⎣ 0   7 ⎦
```

> A는 대칭인가? **_____**
>
> B는 대칭인가? **_____**
>
> C는 대칭인가? **_____**

판별 기준을 다시 떠올리자. 주대각선을 거울로 두었을 때 양쪽이 같은가? 또는 동등하게 aᵢⱼ = aⱼᵢ가 모든 (i, j)에 대해 성립하는가? 세 행렬을 차례로 검사해 보라.

**[Python] Q6 — 대칭 행렬 판별**

```python
import numpy as np

matrices = {
    "A": np.array([[1, 2], [2, 3]]),
    "B": np.array([[1, 2], [3, 4]]),
    "C": np.array([[5, 0], [0, 7]]),
}

for name, M in matrices.items():
    sym = np.array_equal(M, M.T)
    print(f"행렬 {name}: {'대칭 O' if sym else '대칭 X'}")
    if not sym:
        print(f"  → A[0,1]={M[0,1]}, A[1,0]={M[1,0]}  (aᵢⱼ ≠ aⱼᵢ)")
```

행렬 C: 대칭 O
```

## 영-일 행렬과 부울 연산

성분이 0과 1뿐인 행렬을 **영-일 행렬**(zero-one matrix)이라 한다. 이런 특별한 행렬에 대해서는 덧셈과 곱셈 외에 "**부울 연산**"이라는 새로운 연산들이 정의된다.

> **정의 6.** A = [aᵢⱼ]와 B = [bᵢⱼ]가 모두 m × n 영-일 행렬이면,
>
> **결합**(join)  A ∨ B: 성분별 OR. (A ∨ B)ᵢⱼ = aᵢⱼ ∨ bᵢⱼ. 둘 중 하나라도 1이면 1.
>
> **교차**(meet)  A ∧ B: 성분별 AND. (A ∧ B)ᵢⱼ = aᵢⱼ ∧ bᵢⱼ. 둘 다 1이어야 1.

이 두 연산은 성분별 덧셈과 비슷하지만 "**더하는 대신 OR 또는 AND를 취한다**". 결과도 영-일 행렬이다.

더 중요한 연산은 **부울 곱**이다.

> **정의 7.** A가 m × k 영-일 행렬이고 B가 k × n 영-일 행렬이면, 부울 곱 A ⊙ B는 m × n 영-일 행렬이며
>
> (A ⊙ B)ᵢⱼ = (aᵢ₁ ∧ b₁ⱼ) ∨ (aᵢ₂ ∧ b₂ⱼ) ∨ ⋯ ∨ (aᵢₖ ∧ bₖⱼ)

이 정의를 자세히 보면 일반 행렬 곱의 정의와 같은 구조인데, "**곱셈 ×이 AND ∧로, 덧셈 +이 OR ∨로**" 대체된 것이다. 즉 부울 곱은 "**일반 행렬 곱에서 산술 연산을 논리 연산으로 바꾼 것**"이다.

## 왜 영-일 행렬인가 — 관계와 그래프로 가는 다리

영-일 행렬과 부울 연산은 단지 특수한 행렬의 특수한 연산이 아니다. 이산수학의 핵심 개념으로 가는 다리이다. 세 가지 방향을 미리 본다.

**첫째, 관계.** 집합 X 위의 관계 R은 어떤 두 원소 x, y ∈ X가 "**관계가 있는가**"를 결정한다. 예를 들어 "**x는 y의 친구이다**", "**x는 y보다 작다**", "**x와 y는 같은 반이다**" 같은 관계이다. 이 관계를 영-일 행렬로 나타낼 수 있다. aᵢⱼ = 1이면 "**i번째 원소와 j번째 원소가 관계가 있다**", aᵢⱼ = 0이면 "**관계가 없다**"는 뜻이다. 이것이 관계의 행렬 표현이며, Rosen §9.3과 §9.4에서 본격적으로 다룬다.

**둘째, 그래프.** 그래프는 정점과 간선으로 이루어진 구조이다. 정점 사이에 간선이 있는지를 **인접 행렬**(adjacency matrix)로 나타낸다. Aᵢⱼ = 1이면 "**정점 i와 정점 j 사이에 간선이 있다**"는 뜻이고, Aᵢⱼ = 0이면 "**간선이 없다**"는 뜻이다. 인접 행렬은 정확히 영-일 행렬이다. 그래프의 많은 문제(연결성, 경로 존재, 최단 경로 등)가 인접 행렬 위의 연산으로 풀린다. Rosen §10.3에서 다룬다.

**셋째, 추이 폐포.** 한 관계 R이 있을 때, "**몇 단계든 도달 가능한 관계**"를 추이 폐포라 부른다. 예를 들어 "**x가 y의 직접 친구**"라는 관계로부터 "**x가 y의 친구의 친구, 또는 친구의 친구의 친구, ... 몇 단계든 간접적으로 연결된다**"는 관계를 만들 수 있다. 이것이 추이 폐포이다. 놀라운 사실은 이 추이 폐포가 **부울 곱의 거듭제곱**으로 정확히 계산된다는 것이다. A의 부울 곱 거듭제곱 A⁽¹⁾, A⁽²⁾, A⁽³⁾, ... 들의 결합이 추이 폐포를 준다. Rosen §9.4에서 다룬다.

즉 오늘 배운 부울 연산이 다음 강의의 언어가 된다. 관계, 그래프, 추이 폐포 — 이 모든 개념이 영-일 행렬과 부울 연산 위에 세워진다. 행렬이라는 단순한 도구가 이산수학의 깊은 구조로 가는 다리이다.

## III 정리 — 전치와 부울 행렬

이 단계가 끝난다. 손에 쥔 것을 정리하자.

**전치** Aᵀ는 행과 열을 뒤바꾼 행렬이다. **대칭 행렬**은 Aᵀ = A인 정사각 행렬이며, 주대각선을 거울로 양쪽이 같다. 대각 행렬은 항상 대칭이다.

**영-일 행렬**은 성분이 0과 1뿐인 행렬이다. 그 위에 **결합 ∨**, **교차 ∧**, **부울 곱 ⊙** 세 가지 부울 연산이 정의된다. 부울 곱은 일반 행렬 곱에서 산술 연산을 논리 연산으로 바꾼 것이다.

이 모든 것이 다음 강의의 관계와 그래프로 가는 다리이다. 오늘 수수께끼처럼 들렸던 부울 연산이 거기서 "**관계 사이의 합성**"이나 "**그래프의 연결성 계산**"으로 자연스럽게 사용된다. 미리 본 것이 나중에 사용처를 만나게 된다.

# 마무리: A × B ≠ B × A가 만든 세상

이 강의의 가장 기억에 남을 한 줄은 "**A × B ≠ B × A**"이다. 슬라이드 16에서 우리는 이것을 손으로 확인했다. 두 2 × 2 행렬의 곱이 순서에 따라 완전히 다른 결과를 주었다. Lean 4로도 같은 사실을 14줄에 닫았다. 이것이 단순한 수학의 규칙 하나일까? 아니다. 이것은 20세기 물리학을 만든 뿌리이다.

## 1925년 — 하이젠베르크와 양자역학의 시작

1925년 여름, 젊은 베르너 하이젠베르크는 원자 속 전자의 에너지 상태를 계산하다가 한 가지 이상한 일을 발견했다. 그가 만들어 낸 계산 규칙이 일반적인 곱셈의 법칙을 따르지 않았다. 구체적으로, 전자의 "**위치 q**"와 "**운동량 p**"를 나타내는 양이 **p × q ≠ q × p**를 만족하는 것이었다.

하이젠베르크는 이것이 무엇을 의미하는지 확신할 수 없었다. 그는 결과를 막스 보른에게 보냈고, 보른은 이것이 사실 **행렬**이라는 것을 알아보았다. 하이젠베르크가 우연히 발견한 그 이상한 계산 규칙이 바로 "**행렬 곱의 비가환성**"이었다. 물리학자들은 그때까지 행렬이라는 것을 몰랐다. 하이젠베르크도 행렬에 대해 배운 적이 없었다. 그는 단지 관측된 원자 현상을 설명하는 계산 규칙을 만들어 내려 했을 뿐이었다. 그런데 그 규칙이 수학자들이 이미 알고 있던 "**행렬 대수**"와 정확히 같았다.

이 발견이 양자역학의 탄생이었다. 그 이전의 물리학(고전 역학)에서는 모든 양이 실수였고 교환법칙이 당연히 성립했다. x × p = p × x가 언제나 참이었다. 그러나 원자 스케일에서는 이것이 깨진다. 위치와 운동량은 단순한 실수가 아니라 "**행렬과 같은 것**"이며, 두 것을 측정하는 순서가 결과를 바꾼다.

## 하이젠베르크 불확정성 원리

이것이 무엇을 의미하는가? "**두 측정의 순서가 다르다**"는 것이 왜 중요한가? 답은 다음과 같다. **두 양을 동시에 정확하게 측정할 수 없다.**

고전 역학에서는 입자의 위치와 운동량을 동시에 정확하게 알 수 있다. "**이 공은 지금 (3, 2) 위치에 있고, 속도 5로 오른쪽으로 움직이고 있다**"고 말할 수 있다. 그러나 양자역학에서는 이것이 불가능하다. 위치를 정확하게 측정하면 운동량이 불확정해지고, 운동량을 정확하게 측정하면 위치가 불확정해진다. "**두 측정 사이의 교환법칙이 깨졌기 때문**"이다.

이것이 **하이젠베르크 불확정성 원리**이다. 1927년 하이젠베르크가 형식화했고, 이후 양자역학의 가장 근본적인 원리 중 하나가 되었다. 그리고 이 원리의 수학적 뿌리가 정확히 오늘 우리가 본 "**A × B ≠ B × A**"이다.

수학에서 "**A × B ≠ B × A**"는 한 줄의 사실이지만, 물리학에서 그것은 "**측정할 수 없는 것이 있다**"는 자연의 본질이다. 우리가 오늘 두 2 × 2 행렬로 손으로 확인한 그 사실이, 원자와 전자의 세계에서는 "**세상이 근본적으로 어떻게 작동하는가**"를 결정한다.

## 수학은 시간을 넘는다

한 가지 더 주목할 점이 있다. 행렬 대수학은 1850년대 아서 케일리에 의해 처음 정의되었다. 그때는 순수하게 "**수학적 호기심**"이었다. 어떤 응용도 없었다. 케일리는 "**이런 연산을 정의할 수도 있겠네**" 하는 마음으로 행렬과 행렬 곱을 만들었을 뿐이다. 70년이 지난 1925년, 그 호기심이 양자역학의 언어가 된다. 수학자들이 그 이유를 모르고 만든 도구가, 반세기 후 자연의 가장 깊은 법칙을 설명하는 데 정확히 맞았다.

이것이 수학의 신비이다. **수학은 시간을 넘는다.** 오늘 우리가 손으로 계산한 한 쌍의 2 × 2 행렬에서 나타난 사실이 100년 전의 케일리에서 90년 전의 하이젠베르크까지, 그리고 오늘날 양자 컴퓨팅과 양자 정보 이론의 모든 기술로 이어진다.

수업을 마친다. 이 워크북을 가져가서 강의 후 다시 펼쳐 보라. 본문이 한 호흡으로 읽힌다. 오늘 손에 쥔 한 줄 "**행렬은 수의 격자가 아니라, 순서가 있는 세상의 법칙이다**"가 계속 손에 남을 것이다.

다음 강의는 **관계와 그래프**이다. 오늘 배운 영-일 행렬과 부울 연산이 그곳의 언어가 된다. 오늘 만든 도구가 다음 강의에서 사용처를 만나게 된다.

## Q1 — 행렬의 크기와 성분

```
A = ⎡ 3   −1   4 ⎤
    ⎣ 0    2   7 ⎦
```

> A의 크기: **2 × 3** (2행, 3열)
>
> a₁₂ = **−1** (1행 2열)
>
> a₂₃ = **7** (2행 3열)

"**행 먼저, 열 나중**"의 순서를 잘 지켜야 한다. a₁₂는 "**첫째 인덱스가 1, 둘째 인덱스가 2**"이므로 "**1행 2열**"이다. 첫째 행의 두 번째 자리 = −1이다. a₂₃는 "**2행 3열**"이므로 둘째 행의 세 번째 자리 = 7이다.

이 표기법은 모든 행렬 계산에서 계속 등장하므로 손에 익혀 두어야 한다. (i, j) 쌍은 "**i행 j열**"이며, 이 순서는 절대 바뀌지 않는다. 혼동이 생기면 항상 "**행 먼저, 열 나중**"이라고 속으로 말하면 된다.

## Q2 — 행렬 덧셈

```
A = ⎡ 2   5 ⎤       B = ⎡ 1   −3 ⎤
    ⎣ 4  −1 ⎦           ⎣ 6    2 ⎦
```

> A + B = ⎡ **3**    **2** ⎤
>
>        ⎣ **10**    **1** ⎦

계산 과정을 한 줄씩 본다. (1, 1) 자리: 2 + 1 = 3. (1, 2) 자리: 5 + (−3) = 2. (2, 1) 자리: 4 + 6 = 10. (2, 2) 자리: (−1) + 2 = 1. 네 자리 모두 "**같은 위치의 성분끼리 그냥 더하면**" 된다. 이것이 행렬 덧셈의 전부이다. 덧셈은 단순하고 예측 가능하다. 교환법칙과 결합법칙이 모두 성립하므로 실수의 덧셈과 거의 같다.

## Q3 — 행렬 곱 한 성분 계산

```
A = ⎡ 1   2 ⎤       B = ⎡ 5   6 ⎤
    ⎣ 3   4 ⎦           ⎣ 7   8 ⎦
```

> (AB)₁₁ = 1 × **5** + 2 × **7**
>
>        = 5 + 14
>
>        = **19**

이 계산의 호흡을 다시 정리하자. (AB)₁₁은 "**A의 1행과 B의 1열의 내적**"이다. A의 1행은 (1, 2)이고 B의 1열은 (5, 7)이다. 같은 위치의 성분끼리 곱하여 더한다. 첫 위치: 1 × 5 = 5. 둘째 위치: 2 × 7 = 14. 합: 5 + 14 = 19.

이것이 행렬 곱의 핵심 단위 연산이다. 모든 (i, j) 자리는 "**A의 i행과 B의 j열의 내적**"으로 계산된다. 나머지 세 자리도 같은 방식으로 계산된다.

## Q5 — A × B와 B × A 모두 계산

먼저 A × B의 네 자리를 계산한다.

> (AB)₁₁ = 1 × 5 + 2 × 7 = 5 + 14 = **19**
>
> (AB)₁₂ = 1 × 6 + 2 × 8 = 6 + 16 = **22**
>
> (AB)₂₁ = 3 × 5 + 4 × 7 = 15 + 28 = **43**
>
> (AB)₂₂ = 3 × 6 + 4 × 8 = 18 + 32 = **50**
>
> ```
> A × B = ⎡ 19   22 ⎤
>        ⎣ 43   50 ⎦
> ```

다음으로 B × A의 네 자리를 계산한다.

> (BA)₁₁ = 5 × 1 + 6 × 3 = 5 + 18 = **23**
>
> (BA)₁₂ = 5 × 2 + 6 × 4 = 10 + 24 = **34**
>
> (BA)₂₁ = 7 × 1 + 8 × 3 = 7 + 24 = **31**
>
> (BA)₂₂ = 7 × 2 + 8 × 4 = 14 + 32 = **46**
>
> ```
> B × A = ⎡ 23   34 ⎤
>        ⎣ 31   46 ⎦
> ```

**두 결과 비교.**

```
A × B = ⎡ 19   22 ⎤          B × A = ⎡ 23   34 ⎤
       ⎣ 43   50 ⎦                  ⎣ 31   46 ⎦
```

네 자리가 **모두 다르다**. 19 ≠ 23, 22 ≠ 34, 43 ≠ 31, 50 ≠ 46. 따라서 A × B ≠ B × A이다. 한 쌍의 반례로 "**일반적으로 행렬 곱은 교환법칙이 성립하지 않는다**"는 것을 보인 것이다.

이 결과를 본 뒤 Q4의 직감 투표로 돌아가라. "**항상 같다**"라고 답한 사람은 실수의 경험에 따라 자연스럽게 그렇게 답한 것이다. 실수의 곱은 가환적이다. 3 × 5 = 5 × 3 = 15. 그러나 행렬은 "**함수의 표현**"이고, 함수 합성은 순서가 중요하다. 그래서 행렬 곱도 순서가 중요하다. 수학의 한 세계(실수)에서 성립하던 성질이 다른 세계(행렬)에서는 성립하지 않는 것이다.

## Q6 — 대칭 행렬 판별

```
A = ⎡ 1   2 ⎤      B = ⎡ 1   2 ⎤      C = ⎡ 5   0 ⎤
    ⎣ 2   3 ⎦          ⎣ 3   4 ⎦          ⎣ 0   7 ⎦
```

> A는 대칭인가? **예**. a₁₂ = 2이고 a₂₁ = 2이므로 같다. 주대각선 (1, 3)을 기준으로 양쪽이 모두 2이다.
>
> B는 대칭인가? **아니오**. a₁₂ = 2이지만 a₂₁ = 3이므로 다르다. 대칭 조건이 깨진다.
>
> C는 대칭인가? **예**. 대각 행렬(주대각선 외의 모든 성분이 0)은 항상 대칭이다. a₁₂ = 0 = a₂₁, 조건이 자동으로 성립한다.

한 가지 더 보이는 것. 대칭 여부는 "**크기**"와 무관하다. 1 × 1 행렬도 대칭이고(혼자뿐이니 자연히), 100 × 100 행렬도 조건만 만족하면 대칭이다. 중요한 것은 정사각 행렬이어야 한다는 점과, aᵢⱼ = aⱼᵢ가 모든 (i, j)에 대해 성립해야 한다는 점이다. 대칭은 "**모양**"이 아니라 "**성분 사이의 관계**"이다.

# 부록 2: 추가 도전 문제

다음 문제들은 시간이 남거나 더 익히고 싶은 사람을 위한 것이다.

**도전 1.** 두 2 × 2 행렬 A와 B를 자기 마음대로 선택하여, A × B와 B × A를 모두 계산하라. 두 결과가 같은 경우를 만들어 낼 수 있는가? 즉 "**교환법칙이 성립하는 특수한 행렬 쌍**"을 찾아보라.

> 힌트. 몇 가지 방법이 있다. 첫째, A = B로 두면 당연히 A × B = B × A = A²이다. 둘째, 한쪽이 항등 행렬(대각선 1, 나머지 0)이면 I × A = A × I = A이다. 셋째, 한쪽이 A의 역행렬이면 A × A⁻¹ = A⁻¹ × A = I이다. 넷째, 두 행렬이 모두 대각 행렬이면 교환법칙이 성립한다. 대각 행렬의 곱은 각 대각 성분을 곱한 대각 행렬이다.

**[Python] 도전 1 — 교환법칙이 성립하는 특수한 행렬 쌍**

```python
import numpy as np

def commutes(A, B):
    return np.array_equal(A @ B, B @ A)

X  = np.array([[1, 2], [3, 4]])
I2 = np.eye(2, dtype=int)
D1 = np.diag([3, 5])
D2 = np.diag([2, 7])

print(f"A = B (같은 행렬)     AB = BA? → {commutes(X, X)}")
print(f"B = I (항등 행렬)     AB = BA? → {commutes(X, I2)}")
print(f"두 대각 행렬           AB = BA? → {commutes(D1, D2)}")

# 대각 행렬 100쌍 무작위 검증
rng = np.random.default_rng(42)
all_ok = all(
    commutes(np.diag(rng.integers(1,10,2)), np.diag(rng.integers(1,10,2)))
    for _ in range(100)
)
print(f"대각 행렬 무작위 100쌍 모두 교환 가능? → {all_ok}")
```

출력:
```
A = B (같은 행렬)     AB = BA? → True
B = I (항등 행렬)     AB = BA? → True
두 대각 행렬           AB = BA? → True
대각 행렬 무작위 100쌍 모두 교환 가능? → True
```

**도전 2.** A를 2 × 3 행렬, B를 3 × 4 행렬이라 하자. AB는 어떤 크기의 행렬인가? 그리고 BA는 정의될 수 있는가? 일반적으로 m × n 행렬 A와 p × q 행렬 B에 대해 AB와 BA가 모두 정의되려면 어떤 조건이 필요한가?

> 힌트. AB가 정의되려면 "**A의 열 개수 = B의 행 개수**"여야 한다. 2 × 3과 3 × 4는 이 조건을 만족하며, 결과는 2 × 4 행렬이다. BA는 "**B의 열 개수 = A의 행 개수**"를 요구하는데, 4 ≠ 2이므로 BA는 정의되지 않는다. 즉 AB는 가능하지만 BA는 불가능하다. 일반적으로 AB와 BA가 모두 정의되려면 m = q이고 n = p여야 한다. 이 경우 AB는 m × n 행렬이고 BA는 p × q = n × m 행렬이다. 두 결과의 크기도 다를 수 있다.

**[Python] 도전 2 — 행렬 곱의 크기 규칙**

```python
import numpy as np

A = np.ones((2, 3), dtype=int)   # 2×3
B = np.ones((3, 4), dtype=int)   # 3×4

AB = A @ B
print(f"A: {A.shape},  B: {B.shape}  →  AB: {AB.shape}")

try:
    BA = B @ A
except ValueError as e:
    print(f"BA 시도 → 오류: {e}")

# 크기 규칙 함수
def mul_shape(m, k, p, q):
    if k != p:
        return f"({m}×{k}) @ ({p}×{q}) → 불가 (k={k} ≠ p={p})"
    return f"({m}×{k}) @ ({p}×{q}) → ({m}×{q})"

for args in [(2,3,3,4), (4,3,2,3), (3,3,3,3)]:
    print(mul_shape(*args))
```

출력:
```
A: (2, 3),  B: (3, 4)  →  AB: (2, 4)
BA 시도 → 오류: matmul: Input operand 1 has a mismatch ...
(2×3) @ (3×4) → (2×4)
(4×3) @ (2×3) → 불가 (k=3 ≠ p=2)
(3×3) @ (3×3) → (3×3)
```

**도전 3.** 항등 행렬 I₂는 다음과 같다.

```
I₂ = ⎡ 1   0 ⎤
     ⎣ 0   1 ⎦
```

임의의 2 × 2 행렬 A에 대해 I₂ × A = A × I₂ = A임을 직접 계산으로 확인하라. 즉 항등 행렬은 실수의 1과 같은 역할을 한다. 왜 이것이 성립하는지 "**A의 i행과 I의 j열의 내적**" 관점에서 설명하라.

> 힌트. I₂의 j열은 "**j번째 위치만 1이고 나머지는 0**"인 벡터이다. 예를 들어 첫째 열은 (1, 0)이고, 둘째 열은 (0, 1)이다. A의 i행과 이 열을 내적하면 "**A의 (i, j) 성분만 남는다**". 왜냐하면 j번째 위치에서는 aᵢⱼ × 1 = aᵢⱼ이고, 나머지 위치에서는 aᵢₖ × 0 = 0이기 때문이다. 따라서 (A × I)ᵢⱼ = aᵢⱼ이며, 즉 A × I = A이다. 같은 방식으로 I × A = A도 성립한다.

**[Python] 도전 3 — 항등 행렬: I @ A = A @ I = A**

```python
import numpy as np

A  = np.array([[3, 7], [1, 5]])
I2 = np.eye(2, dtype=int)

print("I @ A =\n", I2 @ A)
print("A @ I =\n", A @ I2)
print(f"I @ A = A? → {np.array_equal(I2 @ A, A)}")
print(f"A @ I = A? → {np.array_equal(A @ I2, A)}")

# 단위벡터 관점 출력
for j in range(2):
    ej = I2[:, j]
    for i in range(2):
        dot = int(np.dot(A[i, :], ej))
        print(f"  A의 {i+1}행 · e_{j+1} = {dot}  (= A[{i+1},{j+1}] = {A[i,j]})")
```

출력:
```
I @ A =
 [[3 7]
  [1 5]]
A @ I =
 [[3 7]
  [1 5]]
I @ A = A? → True
A @ I = A? → True
  A의 1행 · e_1 = 3  (= A[1,1] = 3)
  A의 2행 · e_1 = 1  (= A[2,1] = 1)
  A의 1행 · e_2 = 7  (= A[1,2] = 7)

**도전 4.** (AB)ᵀ = BᵀAᵀ임을 2 × 2 구체 예로 확인하라. 즉 슬라이드 16의 A, B에 대해 양변을 모두 계산하고 일치하는지 보라. 그리고 왜 "**전치의 순서가 뒤집히는지**" 직관적으로 생각해 보라.

> 힌트. A × B = [[19, 22], [43, 50]]이므로 (AB)ᵀ = [[19, 43], [22, 50]]이다. Aᵀ = [[1, 3], [2, 4]]이고 Bᵀ = [[5, 7], [6, 8]]이다. Bᵀ × Aᵀ의 네 자리를 계산하면 (1, 1) = 5 × 1 + 7 × 2 = 19, (1, 2) = 5 × 3 + 7 × 4 = 43, (2, 1) = 6 × 1 + 8 × 2 = 22, (2, 2) = 6 × 3 + 8 × 4 = 50이다. 즉 Bᵀ × Aᵀ = [[19, 43], [22, 50]] = (AB)ᵀ이다. 일치한다. 순서가 뒤집히는 이유는 "**전치하면 행렬의 역할이 뒤집힌다**"는 것과 관련된다. 함수 합성 A ∘ B의 역(또는 전치)은 B⁻¹ ∘ A⁻¹인 것과 비슷한 원리이다.

**[Python] 도전 4 — (AB)ᵀ = BᵀAᵀ**

```python
import numpy as np

A = np.array([[1, 2], [3, 4]])
B = np.array([[5, 6], [7, 8]])

AB_T  = (A @ B).T
BT_AT = B.T @ A.T

print("(A @ B)ᵀ =\n", AB_T)
print("Bᵀ @ Aᵀ =\n", BT_AT)
print(f"(AB)ᵀ = BᵀAᵀ? → {np.array_equal(AB_T, BT_AT)}")

# 무작위 3×3 행렬 1000쌍으로 일반 검증
rng = np.random.default_rng(0)
all_ok = all(
    np.array_equal((P := rng.integers(-9,10,(3,3))) @ (Q := rng.integers(-9,10,(3,3))),
                   (lambda P,Q: (P@Q))(P,Q)) or
    np.array_equal((P @ Q).T, Q.T @ P.T)
    for _ in range(1000)
)
print(f"무작위 1000쌍 (PQ)ᵀ = QᵀPᵀ 검증 → {all_ok}")
```

**도전 5.** 영-일 행렬 A와 B가 다음과 같다고 하자.

```
A = ⎡ 1   0 ⎤      B = ⎡ 1   1 ⎤
    ⎣ 1   1 ⎦          ⎣ 0   1 ⎦
```

A ∨ B (결합)과 A ∧ B (교차)를 계산하라. 그리고 부울 곱 A ⊙ B도 계산하라. 일반 행렬 곱 AB와 부울 곱 A ⊙ B가 어떻게 다른지 비교하라.

> 힌트. A ∨ B는 성분별 OR이므로 네 자리 모두 "**둘 중 하나라도 1이면 1**"이다. A ∨ B = [[1, 1], [1, 1]]. A ∧ B는 성분별 AND이므로 "**둘 다 1이어야 1**"이다. A ∧ B = [[1, 0], [0, 1]]. 부울 곱은 "**곱셈 대신 AND, 덧셈 대신 OR**"이다. (A ⊙ B)₁₁ = (1 ∧ 1) ∨ (0 ∧ 0) = 1 ∨ 0 = 1. (A ⊙ B)₁₂ = (1 ∧ 1) ∨ (0 ∧ 1) = 1 ∨ 0 = 1. (A ⊙ B)₂₁ = (1 ∧ 1) ∨ (1 ∧ 0) = 1 ∨ 0 = 1. (A ⊙ B)₂₂ = (1 ∧ 1) ∨ (1 ∧ 1) = 1 ∨ 1 = 1. 즉 A ⊙ B = [[1, 1], [1, 1]]. 이 경우 A ⊙ B = A ∨ B가 되었다. 일반 행렬 곱과는 다르다. 일반 AB는 성분이 2, 3 등 1보다 큰 값을 가질 수 있지만, 부울 곱은 항상 0 또는 1이다.

**[Python] 도전 5 — 부울 행렬: 결합(∨), 교차(∧), 부울 곱(⊙)**

```python
import numpy as np

A = np.array([[1, 0], [1, 1]], dtype=bool)
B = np.array([[1, 1], [0, 1]], dtype=bool)

# 결합 A ∨ B : 성분별 OR
A_or_B  = A | B

# 교차 A ∧ B : 성분별 AND
A_and_B = A & B

# 부울 곱 A ⊙ B : AND+OR
def bool_mul(A, B):
    m, k = A.shape
    n = B.shape[1]
    C = np.zeros((m, n), dtype=bool)
    for i in range(m):
        for j in range(n):
            C[i, j] = np.any(A[i, :] & B[:, j])
    return C

A_bool_B = bool_mul(A, B)

print("A ∨ B =\n", A_or_B.astype(int))
print("A ∧ B =\n", A_and_B.astype(int))
print("A ⊙ B =\n", A_bool_B.astype(int))
print("A @ B (일반 곱) =\n", A.astype(int) @ B.astype(int))

# 성분별 계산 과정
for i in range(2):
    for j in range(2):
        steps = " ∨ ".join(
            f"({int(A[i,k])} ∧ {int(B[k,j])})" for k in range(2))
        print(f"  (A⊙B)[{i+1},{j+1}] = {steps} = {int(A_bool_B[i,j])}")
```

출력:
```
A ∨ B =
 [[1 1]
  [1 1]]
A ∧ B =
 [[1 0]
  [0 1]]
A ⊙ B =
 [[1 1]
  [1 1]]
A @ B (일반 곱) =
 [[1 1]
  [1 2]]
  (A⊙B)[1,1] = (1 ∧ 1) ∨ (0 ∧ 0) = 1
  (A⊙B)[1,2] = (1 ∧ 1) ∨ (0 ∧ 1) = 1
  (A⊙B)[2,1] = (1 ∧ 1) ∨ (1 ∧ 0) = 1
  (A⊙B)[2,2] = (1 ∧ 1) ∨ (1 ∧ 1) = 1
```

**도전 6.** Lean 4로 다음 명제를 증명하라. 슬라이드 17의 14줄 증명을 참고해도 좋다.

```lean
def A : Matrix (Fin 2) (Fin 2) Int := !![1, 0; 0, 2]
def B : Matrix (Fin 2) (Fin 2) Int := !![2, 0; 0, 1]

example : A * B = B * A := by
  sorry  -- 빈칸을 채워라
```

즉 이 특수한 A와 B에 대해서는 "**교환법칙이 성립한다**"는 것을 증명하는 것이다. 왜 이 특수한 경우에만 성립하는지 생각해 보라.

> 힌트. 두 행렬이 모두 대각 행렬이므로 교환법칙이 성립한다. 도전 1의 넷째 방법이다. 증명은 다음과 같이 쓸 수 있다.
>
> ```lean
> example : A * B = B * A := by
>   ext i j
>   fin_cases i <;> fin_cases j <;>
>     simp [A, B, Matrix.mul_apply, Fin.sum_univ_two]
> ```
>
> `ext i j`는 "**두 행렬이 같다는 것을 보이려면 모든 (i, j) 자리가 같음을 보이면 된다**"는 외연성(extensionality) 원리를 적용한다. `fin_cases i`와 `fin_cases j`는 "**i와 j는 각각 0 또는 1이다**"라는 유한한 경우로 나눈다. 이렇게 네 경우(i=0, j=0 / i=0, j=1 / i=1, j=0 / i=1, j=1)로 분리된 뒤, 각 경우에서 simp가 양변을 구체적 숫자로 풀어 주면 모두 같음을 확인할 수 있다.
