## §1. 들어가며

§4.4 강의에서는 **합동**(congruence)이라는 정수론의 핵심 관계를 본격적으로 다룹니다. 두 정수가 어떤 법(modulus)을 두고 "사실상 같은 수"로 취급되는 관계예요. 이 관계가 잘 정의되어 있다는 것, 즉 동치 관계(반사·대칭·추이)임을 보이고, 그 위에 모듈러 역원, 중국 잉여 정리, 페르마 소정리 같은 클래식 결과들을 쌓아 올립니다.

본 강의는 다음 일곱 주제를 다뤄요.

1. 사용자 정의 합동 관계 `CongMod` (정의)
2. 합동과 가분성의 동치 (두 형태 비교)
3. 합동의 세 성질 (반사·대칭·추이)
4. 모듈러 역원의 존재와 유일성 (베주 항등식)
5. ZMod 환경에서의 구체 계산
6. 중국 잉여 정리 (CRT)
7. 페르마 소정리

§4.1·§4.3에서 다룬 모든 도구가 본 절에서 활용됩니다.

## §2. 합동의 사용자 정의

§4.4 강의에서 본 합동의 정의를 다시 적습니다.

**정의** 정수 `a`, `b`, `m`에 대해, `a - b`가 `m`의 정수배이면 "`a`와 `b`는 `m`을 법으로 합동"이라 하고 다음과 같이 씁니다.

```
a ≡ b (mod m)  ⟺  ∃ k : Int, a - b = k * m
```

[Q] §4.1 마지막에 봤던 Mathlib의 `Int.ModEq`와 본 정의가 어떻게 다를까요? (5초) 답: 사실 본질적으로 같은 정의예요. 우리는 직접 만든 형태를 본격적으로 다뤄 본다는 차이.

Lean 4에서는 Mathlib에 이미 `Int.ModEq`라는 정의가 있지만, **본 자료에서는 우리만의 정의 `CongMod`을 직접 만들어 봅니다**. 정의의 내부 동작과 세 성질의 직접 증명을 통해 합동 관계가 어떻게 작동하는지 깊이 이해하기 위함이에요.

[ANALOGY] 마치 자동차 운전하기 전에 부품을 직접 분해·조립해 보는 것과 같아요. 라이브러리를 그냥 호출만 하지 말고, 한 번은 직접 만들어 보면 내부 동작이 손에 익습니다.

```lean
import Mathlib

def CongMod (m a b : Int) : Prop := ∃ k : Int, a - b = k * m

notation:50 a " ≡ " b " [Z" m "]" => CongMod m a b
```

[DEMO] 두 가지 새 요소를 시범 보입니다.

**`def`로 명제 정의** `def CongMod ... : Prop := ...`는 새 **명제**(`Prop`)를 정의합니다. 사실 `CongMod`는 함수처럼 보이지만, 결과가 `Prop`(명제)이므로 "명제를 만드는 함수"예요. 인수를 받아 명제를 돌려주는 형태.

[WATCH] 학생들이 `def`와 `theorem`의 차이에 종종 혼란을 느껴요. `def`는 새로운 객체나 함수, 명제 자체를 정의. `theorem`은 명제가 참임을 증명. 본 자료의 `CongMod`은 명제를 만드는 함수이므로 `def`. 그리고 `CongMod_refl` 같은 정리들은 그 명제가 참임을 보이므로 `theorem`.

**`notation` 선언** 새 표기법을 도입합니다. `a " ≡ " b " [Z" m "]"`라는 패턴을 `CongMod m a b`로 해석. 즉 `5 ≡ 12 [Z 7]`이라고 쓰면 Lean 4가 자동으로 `CongMod 7 5 12`로 받아들여요. 종이의 `5 ≡ 12 (mod 7)`을 가능한 한 가깝게 옮긴 표기.

`:50`은 연산자의 우선순위. 다른 연산자(예: `+`, `*`)와 섞일 때 결합 순서가 어떻게 되는지를 정해요. 본 강의의 학습 단계에서는 자세히 알 필요 없습니다.

[Q] 우리만의 표기법을 만들면 좋은 점이 뭘까요? (5초) 답: 종이의 수학적 표기를 코드에서도 그대로 쓸 수 있어 가독성이 좋아져요. 단점: 다른 사람의 코드를 읽을 때 그 사람의 표기법을 따로 익혀야 함. 표준화의 트레이드오프.

[AI] `notation` 선언은 사실 도메인 특화 언어(DSL, Domain-Specific Language)의 출발선이에요. 자연스러운 표기로 형식 정리를 작성할 수 있게 해 줍니다. AI가 자연어를 정형 언어로 옮길 때도 이런 표기법의 다리가 중요한 역할을 해요.

## §3. 합동과 가분성의 동치

본 자료의 `CongMod`은 `∃ k, a - b = k * m` 형태예요. 그런데 Lean 4의 가분성 `m ∣ (a - b)`는 정의가 `∃ k, (a - b) = m * k`입니다. **곱셈의 순서가 다르죠.**

| 표현 | 정의 |
|---|---|
| `m ∣ (a - b)` | `∃ k, (a - b) = m * k` (k가 오른쪽) |
| `CongMod m a b` | `∃ k, a - b = k * m` (k가 왼쪽) |

정수환은 가환환(commutative ring)이므로 `m * k = k * m`이지만, 형식 증명에서는 두 형태가 그대로 같지 않아요. 명시적인 변환이 필요해요.

[Q] 왜 같은 사실인데 굳이 변환해야 할까요? Lean 4가 자동으로 처리할 수 있지 않나요? (5초)

답: Lean 4는 표현의 정확한 형태를 구분합니다. `m * k`와 `k * m`은 의미상 같지만 표현이 달라요. 가환성으로 변환하려면 `mul_comm`을 명시적으로 적용해야 합니다. 이게 형식 증명의 엄밀함이자 동시에 까다로움.

[WATCH] 학생들에게 가장 자주 헷갈리는 부분 중 하나예요. 강의에서 다시 한 번 강조하세요.

> Lean 4의 표준 가분성 `a ∣ b`의 정의는 **k가 오른쪽**: `∃ k, b = a * k`.  
> 같은 사실의 왼쪽 형태는 `dvd_iff_exists_eq_mul_left`: `∃ k, b = k * a`.  
> 두 형태는 가환환(예: 정수)에서 동치이지만, 정확히 같은 표현은 아닙니다.

본 자료에서는 두 방식으로 이 변환을 보입니다.

**방식 1.** 가분성의 증인을 직접 구성하고 `mul_comm`으로 순서를 맞추기.

```lean
example (a b m : ℤ) (h : ∃ k, a - b = k * m) : m ∣ (a - b) := by
  obtain ⟨k, hk⟩ := h
  refine ⟨k, ?_⟩
  rw [hk, mul_comm]
```

[DEMO] 다섯 줄을 차근차근.

- `obtain ⟨k, hk⟩ := h`: 존재 가정 `h`를 분해해서 증인 `k`와 등식 `hk : a - b = k * m`을 손에 쥡니다.
- `refine ⟨k, ?_⟩`: 결론 `m ∣ (a - b)`의 정의 `∃ k', (a - b) = m * k'`에 같은 `k`를 증인으로 제시. `?_`는 "등식은 아직 못 보였음"의 자리표시.
- `rw [hk, mul_comm]`: `?_` 자리의 목표 `a - b = m * k`를 닫기 위해, 먼저 `hk`로 좌변을 `k * m`으로 치환하고, `mul_comm`으로 곱셈 순서를 뒤집어 `m * k`로.

[Q] `rw [hk, mul_comm]`에서 두 다시쓰기가 차례로 일어나는 거죠? (3초) 답: 그래요. `rw [A, B]`는 `rw [A]; rw [B]`와 같습니다. 콤마로 묶어 한 줄에 여러 개를 적을 수 있어요.

**방식 2.** Mathlib의 `dvd_iff_exists_eq_mul_left` 정리를 활용.

```lean
example (a b m : ℤ) (h : ∃ k, a - b = k * m) : m ∣ (a - b) := by
  obtain ⟨k, hk⟩ := h
  rw [dvd_iff_exists_eq_mul_left]
  exact ⟨k, hk⟩
```

`dvd_iff_exists_eq_mul_left`의 진술:

```
dvd_iff_exists_eq_mul_left : a ∣ b ↔ ∃ k, b = k * a
```

즉 가분성을 **왼쪽 곱셈 형태**로 다시 적은 정리예요. 우리의 `CongMod` 정의와 같은 형태이므로, 이를 적용하면 변환이 자동 처리됩니다.

[ANALOGY] 방식 1은 "내가 직접 만든다", 방식 2는 "이미 있는 정리를 호명한다". 두 방식 모두 같은 결과를 줍니다. Lean 4에서는 이런 선택이 자주 등장해요.

[STUDENT TRY] 5분 활동. 두 방식 모두 따라쳐서 컴파일이 통과되는지 확인. 그리고 어느 쪽이 더 읽기 쉬운지 의견을 적어 보세요. (5분 대기)

## §4. 합동의 세 성질 (1) - 반사성

`CongMod` 관계가 동치 관계임을 보이려면 세 성질을 증명해야 해요. 반사성, 대칭성, 추이성입니다. 하나씩 직접 증명합니다.

**정리(반사성)** 모든 정수 `a`, `m`에 대해 `a ≡ a (mod m)`이에요.

[Q] 종이 증명이 뭘까요? (5초) 답: `a - a = 0 = 0 * m`이므로 증인 `k = 0`으로 성립.

[JOKE] 반사성은 "모든 사람은 자기 자신이다"라는 명제예요. 너무 자명해서 증명할 게 있나 싶죠. 그런데 형식 증명에서는 이 자명한 것도 한 줄 한 줄 명확히 적어야 합니다.

```lean
theorem CongMod_refl (m a : Int) :
    CongMod m a a := by
  unfold CongMod
  -- 목표: ∃ k : Int, a - a = k * m
  use 0
  -- 목표: a - a = 0 * m
  ring
```

[DEMO] 세 가지 새 요소.

**`unfold CongMod`** 정의 `CongMod`을 펼칩니다. 목표가 `CongMod m a a`에서 `∃ k : Int, a - a = k * m`으로 바뀌어요. 정의를 펼치는 것은 Lean 4가 정의의 약속을 따라 식을 변환하는 작업입니다.

**`use 0`** 존재 명제 `∃ k, ...`에서 증인 `k = 0`을 제시. 목표가 `a - a = 0 * m`으로 바뀝니다.

[Q] §4.1·§4.3에서는 `exact ⟨0, by ring⟩` 같은 꺽쇠 형태를 썼는데, 여기서는 왜 `use 0`인가요? (5초) 답: 둘 다 가능해요. 차이는 전술 모드(`by` 다음)에서 `use`가 더 자연스럽고, 표현 모드에서 `⟨..., ...⟩`이 더 짧다는 정도. 본 자료에서 두 형태를 보여 줍니다.

**`ring`** 다항식 항등식 자동 검증. `a - a`는 `0`이고 `0 * m`도 `0`이므로 등식 성립.

종이의 한 줄짜리 증명("a - a = 0 = 0 * m이므로")이 코드의 세 줄과 일대일 대응합니다.

## §5. 합동의 세 성질 (2) - 대칭성

**정리(대칭성)** `a ≡ b (mod m)`이면 `b ≡ a (mod m)`이에요.

[Q] 종이 증명? (5초) `a - b = k * m`이면 `b - a = -(a - b) = -(k * m) = (-k) * m`이므로 증인 `-k`로 성립.

```lean
theorem CongMod_symm (m a b : Int)
    (h : CongMod m a b) :
    CongMod m b a := by
  unfold CongMod at h ⊢
  obtain ⟨k, hk⟩ := h
  -- 증인 -k
  use -k
  -- 목표: b - a = -k * m
  rw [neg_mul]
  -- 목표: b - a = -(k * m)
  rw [← hk]
  ring
```

[DEMO] 새 요소들.

**`unfold CongMod at h ⊢`** 정의를 가정 `h`와 목표(`⊢`) **양쪽**에서 펼칩니다. `at h`만 적으면 `h`에서만, `at ⊢`만 적으면 목표에서만 펼침. 둘 다 하려면 `at h ⊢`처럼 함께 적어요.

[WATCH] `⊢` 기호 입력에 주의. 키보드의 일반 키가 아니에요. Lean 4 편집기에서 `\|-` 또는 `\vdash`를 치고 Enter.

펼친 후:
- `h : ∃ k, a - b = k * m`
- 목표: `∃ k, b - a = k * m`

**`obtain ⟨k, hk⟩ := h`** §3에서 본 패턴.

**`use -k`** 새 증인으로 `-k`를 제시.

**`rw [neg_mul]`** `neg_mul`의 진술: `(-a) * b = -(a * b)`. 목표 안의 `-k * m`을 `-(k * m)`으로 변환.

[Q] 왜 `neg_mul`을 명시적으로 호출해야 할까요? (5초) 답: Lean 4는 `-k * m`과 `-(k * m)`을 다른 표현으로 봅니다. 둘은 의미상 같지만 형태가 달라요. `neg_mul`이 두 형태 사이의 다리.

**`rw [← hk]`** `hk`를 역방향으로 적용. `hk`의 진술이 `a - b = k * m`이므로, `←` 방향은 `k * m → a - b`. 목표 안의 `k * m`이 `a - b`로 바뀌어요.

이제 목표는 `b - a = -(a - b)`. 이는 자명한 산술 항등식. `ring`이 닫음.

[ANALOGY] 대칭성 증명은 마치 거울을 보는 것 같아요. `a - b`와 `b - a`는 거울상이고, `-k`와 `k`도 거울상. 두 거울상이 등식으로 일치하는 걸 보이는 거죠.

## §6. 합동의 세 성질 (3) - 추이성

**정리(추이성)** `a ≡ b (mod m)`이고 `b ≡ c (mod m)`이면 `a ≡ c (mod m)`이에요.

[Q] 종이 증명? (10초) `a - b = k₁ * m`, `b - c = k₂ * m`이면 `a - c = (a - b) + (b - c) = (k₁ + k₂) * m`. 증인 `k₁ + k₂`.

```lean
theorem CongMod_trans (m a b c : Int)
    (h1 : CongMod m a b)
    (h2 : CongMod m b c) :
    CongMod m a c := by
  unfold CongMod at h1 h2 ⊢
  obtain ⟨k1, hk1⟩ := h1
  obtain ⟨k2, hk2⟩ := h2
  use k1 + k2
  -- 목표: a - c = (k1 + k2) * m
  rw [show a - c = (a - b) + (b - c) by ring]
  rw [hk1, hk2]
  ring
```

[DEMO] 새 요소.

**`rw [show a - c = (a - b) + (b - c) by ring]`** 특이한 형태예요. 인라인으로 보조 등식 `a - c = (a - b) + (b - c)`을 즉석에서 증명하고(`by ring`), 그것을 `rw`로 적용합니다. `show ... by ...`는 "이 명제를, 이 증명으로"라는 표현이에요.

[ANALOGY] 마치 요리할 때 "양념 만들기"가 필요해서 잠깐 옆에서 만들고 다시 본 요리로 돌아오는 것 같아요. 인라인으로 필요한 보조 사실을 만들고 바로 사용.

핵심: 우리 목표가 `a - c = ...` 형태이므로, 우선 `a - c`를 두 차의 합 `(a - b) + (b - c)`로 다시 씁니다. 그러면 양변에 `a - b`와 `b - c`가 노출되어 가설 `hk1`과 `hk2`를 적용할 수 있어요.

**`rw [hk1, hk2]`** 두 가설을 차례로 적용. 첫 번째: `a - b → k1 * m`. 두 번째: `b - c → k2 * m`. 결과: `(k1 * m) + (k2 * m) = (k1 + k2) * m`.

**`ring`** 마지막 다항식 항등식 검증. 분배 법칙으로 양변이 같음.

[Q] 추이성 증명에서 가장 절묘한 트릭이 뭐였죠? (5초) 답: `a - c`를 `(a - b) + (b - c)`로 분해한 것. 종이에서는 "두 등식을 그냥 더하자"라고 짧게 말하는데, 형식 증명에서는 이 분해를 명시적으로 적어 줘야 해요.

[AI] 동치 관계의 세 성질은 사실 모든 분류 시스템의 토대예요. AI가 데이터를 그룹별로 묶을 때, 두 데이터가 "같은 그룹"인지 판정하는 기준이 동치 관계입니다. 반사성·대칭성·추이성을 만족해야 일관된 분류가 가능해요. 본 자료에서 우리가 증명한 게 그런 분류의 수학적 토대 그 자체입니다.

## §7. 모듈러 역원의 존재 (베주 항등식 활용)

[교수자 멘트] 10분 휴식 후 본 자료의 첫 큰 정리로 들어갑니다. ... (휴식)

§4.4 강의의 강력한 정리예요. **확장된 유클리드 알고리즘**(extended Euclidean algorithm)의 직접 응용입니다.

**정리(모듈러 역원의 존재)** `gcd(a, m) = 1`이면, `a_bar · a ≡ 1 (mod m)`인 정수 `a_bar`가 존재합니다.

[Q] "모듈러 역원"이 무슨 의미일까요? (5초) 답: 곱셈으로 1을 만들어 주는 짝꿍 수. 예를 들어 mod 7에서 3 · 5 = 15 ≡ 1 (mod 7)이므로 5가 3의 mod 7 역원이에요.

[ANALOGY] 일반 곱셈에서 2의 역원은 1/2이죠. 그런데 정수에서는 1/2가 없어요. 모듈러 산술의 매력은 — 정수 안에서도 역원이 존재할 수 있다는 것입니다. 단, gcd 조건이 맞아야 해요.

**종이 증명의 핵심:**
- 베주 항등식: `gcd(a, m) = a · s + m · t`인 정수 `s`, `t`가 존재.
- 조건 `gcd(a, m) = 1`이면 `1 = a · s + m · t`.
- 양변에서 `m · t`를 빼면 `s · a - 1 = -(m · t) = (-t) · m`.
- 즉 증인 `s` (역원 후보)와 `-t` (`CongMod`의 증인)로 정확히 합동 관계 성립.

[Q] 종이 증명의 묘미가 어디 있을까요? (10초) 답: 베주 항등식이라는 추상 정리가 갑자기 구체적인 역원 `s`를 던져 줍니다. 추상이 즉시 구체로 바뀌는 순간이에요.

[JOKE] 저는 학부 때 처음 베주 항등식 증명을 봤을 때, "선생님, 그러면 그 s와 t는 어떻게 찾나요?"라고 물었던 기억이 있어요. 답은 "유클리드 호제법을 역으로 추적하면 된다"였죠. 즉 알고리즘이 자동으로 찾아 주는 거예요.

```lean
theorem inverse_exists
    (a m : Int) (_hm : 1 < m)
    (h_cop : Int.gcd a m = 1) :
    ∃ ā : Int, CongMod m (ā * a) 1 := by
  -- 베주 계수: Mathlib4에서 함수 Int.gcdA, Int.gcdB로 제공.
  set s := Int.gcdA a m
  set t := Int.gcdB a m
  -- 베주 항등식.
  have h_bezout : (1 : Int) = a * s + m * t := by
    have h := Int.gcd_eq_gcd_ab a m
    rw [h_cop] at h
    exact_mod_cast h
  -- 증인 ā = s
  use s
  unfold CongMod
  -- 증인 k = -t
  use -t
  -- 목표: s * a - 1 = -t * m
  have h1 : s * a - 1 = -(m * t) := by
    rw [h_bezout]
    ring
  rw [h1]
  ring
```

[DEMO] 본 자료에서 가장 흥미로운 코드. 여러 새 요소가 등장합니다.

### 부분 1. 베주 계수 도입

```lean
  set s := Int.gcdA a m
  set t := Int.gcdB a m
```

[Q] `Int.gcdA`, `Int.gcdB`가 뭘까요? (5초) 답: Mathlib에서 미리 계산해 둔 베주 계수 **함수**예요. 즉 `Int.gcdA a m`을 호출하면 `s`가, `Int.gcdB a m`을 호출하면 `t`가 자동으로 나옵니다.

[ANALOGY] 마치 자동으로 비밀번호를 생성해 주는 함수 같아요. 우리가 직접 유클리드 호제법을 역추적하지 않아도, Mathlib이 그 결과를 함수로 제공.

본 자료에서 가장 편리한 부분이에요. 베주 계수를 우리가 직접 계산할 필요 없이, Mathlib이 제공하는 함수로 받아 옵니다.

[WATCH] 학생들이 자주 묻습니다 — "그러면 `Int.gcdA 5 7`의 값은 뭐예요?" 답: `#eval Int.gcdA 5 7`로 직접 확인할 수 있어요. 결과는 3(5·3 + 7·(-2) = 1이므로 s = 3, t = -2).

### 부분 2. 베주 항등식 만들기

```lean
  have h_bezout : (1 : Int) = a * s + m * t := by
    have h := Int.gcd_eq_gcd_ab a m
    rw [h_cop] at h
    exact_mod_cast h
```

[DEMO] 세 단계.

**`Int.gcd_eq_gcd_ab`** Mathlib의 베주 항등식 정리. 진술:

```
Int.gcd_eq_gcd_ab : ∀ (a b : ℤ), ↑(Int.gcd a b) = a * Int.gcdA a b + b * Int.gcdB a b
```

말로 풀면 "gcd(a, b)는 a와 b의 정수 결합으로 표현 가능". 양변의 `gcd`는 자연수이지만 우변이 정수이므로 정수로 캐스팅된 형태로 진술됩니다.

[Q] `↑`가 뭘까요? (3초) 답: **자연수에서 정수로의 캐스팅 화살표**. `↑(Int.gcd a b)`는 "Int.gcd a b(자연수)를 정수로 변환한 값"이에요.

**`rw [h_cop] at h`** 가설 `h_cop : Int.gcd a m = 1`을 `h` 안에 적용. 결과: `h : (1 : ℕ) = a * s + m * t` (좌변이 1로 단순화).

[WATCH] `(1 : ℕ)`이 `(1 : ℤ)`로 자동 변환되지 않아요. Lean 4의 엄밀한 타입 시스템 때문이에요. 다음 단계에서 명시적으로 캐스팅합니다.

**`exact_mod_cast h`** 캐스팅 처리. 좌변이 `(1 : ℕ)`로 자연수인데 우리는 `(1 : Int)`를 원해요. `exact_mod_cast`가 자연수↔정수 캐스팅을 자동으로 맞춰 줍니다.

[ANALOGY] `exact_mod_cast`는 마치 통역사 같아요. 같은 사실을 다른 언어(자연수 언어 ↔ 정수 언어)로 번역해 줍니다.

### 부분 3. 중첩된 증인 제시

```lean
  use s
  unfold CongMod
  use -t
```

두 번 `use`가 등장합니다. 외부 결론은 `∃ ā, CongMod m (ā * a) 1`이고, `CongMod`의 정의도 `∃ k, ...`이므로 결국 **두 개의 존재 명제가 중첩**되어 있어요. 그래서 두 번 증인 제시.

[Q] 외부 증인과 내부 증인이 무엇이죠? (5초) 답:
- 외부 증인 `s`: 우리가 찾는 모듈러 역원 `ā = s`.
- 내부 증인 `-t`: 합동 정의의 `k` 부분. `s * a - 1 = (-t) * m`이라는 등식을 만족시키는 정수.

본 정리에서 가장 까다로운 부분이지만, 한 번 이해하면 다른 정리에서도 같은 패턴이 보여요.

### 부분 4. 마지막 등식

```lean
  have h1 : s * a - 1 = -(m * t) := by
    rw [h_bezout]
    ring
  rw [h1]
  ring
```

[DEMO] `have h1` 안: `h_bezout : 1 = a * s + m * t`를 적용해 `s * a - 1` 안의 `1`을 풀어쓰면 `s * a - (a * s + m * t)`, 정리하면 `-(m * t)`. `ring`이 자동 처리.

그 다음 `rw [h1]`로 목표를 `-(m * t) = -t * m`으로 다시 쓰고, `ring`으로 부호·곱셈 순서를 정리해 닫음.

[Q] 마지막 `ring`이 왜 필요할까요? (3초) 답: `-(m * t)`와 `-t * m`이 같은 표현이지만 정확히 같은 형태는 아니에요. `ring`이 가환환의 모든 변환을 처리해서 두 형태가 같음을 검증.

## §8. 모듈러 역원의 유일성

**정리(유일성)** `a`의 두 모듈러 역원은 `m`을 법으로 합동이에요. 즉 `a_1 * a ≡ 1`이고 `b_1 * a ≡ 1`이면 `a_1 ≡ b_1 (mod m)`.

[Q] 종이 증명? (10초) `a_1 * a - 1 = k_1 * m`, `b_1 * a - 1 = k_2 * m`. 두 등식을 적절히 결합하면 `a_1 - b_1`이 `m`의 정수배가 됨. 구체적으로 `b_1 * (a_1 * a - 1) - a_1 * (b_1 * a - 1) = b_1 * k_1 * m - a_1 * k_2 * m`. 좌변 정리하면 `a_1 - b_1`. 따라서 증인 `b_1 * k_1 - a_1 * k_2`.

```lean
theorem inverse_unique
    (a m a1 b1 : Int) (_hm : 1 < m)
    (_h_cop : Int.gcd a m = 1)
    (h1 : CongMod m (a1 * a) 1)
    (h2 : CongMod m (b1 * a) 1) :
    CongMod m a1 b1 := by
  obtain ⟨k1, hk1⟩ := h1
  obtain ⟨k2, hk2⟩ := h2
  refine ⟨b1 * k1 - a1 * k2, ?_⟩
  linear_combination b1 * hk1 - a1 * hk2
```

[DEMO] 본 자료에서 가장 강력한 자동화 전술이 등장합니다.

**`linear_combination`** 강력한 전술. 인수로 받은 표현(여기서는 `b1 * hk1 - a1 * hk2`)이 **주어진 등식들의 선형 결합**으로 목표를 닫음을 검증해요.

직관적으로: 가설 `hk1`이 등식 `A1 = B1`이고 `hk2`가 `A2 = B2`이면, `b1 * hk1 - a1 * hk2`는 "`b1 * A1 - a1 * A2 = b1 * B1 - a1 * B2`"라는 새 등식을 만들어요. 만약 그 새 등식이 우리 목표와 (대수적으로) 같다면 `linear_combination`이 즉결.

[ANALOGY] `linear_combination`은 마치 자동 대수 계산기예요. "이 등식들을 이렇게 조합하면 답이 나옵니다"라고 말하면, 계산기가 모든 분배·결합·교환을 자동으로 검증.

본 정리에서:
- `hk1 : a1 * a - 1 = k1 * m`
- `hk2 : b1 * a - 1 = k2 * m`
- `b1 * hk1 - a1 * hk2` → `b1 * (a1 * a - 1) - a1 * (b1 * a - 1) = b1 * k1 * m - a1 * k2 * m`
- 좌변 정리: `b1 * a1 * a - b1 - a1 * b1 * a + a1 = a1 - b1`.
- 우변 정리: `(b1 * k1 - a1 * k2) * m`.
- 결과: `a1 - b1 = (b1 * k1 - a1 * k2) * m`. 이것이 우리 목표.

`linear_combination`은 이 모든 대수 결합을 자동 검증합니다. **본 자료에서 가장 강력한 자동화 전술 중 하나**예요.

[Q] `linear_combination`과 `ring`의 차이가 뭘까요? (5초) 답: `ring`은 다항식 항등식만 처리(가정 없이). `linear_combination`은 주어진 가설 등식들의 선형 결합으로 목표 등식을 만드는 작업. 즉 `linear_combination`은 `ring`을 포함하는 더 강력한 전술이에요.

[WATCH] `linear_combination`이 막혔을 때는 종이로 손계산해서 정확한 계수를 찾아야 해요. 본 정리에서 `b1 * hk1 - a1 * hk2`라는 계수가 어떻게 나왔는지를 종이에서 먼저 도출하고, 그 결과를 Lean 4에 입력하는 거예요.

## §9. ZMod 환경에서의 구체 계산

[교수자 멘트] 10분 휴식 후 새로운 환경으로 갑니다. ... (휴식)

지금까지의 `CongMod` 정의와 `Int.ModEq`는 정수 위에서의 합동 관계를 다뤘어요. 그러나 Lean 4에는 더 강력한 도구가 있습니다. 바로 **`ZMod n`**이에요.

**`ZMod n`이란 무엇인가** `ZMod n`은 "정수를 `n`으로 나눈 나머지의 집합", 즉 `{0, 1, 2, ..., n-1}`을 환(ring)으로 만든 구조예요. 종이에서 `Z/nZ`로 쓰는 그 환과 같아요. `ZMod n`의 원소는 모듈러 산술의 자연스러운 표현입니다.

[Q] 왜 우리가 `ZMod n`이라는 새 환경이 필요할까요? (5초) 답: 합동 관계가 자동으로 등식이 되니까요. 예를 들어 `3 ≡ 10 (mod 7)`은 정수 위에서는 두 다른 정수의 합동 관계이지만, `ZMod 7`에서는 `(3 : ZMod 7) = (10 : ZMod 7)`이라는 그냥 등식이에요. `3 = 3`인 셈입니다.

[ANALOGY] 시계를 그릴 때 12시간 표기로 그리는 것과 같아요. 13시를 일부러 1시 자리에 그려 놓으면, "13시와 1시가 같은 자리"임이 그림으로 자명하죠. `ZMod n`은 그 시계 같은 환경.

**시연 1: 모듈러 역원의 명시적 검증**

종이에서 자주 푸는 문제: "3의 mod 7 역원은 무엇인가?" 답은 5. 검산: `3 * 5 = 15 = 14 + 1 ≡ 1 (mod 7)`.

```lean
example : (3 : ZMod 7) * 5 = 1 := by decide
```

본 한 줄이 위 사실의 형식 증명이에요. `ZMod 7` 환에서 `3 * 5`을 계산하면 `15 mod 7 = 1`이고, 우변도 `1`이므로 등식 성립. `decide`가 직접 계산으로 즉결.

[DEMO] `ZMod 7`이 얼마나 자연스러운 환경인지 시범을 보입니다. `decide` 한 줄로 충분.

**시연 2: 선형 합동의 가해성**

§4.4 강의의 중심 정리 중 하나. "`p`가 소수이고 `a`가 `ZMod p`에서 0이 아니면, 임의의 `b`에 대해 `a * x = b`의 해 `x`가 존재한다."

[Q] 이게 무엇을 의미하나요? (5초) 답: `ZMod p`(p 소수)가 **체**(field)라는 사실의 다른 표현이에요. 0이 아닌 모든 원소가 역원을 가집니다.

[ANALOGY] 체란 "사칙연산이 모두 가능한 환경"이에요. 자연수는 환이지만 체는 아니에요(2의 자연수 역원이 없으니까). 실수는 체. ZMod p(p 소수)도 체. 비유하자면 사칙연산이 자유로운 "성숙한" 환경.

```lean
example (a b : ZMod 7) (ha : a ≠ 0) :
    ∃ x : ZMod 7, a * x = b := by
  haveI : Fact (Nat.Prime 7) := ⟨by decide⟩
  refine ⟨a⁻¹ * b, ?_⟩
  field_simp
```

[DEMO] 네 가지 새 요소.

**`haveI : Fact (Nat.Prime 7) := ⟨by decide⟩`** `Fact`라는 typeclass에 인스턴스를 주입합니다. Mathlib의 많은 정리(특히 `ZMod p`가 체임을 활용하는 정리들)는 `[Fact (Nat.Prime p)]`라는 전역 가정을 요구해요. `Fact (Nat.Prime 7)`은 "7이 소수임을 typeclass 시스템이 알 수 있는 형태로 표현"한 것이고, `haveI`로 지역적으로 그 인스턴스를 만들어 줍니다. 안쪽은 `⟨by decide⟩`로 "7이 소수임"의 증명을 즉석에서 제공.

[Q] 왜 `have`가 아니라 `haveI`일까요? (5초) 답: `haveI`는 "typeclass 인스턴스로도 등록한다"는 의미예요. 후속 함수들이 자동으로 그 인스턴스를 찾아 쓸 수 있게 됩니다.

[WATCH] 학생들이 `Fact`라는 typeclass에 처음에는 혼란스러워 해요. 직관적 설명: "Fact는 사실을 typeclass로 포장하는 도구". `Nat.Prime 7`은 명제(증명되어야 할 사실), `Fact (Nat.Prime 7)`은 그 명제가 참임을 typeclass로 박아 둔 형태.

**`refine ⟨a⁻¹ * b, ?_⟩`** 증인을 제시. 종이 증명의 "해는 `x = a⁻¹ * b`이다" 그 자체. `?_`는 등식 `a * (a⁻¹ * b) = b`의 자리표시.

**`a⁻¹` 표기** `ZMod p`(p 소수)가 체이므로 0이 아닌 원소의 역원이 존재. `a⁻¹`은 `a`의 역원(즉 `a * a⁻¹ = 1`인 원소).

[Q] `a⁻¹` 입력은? (3초) 답: `\inv`를 치고 Enter. 또는 `\u207B u00B9`.

**`field_simp`** 분수·역원이 들어간 식을 자동으로 정리하는 전술. 우리 목표 `a * (a⁻¹ * b) = b`에서 `a * a⁻¹ = 1`이 적용되어 좌변이 `1 * b = b`로 정리되고, 우변과 일치.

[AI] `field_simp`는 컴퓨터 대수 시스템(CAS, Computer Algebra System)의 핵심 알고리즘이에요. 분수 식을 자동 정리하는 능력이 Mathematica, Maple, SymPy 같은 시스템의 자존심입니다. 우리가 Lean 4에서 한 줄로 호출하는 게 그 결과예요.

## §10. 중국 잉여 정리 (CRT)

§4.4 강의의 또 다른 빛나는 정리예요. 종이에서 본 정리의 모양:

**정리(중국 잉여 정리)** 자연수 `m`, `n`이 서로소이면, 임의의 `a`, `b`에 대해 다음 두 합동을 동시에 만족하는 `x`가 (mod `mn`에서) 유일하게 존재합니다.

```
x ≡ a (mod m),   x ≡ b (mod n).
```

[Q] 이 정리의 이름이 왜 "중국"인지 아시나요? (5초) 답: 3~4세기 중국의 수학자 손자(孫子)가 처음 제시한 문제 "**삼인동행칠십희, 오수매화이십일지, 칠자단오만조반, 백령오일정상지**"에서 비롯됩니다. "어떤 수를 3으로 나누면 2 남고, 5로 나누면 3 남고, 7로 나누면 2 남는다. 그 수는?" 답은 23.

[JOKE] 사실 손자가 풀이 알고리즘까지 적어 놨어요. "삼인동행칠십희"는 "3으로 나눈 나머지에 70을 곱한다". 1500년 전의 중국 수학자가 만든 알고리즘을 우리가 지금 Lean 4로 검증하는 거예요. 시간을 가로지르는 수학의 매력.

Mathlib에서는 이 정리를 더 일반적이고 우아한 형태로 진술합니다. **환 동형 사상**(ring isomorphism)으로 옮긴 것이에요.

**정리(CRT, 환 동형 형태)** `m`, `n`이 서로소이면, `ZMod (m * n) ≃+* ZMod m × ZMod n`.

[Q] 이 형태의 의미가 뭘까요? (10초) 답: "mn을 법으로 한 환은 m을 법으로 한 환과 n을 법으로 한 환의 직접곱(direct product)과 동형이다". 동형 사상은 어떤 원소 `x ∈ ZMod (m*n)`을 `(x mod m, x mod n) ∈ ZMod m × ZMod n`으로 보내는 자연스러운 사상.

[ANALOGY] 비유: 큰 도시 하나를 다루는 것보다, 작은 도시 두 개를 따로 다루는 게 더 쉬울 때가 있어요. CRT가 그 분할을 정확히 보장합니다. mn(큰 환경)을 m과 n(작은 환경 두 개)으로 분할해도 정보 손실이 없다는 것.

```lean
example (m n : ℕ) (hmn : Nat.Coprime m n) :
    ZMod (m * n) ≃+* ZMod m × ZMod n :=
  ZMod.chineseRemainder hmn
```

Mathlib의 `ZMod.chineseRemainder`가 정확히 이 정리예요. 인수로 서로소성 가정만 넘기면 환 동형이 돌아옵니다.

**기호 설명**
- `≃+*`: 환 동형 사상의 기호. 환의 덧셈·곱셈 구조를 모두 보존하는 양방향 일대일 대응.
- `Nat.Coprime m n`: `m`과 `n`이 서로소임의 명제. 정의는 `Nat.gcd m n = 1`.

[Q] `≃+*` 입력은? (3초) 답: `\equiv+*`. 또는 `\~=+*`. Lean 4 편집기에서 자동 변환.

**시연: 손자의 정리 사례**

종이의 고전 문제. 다음 세 합동을 동시에 만족하는 자연수가 있는가?

```
x ≡ 2 (mod 3),   x ≡ 3 (mod 5),   x ≡ 2 (mod 7).
```

[STUDENT TRY] 종이로 손계산해 보세요. 답은? (5분 대기)

답: 23. 검산: 23 = 7·3 + 2, 23 = 4·5 + 3, 23 = 3·7 + 2. 모두 성립.

105(= 3·5·7)를 법으로 한 유일한 해이기도 해요.

```lean
example : (23 : ZMod 105).val % 3 = 2 ∧
          (23 : ZMod 105).val % 5 = 3 ∧
          (23 : ZMod 105).val % 7 = 2 := by
  refine ⟨?_, ?_, ?_⟩ <;> decide
```

[DEMO] 새 요소들.

**`.val`** `ZMod n`의 원소를 자연수로 변환하는 메서드. `(23 : ZMod 105).val`은 `ZMod 105` 안의 `23`을 다시 자연수 `23`으로 보낸 값. 그 위에서 `% 3`, `% 5`, `% 7`을 적용해 각 모듈러를 봅니다.

**`refine ⟨?_, ?_, ?_⟩ <;> decide`** 세 합접의 결론을 세 자리표시로 분해하고, **모든 자리표시에 동시에** `decide`를 적용. 

[Q] `<;>` 연산자가 뭘까요? (3초) 답: "앞 전술의 모든 결과 부목표에 뒤의 전술을 적용"이라는 의미예요. 본 자료에서 새로 등장한 결합 표현. 세 개의 단순 계산을 한 줄에 묶어 처리합니다.

[WATCH] `<;>`(점뒤점, 또는 `t1 <;> t2`)와 `;`(세미콜론, `t1; t2`)의 차이. `;`는 "앞 전술 후 뒤 전술을 첫 부목표에만". `<;>`는 "앞 전술 후 뒤 전술을 모든 부목표에". 본 코드는 세 부목표 모두에 `decide`를 적용해야 하므로 `<;>`.

[AI] 중국 잉여 정리는 분산 컴퓨팅의 핵심 알고리즘이에요. 큰 수의 계산을 여러 작은 서버에 나눠 분산 처리할 때 CRT를 활용. 또한 RSA 암호의 효율적 구현(CRT-RSA)에서도 결정적인 역할을 합니다. AI의 분산 학습에서도 같은 원리가 활용돼요.

## §11. 페르마 소정리

§4.4의 클라이맥스예요.

**정리(페르마 소정리)** `p`가 소수이고 `a`가 `ZMod p`에서 0이 아니면, `a^(p-1) = 1` (in `ZMod p`).

[Q] 종이로 본 페르마 소정리의 의미가 뭐였죠? (5초) 답: "`a`가 `p`와 서로소이고 `p`가 소수이면 `a^(p-1) ≡ 1 (mod p)`이다." 17세기 페르마가 발견했고, 오일러가 일반화(`a^φ(n) ≡ 1`)했어요.

[JOKE] 페르마는 이 정리를 발견하고는 "증명을 적어 두고 싶지만 여백이 좁다"고 책 모서리에 적었어요(이건 마지막 정리 이야기지만, 페르마 소정리도 비슷한 분위기로 처음 알려졌습니다). 17세기 수학자의 깐깐함을 21세기 Lean 4가 한 줄로 증명합니다.

[AI] 페르마 소정리는 **RSA 암호의 직접적 토대**예요. RSA 키 생성 과정에서 페르마 소정리(또는 오일러의 일반화)가 결정적인 단계에 등장합니다. 인터넷 뱅킹, HTTPS, 카카오 결제 모두 이 정리에 의존해요.

```lean
example (p : ℕ) [Fact p.Prime] (a : ZMod p) (ha : a ≠ 0) :
    a ^ (p - 1) = 1 :=
  ZMod.pow_card_sub_one_eq_one ha
```

본 정리는 Mathlib의 `ZMod.pow_card_sub_one_eq_one`로 한 줄. 호출만 합니다.

`[Fact p.Prime]`은 **typeclass 인수**예요. 정리 선언의 대괄호 `[]` 안에 두면, Lean 4가 자동으로 적절한 인스턴스를 찾아 채워 줍니다. 우리는 `p`가 소수라는 사실을 정리의 전제로 두지만, 직접 인수로 받지는 않아요(인스턴스로 처리).

[Q] 그러면 본 정리를 사용할 때 우리가 `Fact p.Prime`을 어떻게 제공할까요? (5초) 답: 호출 문맥에서 `haveI : Fact (Nat.Prime p) := ⟨...⟩`로 인스턴스를 만들어 두면 자동으로 채워져요.

**따름정리** 모든 `a ∈ ZMod p`에 대해 `a^p = a`.

[Q] 종이 증명? (10초) `a = 0`이면 `0^p = 0`. `a ≠ 0`이면 페르마 소정리로 `a^(p-1) = 1`이고, 양변에 `a`를 곱하면 `a^p = a`.

```lean
example (p : ℕ) [Fact p.Prime] (a : ZMod p) : a ^ p = a := by
  have hpPrime : Nat.Prime p := Fact.out
  by_cases ha : a = 0
  · rw [ha, zero_pow hpPrime.pos.ne']
  · have h : a ^ (p - 1) = 1 := ZMod.pow_card_sub_one_eq_one ha
    have hp : p = (p - 1) + 1 := (Nat.sub_add_cancel hpPrime.pos).symm
    calc
      a ^ p
          = a ^ ((p - 1) + 1) := by rw [← hp]
        _ = a ^ (p - 1) * a   := pow_succ a (p - 1)
        _ = 1 * a             := by rw [h]
        _ = a                 := one_mul a
```

[DEMO] 본 자료에서 가장 큰 정리. 여러 새 요소를 풀어 봅시다.

**`Fact.out`** `[Fact p.Prime]` 인스턴스에서 내용물(`p.Prime`)을 꺼내는 메서드. 인스턴스로 받은 사실을 명시적인 가정 이름(`hpPrime`)으로 손에 쥡니다.

[ANALOGY] `Fact.out`은 마치 봉인된 상자를 여는 것 같아요. 타입클래스 안에 박아 둔 사실을 다시 명시적인 가정으로 꺼내는 거죠.

**`by_cases ha : a = 0`** 명제 `a = 0`과 그 부정 `¬ (a = 0)`으로 분기. 두 경우를 각각 `·`(점)으로 시작하는 줄에서 처리.

[Q] `by_cases`가 작동하려면 그 명제가 결정 가능해야 하나요? (5초) 답: 일반적으로는 그래요. 그런데 Lean 4는 classical 논리를 기본으로 채택하니까, 어떤 명제든 `by_cases`로 분기할 수 있어요. 단, 결정 가능한 명제는 계산도 가능하다는 장점이 있죠.

[WATCH] `by_cases`와 `cases`의 혼동. `by_cases`는 임의 명제로 분기(classical). `cases`는 귀납적 데이터 구조(예: 리스트, 자연수)의 모든 가지로 분기(constructive). 본 자료에서는 `by_cases`만 사용.

**경우 1: `a = 0`**

```lean
  · rw [ha, zero_pow hpPrime.pos.ne']
```

- `rw [ha]`: 목표 안의 `a`를 `0`으로 치환. 목표: `0 ^ p = 0`.
- `rw [zero_pow hpPrime.pos.ne']`: `zero_pow`의 진술은 `n ≠ 0 → (0 : α)^n = 0`. `hpPrime.pos.ne'`은 "`p`가 양수이므로 `p ≠ 0`"의 도출.

[Q] `.pos`와 `.ne'`의 의미는? (5초) 답:
- `.pos`: `Nat.Prime → 0 < p`. 소수는 양수.
- `.ne'`: `0 < n → n ≠ 0`. 양수는 0이 아님.

점 표기법을 연쇄해 짧게 적었어요.

**경우 2: `a ≠ 0`**

```lean
  · have h : a ^ (p - 1) = 1 := ZMod.pow_card_sub_one_eq_one ha
    have hp : p = (p - 1) + 1 := (Nat.sub_add_cancel hpPrime.pos).symm
    calc
      a ^ p
          = a ^ ((p - 1) + 1) := by rw [← hp]
        _ = a ^ (p - 1) * a   := pow_succ a (p - 1)
        _ = 1 * a             := by rw [h]
        _ = a                 := one_mul a
```

**페르마 소정리 적용** `have h := ZMod.pow_card_sub_one_eq_one ha`.

**`p = (p-1) + 1` 등식 도출** `Nat.sub_add_cancel hpPrime.pos`로 `p - 1 + 1 = p`를 얻고, `.symm`으로 좌우를 뒤집어 `p = (p - 1) + 1`.

[Q] `.symm`의 역할은? (3초) 답: `Eq.symm`의 점 표기법. `a = b`를 `b = a`로 뒤집기.

**`calc` 블록의 네 단계**

```
a ^ p
  = a ^ ((p - 1) + 1)   -- hp를 ← 방향으로 적용
  = a ^ (p - 1) * a     -- pow_succ
  = 1 * a               -- h를 적용
  = a                   -- one_mul
```

[ANALOGY] `calc` 블록은 마치 수학 노트에 등식 사슬을 적는 것 같아요. "그래서 = 그래서 = 그래서 = 답"의 자연스러운 형태.

## 부록 A. 자주 나오는 학생 질문

**Q1. `CongMod`을 우리가 굳이 정의해 봐야 했나요? `Int.ModEq`가 이미 있는데요.**  
A: 정의의 내부 동작을 손에 익히기 위함이에요. 한 번 직접 만들어 본 후에 라이브러리를 쓰는 게 깊은 이해를 위한 길.

**Q2. `unfold`와 `simp only [<정의 이름>]`의 차이가 뭐죠?**  
A: 둘 다 정의를 펼치는 효과. `unfold`는 직접적이고 단순함. `simp only [...]`는 더 강력하지만 부수 효과가 있을 수 있어요. 학습 단계에서는 `unfold`가 더 안전.

**Q3. `linear_combination`이 막혔을 때는 어떻게 하나요?**  
A: 종이로 손계산해서 정확한 계수를 찾아 보세요. 본 자료의 `b1 * hk1 - a1 * hk2` 같은 형태가 어떻게 나오는지를 종이에서 먼저 도출.

**Q4. `Fact (Nat.Prime p)`을 왜 쓰나요?**  
A: Mathlib의 많은 정리가 typeclass로 가정을 받기 때문이에요. `[Fact p.Prime]`이 인스턴스로 등록되어 있어야 `ZMod p`가 체로 인식됩니다.

**Q5. `≃+*`처럼 복잡한 기호를 어떻게 외우나요?**  
A: 외우는 게 아니라 패턴을 익히는 거예요. `≃`은 동형, `+`는 덧셈 보존, `*`는 곱셈 보존. 합치면 "환 동형 사상"이 자연스럽게 떠올라요.

**Q6. `by_cases`와 LEM의 관계는?**  
A: `by_cases`는 본질적으로 LEM(law of excluded middle, 배중률)에 의존해요. Lean 4는 classical 논리를 기본 채택해서 모든 명제에 LEM 적용 가능. constructive 환경에서는 결정 가능한 명제에만 적용 가능합니다.

**Q7. ZMod n과 Int.ModEq 중 어느 것을 써야 하나요?**  
A: 본격적인 계산이 필요하면 `ZMod n`(체나 환 구조 활용). 정수론적 명제만 다루면 `Int.ModEq`. 본 자료에서 둘 다 보여 줍니다.
