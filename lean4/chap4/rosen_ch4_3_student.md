# §4.1 가분성과 나머지 산술 

> Rosen 이산수학 8판 × Lean 4
> 정수론의 출발점이자 현대 암호학의 토대

---

지금이 오후 2시이다. 100시간 후는 몇 시인가?

답은 오후 6시이다. 어떻게? $100 = 24 \cdot 4 + 4$이므로, 100시간은 '하루 네 번 + 4시간'이다. 따라서 100시간 후 시각은 2시 + 4시간 = 6시.

이 한 줄짜리 시계 계산이 오늘 한 절(§4.1)의 모든 것이다. 같은 한 줄이 **HTTPS 연결**, **블록체인 해시**, **신용카드 보안코드**, 그리고 **ChatGPT가 우리 회사 문서를 검색하는 RAG 시스템**의 수학적 토대이다. 믿기지 않는다면 — 이 글이 끝날 때쯤 직접 납득하게 될 것이다.

## 1. 가분성 — 모든 정수론의 출발점

### 1.1 정의 — 'a가 b를 나눈다'의 진짜 의미

두 정수를 보고 '하나가 다른 하나를 나눈다'고 말하는 일은 너무 익숙해서 정의가 필요 없어 보인다. 그러나 수학에서 '익숙함'은 정의가 아니다.

**정의 1** ($a \neq 0$인 정수 $a, b$에 대하여)

> $a$가 $b$를 **나눈다**(divides)는 것은, $b = ac$를 만족하는 정수 $c$가 **존재한다**는 뜻이다. 이때 $a \mid b$로 쓴다. 나누지 않을 때는 $a \nmid b$로 쓴다.

읽기에는 평범하지만 한 단어가 결정적이다 — **'존재한다'**. 이것이 가분성을 단순한 '나눗셈'에서 '**참/거짓을 묻는 명제**'로 바꾼다.

#### 가장 흔한 함정

세로 막대 ' $\mid$ '는 나눗셈 기호 ' $\div$ '가 **아니다**. 둘은 종이 다른 두 가지 대상이다.

| 표현 | 의미 | 종류 |
|---|---|---|
| $3 \mid 12$ | '3이 12를 나눈다' | **명제** (참 또는 거짓) |
| $12 / 3$ | '12를 3으로 나눈 결과' | **값** (= 4) |

따라서 ' $3 \mid 12 = 4$ ' 같은 표현은 **잘못된 표현**이다. 명제와 값은 같다고 할 수 없다. 마치 ' $P \land Q = 5$ '라고 쓰는 것과 같다 — 종이 다르다. 이 점을 분명히 하고 가야 이후 합동을 만났을 때 다시 헤매지 않는다.

#### 예시로 점검

- $3 \mid 12$ — 참. $c = 4$가 존재한다( $12 = 3 \cdot 4$ ).
- $5 \nmid 23$ — 참. $23 = 5c$인 정수 $c$가 없다( 가장 가까운 것이 $c = 4.6$ ).
- $-4 \mid 28$ — 참. $c = -7$이 존재한다( $28 = -4 \cdot (-7)$ ).
- $17 \mid 0$ — 참. $c = 0$이 존재한다( $0 = 17 \cdot 0$ ). 모든 0이 아닌 $a$에 대해 $a \mid 0$이다.
- $0 \mid 5$ — Rosen의 정의 1은 $a \neq 0$을 요구하므로 이 표현은 **정의되지 않는다**.

### 1.2 첫 응용 — n 이하 d의 배수 개수

이 작은 도구를 어디에 쓸 수 있을까. 다음 질문을 보자.

> $n$ 이하의 양의 정수 중 $d$의 배수는 몇 개인가?

$d$의 양의 배수는 $d, 2d, 3d, \ldots$의 형태이다. ' $dk \le n$ '을 만족하는 양의 정수 $k$의 개수를 세면 된다. 그런데 ' $dk \le n$ '은 ' $k \le n/d$ '와 같으므로, **$k$의 개수는 $\lfloor n/d \rfloor$**이다.

예를 들어 100 이하의 7의 배수는 $\lfloor 100/7 \rfloor = 14$개이다. Python에서는 `100 // 7`로 같은 값을 즉시 얻는다 — '`//`'가 정수 나눗셈, 즉 '몫만 취하는 나눗셈'이다.

### 1.3 첫 Lean 4 증명 — ' $3 \mid 12$ '

Lean 4에서 가분성의 정의는 우리가 본 것과 거의 같다.

> `a ∣ b` ⟺ `∃ c, b = a * c`

'존재'는 Lean에서 `∃` 기호로 표기된다. 그리고 존재 명제를 증명하는 방법은 단순하다 — **증인을 제시한다**. 즉 ' $c$가 무엇인지 콕 짚어 보여 준다'.

```lean
example : (3 : ℤ) ∣ 12 := by
  exact ⟨4, by rfl⟩
```

이 한 줄을 풀어 읽으면 다음과 같다.

- `⟨_, _⟩`은 '존재 증명'을 만드는 형태이다. 첫째 자리에 증인 $c$를 두고, 둘째 자리에 ' $12 = 3 \cdot c$ '라는 등식의 증명을 둔다.
- 증인은 $c = 4$이다.
- 그리고 ' $12 = 3 \cdot 4$ '가 참이라는 사실은 — **양변을 계산하면 같다**. Lean에서는 이걸 `rfl`(reflexivity, 반사성)이라는 한 단어로 처리한다.

이게 여러분의 첫 공식 증명이다. 길지 않다 — 한 줄. 그러나 이 한 줄이 다음에 만날 모든 가분성 증명의 기본 패턴이다. **증인 제시 + 등식 검증**.

## 2. 정리 1 — 가분성의 세 가지 기본 성질

가분성을 한 번 정의해 두면 그것에서 파생되는 정리들이 도구처럼 쌓인다. 정리 1은 **이후 모든 정수론이 조립될 세 개의 레고 블록**이다.

**정리 1**. $a, b, c$가 정수라 하자.

- (i) $a \mid b$이고 $a \mid c$이면 $a \mid (b + c)$. (**합의 보존**)
- (ii) $a \mid b$이면 임의의 정수 $c$에 대하여 $a \mid bc$. (**곱의 보존**)
- (iii) $a \mid b$이고 $b \mid c$이면 $a \mid c$. (**연쇄성**)

세 조항 모두 증명 패턴이 동일하다.

> **(1) 가설에서 증인 꺼내기 → (2) 결론을 보일 새 증인 제시 → (3) 치환과 산술로 등식 검증**

이 패턴이 가분성·합동·정수론 전체를 관통한다. 일단 (i)을 손으로 천천히 풀어 본다.

### 2.1 정리 1-(i) 증명 — 수학적 단계

$a \mid b$이고 $a \mid c$라고 하자.

**(1단계)** $a \mid b$를 정의로 풀면, $b = as$인 정수 $s$가 존재한다. 이 $s$를 '**꺼낸다**'.

**(2단계)** 같은 방식으로, $c = at$인 정수 $t$가 존재한다.

**(3단계)** 이제 ' $a \mid (b+c)$ '를 보여야 한다. 즉 ' $b + c = a \cdot ?$ '을 만족하는 정수가 있어야 한다. 무엇이 후보인가? **$s + t$**.

**(4단계)** 검증한다.

$$b + c = as + at = a(s + t)$$

첫 등호는 1단계와 2단계의 치환이다. 둘째 등호는 분배법칙이다. 따라서 $b + c$가 $a$의 정수배(정수 $s + t$를 곱한 것)임이 보였다.

**(5단계)** 증인 $s + t$가 존재함을 확인했으므로, 정의에 의해 $a \mid (b + c)$. 증명 끝.

다섯 단계지만 본질은 셋 — **꺼내기, 제시, 검증**. 이 셋이 한 호흡으로 흘러간다.

### 2.2 정리 1-(i) Lean 4 증명 — 수학과 1:1 대응

위 증명을 Lean 4로 옮기면 거의 그대로이다.

```lean
theorem dvd_add_my (a b c : ℤ)
    (hab : a ∣ b) (hac : a ∣ c) :
    a ∣ (b + c) := by
  obtain ⟨s, hs⟩ := hab     -- (1) 가설에서 증인 s 꺼내기 → hs : b = a * s
  obtain ⟨t, ht⟩ := hac     -- (2) 가설에서 증인 t 꺼내기 → ht : c = a * t
  refine ⟨s + t, ?_⟩         -- (3) 새 증인 s + t 제시
  rw [hs]                    -- (4) b → a * s 치환
  rw [ht]                    -- (5) c → a * t 치환
  rw [← mul_add]             -- (6) 분배법칙 역방향: a*s + a*t → a*(s+t)
```

각 줄이 수학 단계와 정확히 짝을 이룬다.

- `obtain` — 가설 안에 숨어 있는 '존재' 증인을 '**꺼내는**' 동작.
- `refine ⟨_, ?_⟩` — 결론의 '존재' 증인을 '**제시하는**' 동작. 빈 자리(`?_`)는 '그 다음에 채울 등식'이다.
- `rw` — '**rewrite**', 즉 등식을 이용한 치환. 우리가 수학에서 ' $b$를 $as$로 바꾼다'고 말하는 것과 똑같다.

#### 한 가지 — 화살표가 왜 거꾸로?

마지막 줄 `rw [← mul_add]`에서 화살표 ' $\leftarrow$ '가 거꾸로 붙어 있다. 왜 그런가?

Mathlib의 `mul_add`라는 정리가 있다. 그 진술은 다음과 같다.

> $a \cdot (b + c) = a \cdot b + a \cdot c$

좌변에서 우변으로 가는 방향이 '분배해서 펼친다'이다. 이게 **기본 방향**이다. 그런데 우리가 지금 하고 싶은 일은 그 반대 — ' $a \cdot s + a \cdot t$ '를 ' $a \cdot (s + t)$ '로 **합치는** 것이다. 즉 정리를 **거꾸로 적용**하고 싶다. 그래서 `rw` 앞에 ' $\leftarrow$ ' 화살표가 붙는다.

직관적으로 말하면, **' $\leftarrow$ '는 '덜 풀린 형태로 돌아가라'는 명령**이다. 이걸 손에 익히면 Lean 증명의 절반은 완성된 셈이다.

### 2.3 정리 1-(ii), (iii) — 같은 패턴의 반복

(ii)와 (iii)도 같은 패턴이다.

**(ii)** $a \mid b$이면 $a \mid bc$.

수학 증명 — $b = as$인 $s$를 꺼낸다. 새 증인은 $sc$. 검증: $bc = (as)c = a(sc)$ — 결합법칙이다. 끝.

```lean
theorem dvd_mul_right_my (a b : ℤ) (hab : a ∣ b) (c : ℤ) :
    a ∣ (b * c) := by
  obtain ⟨s, hs⟩ := hab
  refine ⟨s * c, ?_⟩
  rw [hs]
  rw [mul_assoc]
```

**(iii)** $a \mid b$이고 $b \mid c$이면 $a \mid c$.

수학 증명 — $b = as$, $c = bt$를 꺼낸다. 새 증인은 $s \cdot t$. 검증: $c = bt = (as)t = a(st)$. 결합법칙으로 한 번 더 정리. 끝.

세 조항을 모두 직접 손으로 한 번씩 풀어 보는 것이 강력하게 권장된다 — 워크북에 빈칸 형태로 들어 있다.

### 2.4 따름정리 1 — 첫 '조립' 증명

세 블록을 갖춘 다음에는 **조립**이 가능해진다.

**따름정리 1**. $a \mid b$이고 $a \mid c$이면, 임의의 정수 $m, n$에 대해 $a \mid (mb + nc)$.

증명에 새로운 아이디어는 필요 없다. 이미 만든 두 도구 — 정리 1의 (i)와 (ii) — 만 조립한다.

- **정리 1-(ii)** 두 번 적용:
  - $a \mid b \Rightarrow a \mid mb$
  - $a \mid c \Rightarrow a \mid nc$
- **정리 1-(i)** 한 번 적용:
  - $a \mid mb$이고 $a \mid nc \Rightarrow a \mid (mb + nc)$.

증명 끝.

이런 '조립'이 수학 라이브러리가 자라는 방식이다. **새 정리를 만날 때, 처음부터 다시 풀지 않는다 — 이미 증명한 도구를 찾아 조립한다**. 그리고 — 이 '**도구를 찾아 조립한다**'는 동작이 곧 **현대 AI 자동 증명기의 핵심 동작**이다. 이것이 곧 등장할 RAG 이야기의 시작이다.

## 3. 나눗셈 알고리즘 — 몫과 나머지

지금까지 '나눠떨어지는 경우'($a \mid b$)만 다뤘다. 그러나 정수의 나눗셈은 보통 '떨어지지 않고 나머지가 남는' 경우이다. 이 경우의 정확한 진술이 다음 정리이다.

**정리 2 (나눗셈 알고리즘, Division Algorithm)**. $a \in \mathbb{Z}$, $d \in \mathbb{Z}^+$일 때, 다음 두 조건을 만족하는 정수 $q, r$이 **유일하게 존재**한다.

$$a = dq + r, \qquad 0 \le r < d$$

여기서 $d$는 **약수**(divisor), $a$는 **나뉠수**(dividend), $q$는 **몫**(quotient), $r$은 **나머지**(remainder)이다.

'유일하게 존재한다'와 ' $0 \le r < d$ ' 두 조건이 이 정리의 핵심이다. 후자가 없으면 같은 $a, d$에 대해 무한히 많은 $(q, r)$ 쌍이 가능하다.

### 3.1 두 예제

**예제 1**. 101을 11로 나누어 보자. 가장 가까운 11의 배수는 99이다. 따라서

$$101 = 11 \cdot 9 + 2 \quad (q = 9,\ r = 2).$$

직관적이다.

**예제 2**. $-11$을 3으로 나누어 보자. 여기서 학생들이 자주 막힌다.

' $-11 = 3 \cdot (-3) - 2$ '라고 쓰면 어떨까? 식 자체는 맞다. 그러나 정의가 요구하는 ' $0 \le r < d$ '를 위반한다 — $r = -2$가 음수이다. **따라서 정의상 답이 아니다**.

올바른 답은 다음이다.

$$-11 = 3 \cdot (-4) + 1 \quad (q = -4,\ r = 1).$$

'몫을 한 칸 더 음수로 내려'($-3 \to -4$) 나머지가 양수가 되도록 보정한다. 음수 나누기에서 항상 일어나는 보정이다.

### 3.2 결정적 주의점 — 언어별 mod 연산자 차이

같은 ' $\%$ ' 기호가 프로그래밍 언어마다 다른 답을 낸다. 이것이 수많은 보안 버그의 원인이 되어 왔다.

| 환경 | `(-11) % 3`의 결과 | 의미 |
|---|---|---|
| 수학 정의 | 1 | $0 \le r < d$ 보장 |
| Python | 1 | 수학과 동일 |
| Lean 4 (Int) | 1 | 수학과 동일 |
| C / C++ / Java | $-2$ | 피제수와 같은 부호 |
| BASIC, Maple, Excel | 1 | 수학과 동일 |

C·C++·Java에서 ' $-11 \% 3 = -2$ '가 나오는 이유는 — 이들 언어가 '**피제수와 같은 부호**'를 가진 나머지를 반환하도록 정의되어 있기 때문이다. 수학적 정의를 따르지 않는다.

이 차이는 무서운 결과를 낳을 수 있다. 예를 들어 다음과 같은 보안 코드를 보자.

```c
int bucket = hash(input) % N;
buckets[bucket].add(input);
```

`hash(input)`이 음수를 반환하면 `bucket`이 음수가 된다. C에서는 `(-12345) % 256`이 음수이고, `buckets[-12345 % 256]`은 **배열 범위를 벗어난 메모리**에 접근한다. 이는 단순한 **세그멘테이션 폴트**일 수도, 더 심각하게는 **임의 메모리 읽기·쓰기 취약점**일 수도 있다. 1990~2000년대 보안 패치 로그에는 이 종류의 버그가 수백 건 기록되어 있다.

요점은 — **언어가 수학적 정의를 따르는지 항상 확인하라**. 모듈로 산술이 곧 만날 합동의 토대이고, 거기서도 같은 규칙이 적용된다.

## 4. 합동 — 새로운 수 세계로의 입구

지금까지의 도구로 한 발만 더 디디면 완전히 새로운 풍경이 열린다. 그 한 발이 **합동**(congruence)이다.

### 4.1 정의 — '모듈로 m에서 같다'

**정의 3**. 정수 $a, b$와 양의 정수 $m$에 대하여,

$$a \equiv b \pmod m \iff m \mid (a - b)$$

라고 정의한다. 이때 $a$와 $b$는 '**모듈로 $m$에서 합동**'이라 읽는다.

직역하면 ' $a$와 $b$의 차이가 $m$의 배수이다'. 그러나 직관적으로 더 좋은 해석은 '**모듈로 $m$ 기준에서 보면 두 수가 구분되지 않는다**'이다.

#### 일상 비유 — 요일

오늘이 수요일이라고 하자. 7일 후도 수요일이다. 14일 후도 수요일이다. 700일 후도 수요일이다. **요일 기준에서 이 모든 날은 같은 날**이다.

- $0 \equiv 7 \equiv 14 \equiv \cdots \pmod 7$

이것이 합동이다. ' $m$이라는 기준을 지웠을 때 같다'.

#### 예제로 점검

- $17 \equiv 5 \pmod 6$ ? $17 - 5 = 12 = 6 \cdot 2$. **참**.
- $24 \equiv 14 \pmod 6$ ? $24 - 14 = 10$. $6 \nmid 10$이므로 **거짓**.
- $-7 \equiv 5 \pmod 6$ ? $-7 - 5 = -12 = 6 \cdot (-2)$. **참**.

#### 함정 — 합동과 mod의 차이

다음 두 표현을 분명히 구분해야 한다.

| 표현 | 의미 | 종류 |
|---|---|---|
| $a \equiv b \pmod m$ | '모듈로 $m$에서 같다' | **관계** (참 또는 거짓) |
| $a \;\mathrm{mod}\; m$ | ' $a$를 $m$으로 나눈 나머지' | **값** (정수) |

전자는 명제이다. 두 수에 대해 '참인가 거짓인가'를 묻는다. 후자는 함수이다. 한 수를 받아 한 수를 돌려준다. 둘은 동치이지만(다음 정리들이 그것을 증명한다) **종이 다르다**. 이 점을 분명히 하면 이후 합동 증명에서 헤매지 않는다.

### 4.2 정리 3, 4 — 합동과 mod의 연결

**정리 3**. $a \equiv b \pmod m \iff a \;\mathrm{mod}\; m = b \;\mathrm{mod}\; m$.

즉, '관계 $\equiv$ '와 '값의 등식 $\mathrm{mod}$ '가 동치이다. 두 종이 다른 두 표현이 같은 사실을 가리킨다는 뜻이다.

**정리 4**. $a \equiv b \pmod m \iff a = b + km$인 정수 $k$가 존재한다.

이것이 **합동을 풀어쓴 등식**이다. '관계'를 ' $a = b + km$ '이라는 **단순한 등식**으로 변환한다. 거의 모든 합동 증명이 이 다리를 건너간다 — 페르마 소정리, 오일러 정리, RSA 정확성 증명, 모두.

### 4.3 정리 4의 Lean 4 증명 — 양방향

' $\Leftrightarrow$ '는 두 방향의 ' $\Rightarrow$ '의 결합이다. 따라서 두 방향 모두 증명해야 한다. Lean 4에서는 `constructor` 전술로 ' $\Leftrightarrow$ '를 두 개의 ' $\Rightarrow$ '로 쪼갠다.

```lean
def MyCong (m a b : ℤ) : Prop := m ∣ (a - b)

theorem myCong_iff (m a b : ℤ) :
    MyCong m a b ↔ ∃ k, a = b + k * m := by
  constructor
  -- (→) 방향: 가분성 → 등식
  · intro h
    obtain ⟨k, hk⟩ := h          -- hk : a - b = m * k
    refine ⟨k, ?_⟩
    rw [← sub_add_cancel a b]    -- a = (a - b) + b
    rw [hk]                       -- (a - b) → m * k
    rw [add_comm]                 -- m*k + b → b + m*k
    rw [mul_comm m k]             -- m*k → k*m
  -- (←) 방향: 등식 → 가분성
  · intro h
    obtain ⟨k, hk⟩ := h          -- hk : a = b + k * m
    refine ⟨k, ?_⟩
    rw [hk]
    rw [add_sub_cancel_left]
    rw [mul_comm]
```

각 줄은 정확한 의도를 가진다. 예를 들어 `rw [← sub_add_cancel a b]`는 ' $a$를 $(a-b) + b$로 풀어쓴다'는 동작이다. 그 풀어쓴 자리에 가설 $hk$를 치환할 빈자리가 생긴다. ' $\leftarrow$ ' 화살표가 두 번 등장하는데, 둘 다 '덜 풀린 형태로 돌아가라'는 같은 의미이다.

### 4.4 정리 5 — 합동은 + 와 ·에서 보존된다

**정리 5**. $a \equiv b \pmod m$이고 $c \equiv d \pmod m$이면, 다음이 성립한다.

$$a + c \equiv b + d \pmod m, \qquad ac \equiv bd \pmod m.$$

이 정리가 합동의 꽃이다. 합동이 산술 연산에서 보존된다는 사실 덕분에, **'모듈로 $m$ 대수'**라는 새로운 세계가 가능해진다. 식 변형, 방정식 풀이, 대수적 조작이 정수에서와 거의 같은 방식으로 진행된다.

#### 직접 체험 — 큰 수의 mod 계산

이 정리가 얼마나 강력한지 한 번 손으로 확인해 보자.

> $7^{100} \;\mathrm{mod}\; 5$를 계산하라.

' $7^{100}$이 80자리에 가까운 거대한 수인데 어떻게?' — 정리 5 덕분에 가능하다.

- $7 \equiv 2 \pmod 5$이므로, $7^{100} \equiv 2^{100} \pmod 5$.
- $2^4 = 16 \equiv 1 \pmod 5$이므로, $2^{100} = (2^4)^{25} \equiv 1^{25} = 1 \pmod 5$.

**답: 1**. 계산기 없이 10초 안에 구할 수 있다. $7^{100}$ 자체는 80자리 거대 수이지만, 모듈로 5로 보면 그저 $1$이다. **거대한 수 계산을 작은 수 계산으로 바꾸는 마법** — 이것이 RSA 등 현대 암호학이 가능한 핵심 이유이다.

#### 함정 — 합동에서 양변 나누기

정리 5는 합동이 ' $+$, $\cdot$에서 보존된다'고 말한다. **나눗셈은 포함되어 있지 않다**. 그리고 실제로 — 일반적으로 양변을 같은 수로 나눌 수 없다.

> $2 \cdot 3 \equiv 2 \cdot 0 \pmod 6$은 참이다. 검산: $2 \cdot 3 = 6 \equiv 0$, $2 \cdot 0 = 0 \equiv 0$.
> 그러나 양변을 2로 나누어 ' $3 \equiv 0 \pmod 6$ '은 **거짓**이다($3 - 0 = 3$, $6 \nmid 3$).

언제 양변을 나눌 수 있는가? **나누는 수 $c$와 모듈 $m$이 서로소**일 때만 가능하다. 즉 $\gcd(c, m) = 1$일 때. 자세한 내용은 §4.3 베주 정리와 함께 다룬다.

### 4.5 정리 5(합)의 Lean 4 증명

정리 5는 두 부분(합, 곱)으로 구성된다. 합 부분의 증명을 본다. 한 가지 도구를 미리 만든다.

```lean
lemma sub_add_sub_split (a b c d : ℤ) :
    (a + c) - (b + d) = (a - b) + (c - d) := by ring
```

이는 순수한 정수 산술 항등식으로 `ring`을 한 번 사용해 정당화된다. 이 보조 정리를 활용하면 본 증명은 정리 1-(i)와 거의 같은 패턴이다.

```lean
theorem myCong_add (m a b c d : ℤ)
    (hab : MyCong m a b) (hcd : MyCong m c d) :
    MyCong m (a + c) (b + d) := by
  unfold MyCong at hab hcd ⊢
  obtain ⟨s, hs⟩ := hab
  obtain ⟨t, ht⟩ := hcd
  refine ⟨s + t, ?_⟩
  rw [sub_add_sub_split a b c d]
  rw [hs]
  rw [ht]
  rw [← mul_add]
```

새로운 정리이지만 **새로운 아이디어는 거의 없다**. 정리 1-(i)에서 만든 도구와 '차이를 분리하는' 보조 정리 하나만 추가했을 뿐. 수학 라이브러리는 이런 식으로 자란다.

### 4.6 따름정리 2 — ' $\mathrm{mod}$의 합과 곱'

정리 5를 '값'의 언어로 옮기면 다음 따름정리가 나온다.

**따름정리 2**. 정수 $a, b$와 양의 정수 $m$에 대해

$$(a + b) \;\mathrm{mod}\; m = ((a \;\mathrm{mod}\; m) + (b \;\mathrm{mod}\; m)) \;\mathrm{mod}\; m,$$

$$(ab) \;\mathrm{mod}\; m = ((a \;\mathrm{mod}\; m) \cdot (b \;\mathrm{mod}\; m)) \;\mathrm{mod}\; m.$$

해석은 이렇다 — **큰 수의 mod는 각 항을 먼저 mod 한 뒤 연산해도 같은 답이다**. 그러면 **중간 계산 값이 절대 $m$을 넘지 않는다**. 메모리 폭발 없이 거대한 지수승이 가능해진다.

Python에서는 이미 이 사실을 반영한 `pow(base, exp, mod)`라는 함수가 표준으로 들어 있다.

```python
>>> pow(2, 1000, 1000000007)
688423210
```

$2^{1000}$은 약 300자리 수이지만, 이 함수는 그것을 직접 계산하지 않는다. 매 단계에서 mod로 잘라내기 때문에 0.001초 안에 답이 나온다. 따름정리 2가 이 알고리즘의 정당성을 보장한다.

다음 절(§4.2)에서 이를 체계적으로 처리하는 '**빠른 나머지 지수승**'(square-and-multiply) 알고리즘을 만들 것이다. 이것이 RSA 암호의 1/3에 해당하는 핵심 부품이다.

## 5. 새로운 수 세계 — $\mathbb{Z}_m$과 군

### 5.1 군 — 가장 단순한 대수 구조

'군'(group)이라는 단어를 처음 만나면 부담스럽지만, 한 줄짜리 직관이다.

> **군은 '되돌릴 수 있는 연산'이 있는 집합이다**.

' $+3$ '이라는 동작은 ' $-3$ '으로 되돌릴 수 있다. 30도 회전은 $-30$도 회전으로 되돌릴 수 있다. 이렇게 항상 '되돌림'이 가능한 연산을 가진 집합 — 그것이 군이다.

왜 이런 추상적 이름을 붙이는가? 한 마디로 **재사용**이다. 한 번 '이 집합은 군이다'가 증명되면, 군 일반에 대해 이미 증명된 모든 정리(항등원의 유일성, 역원의 유일성, 소거 법칙 등)가 **공짜로** 그 집합에 따라온다. 코딩의 라이브러리와 같은 이치이다.

### 5.2 군의 정의 — 4공리 + 교환군

**정의**. 집합 $G$와 이항연산 $* : G \times G \to G$의 쌍 $(G, *)$가 다음 네 공리를 모두 만족할 때, **군**(group)이라 한다.

- **(G1) 폐쇄성** — $a, b \in G$이면 $a * b \in G$. 연산 결과가 집합 밖으로 나가지 않는다.
- **(G2) 결합성** — $(a * b) * c = a * (b * c)$. 괄호를 어떻게 쳐도 결과가 같다.
- **(G3) 항등원** — 모든 $a$에 대해 $e * a = a * e = a$인 원소 $e \in G$가 존재한다.
- **(G4) 역원** — 각 $a \in G$마다 $a * b = b * a = e$인 $b \in G$가 존재한다. 이 $b$를 $a^{-1}$로 쓴다.

여기에 다음 공리를 추가로 만족하면 **교환군**(abelian group)이라 부른다.

- **(G5) 교환성** — $a * b = b * a$.

### 5.3 친숙한 예와 반례

**군이 되는 예** — $(\mathbb{Z}, +)$, $(\mathbb{Q}, +)$, $(\mathbb{R}, +)$. 그리고 0을 제외한 곱셈군 $(\mathbb{Q} \setminus \{0\}, \cdot)$, $(\mathbb{R} \setminus \{0\}, \cdot)$. 행렬군 $(\mathrm{GL}(n, \mathbb{R}), \cdot)$ — 이는 비교환군의 대표 예이다.

**군이 아닌 반례**:

- $(\mathbb{N}, +)$ — (G4) 위반. 1의 덧셈 역원은 $-1$인데 자연수 집합에 없다.
- $(\mathbb{Z}, \cdot)$ — (G4) 위반. 2의 곱셈 역원은 $1/2$인데 정수 집합에 없다.

핵심 통찰은 다음이다 — **군 판정의 결정적 단계는 거의 항상 (G4) 역원**이다. 폐쇄성·결합성·항등원은 자명한 경우가 많다. 역원이 있느냐 없느냐가 군이냐 아니냐를 가른다.

### 5.4 $(\mathbb{Z}_m, +_m)$이 교환군임 — 1:1 검증

이제 §4.1의 정점이다. **$\mathbb{Z}_m = \{0, 1, 2, \ldots, m-1\}$**과 'mod $m$ 덧셈' $+_m$의 쌍이 교환군임을 보인다. 다섯 공리를 차례로 점검하자.

- **(G1) 폐쇄성**. $+_m$은 정의상 결과에 mod $m$을 취하므로 항상 $0 \le r < m$인 값을 돌려준다. 자동으로 $\mathbb{Z}_m$ 안.
- **(G2) 결합성**. 정수에서 결합성이 성립하고, **정리 5**가 그것을 mod 산술로 옮겨 온다. 50분 전에 증명한 정리 5가 여기서 빛을 발한다.
- **(G3) 항등원**. $0 \in \mathbb{Z}_m$이 항등원. 자명.
- **(G4) 역원**. **결정적 단계**. $a \neq 0$이면 $m - a$가 $a$의 덧셈 역원이다. 검산: $a +_m (m - a) = m \;\mathrm{mod}\; m = 0$. 그리고 $0 < m - a < m$이므로 $m - a \in \mathbb{Z}_m$. 0 자신의 역원은 0.
- **(G5) 교환성**. 정수의 교환성을 정리 5로 mod 산술에 옮긴다.

**결론** — $(\mathbb{Z}_m, +_m)$은 모든 양의 정수 $m$에 대해 **교환군**이다. 이것이 §4.1이 보여 주는 '**완전히 새로운 수 세계가 잘 정의된 대수 구조를 갖는다**'의 증명이다.

### 5.5 $(\mathbb{Z}_m, \cdot_m)$은 군이 아니다

곱셈으로 가면 이야기가 달라진다. **$(\mathbb{Z}_6, \cdot_6)$은 군이 아니다**.

이유 — 2의 곱셈 역원이 $\mathbb{Z}_6$에 없다. 직접 표를 그려 본다.

| $b$ | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| $2 \cdot_6 b$ | 0 | 2 | 4 | 0 | 2 | 4 |

표 어디에도 '1'이 나타나지 않는다. 즉 $2 \cdot_6 b = 1$인 $b \in \mathbb{Z}_6$가 없다. (G4) 위반.

**왜 그런가**? $\gcd(2, 6) = 2 \neq 1$이기 때문이다. 다음의 사실이 정확한 조건이다.

> $\mathbb{Z}_m$에서 $a$의 곱셈 역원이 존재한다 $\iff$ $\gcd(a, m) = 1$.

그리고 — ** $m$이 소수 $p$ **이면, $1$부터 $p-1$까지 모든 원소가 $p$와 서로소이다. 따라서 **0이 아닌 모든 원소가 곱셈 역원을 가진다**. 이것이 ' $\mathbb{Z}_p$가 **체**(field)'라는 강한 성질이다. 그리고 — **이것이 RSA, ECDSA, 공개키 암호 전체가 ' $\mathbb{Z}_p$ ($p$ 소수)' 위에서 작동하는 이유**이다.

### 5.6 Lean 4 — Mathlib의 자동 인스턴스 등록

지금까지 손으로 한 다섯 공리 증명을 Mathlib은 더 일반화된 형태로 이미 가지고 있다. 우리는 그것을 '**소비**'할 수 있다.

```lean
import Mathlib

-- ℤ_m은 임의의 m에 대해 덧셈에 관한 교환군이다
example (m : ℕ) [NeZero m] : AddCommGroup (ZMod m) := inferInstance

-- ℤ_7에서 3의 덧셈 역원은 4
example : (3 : ZMod 7) + 4 = 0 := by rfl

-- 결합성·교환성 자동 활용
example (a b : ZMod 7) : a + b = b + a := by rw [add_comm]
```

`inferInstance`는 '**Mathlib이 알아서 찾아 다오**'라는 뜻이다. 'ZMod m이 AddCommGroup'임이 라이브러리에 등록되어 있어, 한 단어로 활용된다.

## 6. 최신 AI · 암호학과의 연결

§4.1에서 다룬 도구들 — 가분성, 정리 1, 합동, 정리 5, $\mathbb{Z}_m$ 군 구조 — 이 현대 AI의 세 기둥에 어떻게 살아 있는지 본다.

### 6.1 RAG와 LSH — 검색 일관성

**RAG**(Retrieval-Augmented Generation)는 LLM(GPT, Claude, Gemini 등)이 답을 만들 때 외부 지식 베이스에서 관련 자료를 먼저 검색한 뒤 그 자료를 참고하여 답하게 하는 방법이다. 사실상 ChatGPT 시대 LLM 응용의 표준 구조이다.

RAG의 검색 단계는 수백만 개 문서 청크를 매번 비교할 수 없기 때문에 **Locality-Sensitive Hashing**(LSH)으로 가속한다. LSH는 '비슷한 벡터는 같은 해시 버킷에 떨어지게'라는 성질을 가진 해시 함수를 여러 개 적용한다.

이 해시 함수 안에 ' $h(x) = (\sum a_i x_i) \;\mathrm{mod}\; p$ ' 같은 **모듈로 큰 소수 산술**이 들어 있다. 그리고 §4.1의 정리 5('합동은 +, ·에서 보존')가, 분산 환경에서 청크별로 따로 해시를 계산해도 결과가 깨지지 않음 — 즉 **검색 일관성** — 을 수학적으로 보장한다.

(이 부분이 학생에게 직관적으로 와 닿지 않으면, 따로 마련된 **rag_interactive.html** 부속 자료에서 단계별 시뮬레이션으로 확인해 보길 권한다.)

### 6.2 LLM의 RoPE — 위치 인코딩의 주기성

GPT-4, Claude, Gemini 모두 사용하는 **RoPE**(Rotary Position Embedding)는 토큰 위치를 인코딩할 때 다음 형태의 회전을 사용한다.

$$\mathrm{RoPE}(x, \mathrm{pos}) = x \cdot e^{i \cdot \mathrm{pos} \cdot \theta}$$

여기서 '회전 각도 mod $2\pi$ '가 핵심 — 즉 **연속판 $\mathbb{Z}_m$ **이다. 정수 대신 실수이지만, '**주기성**'이라는 핵심 직관은 동일하다. '위치가 멀어져도 같은 패턴이 다시 나타난다'는 RoPE의 강점이 'mod $m$ '의 순환성과 같은 자리에서 나온다.

### 6.3 RSA — 빠른 나머지 지수승

RSA 암호화는 ' $m^e \;\mathrm{mod}\; N$ '을 빠르게 계산하는 것이 핵심이다. 다음 절(§4.2)에서 다룰 '**빠른 나머지 지수승**'(square-and-multiply) 알고리즘이 RSA의 1/3에 해당하는 부품이다. 그 정당성은 우리가 본 **따름정리 2**('mod의 합과 곱')에 의해 보장된다.

### 6.4 AlphaProof — 자동 증명기의 RAG

**DeepMind AlphaProof**(2024)는 IMO 2024에서 6문제 중 5문제를 Lean 4로 풀어 **은메달급 성적**을 거뒀다. 그 동작은 다음과 같다.

1. 자연어 문제를 Lean 4 진술로 **자동 형식화**(autoformalization)한다.
2. Mathlib의 수만 개 정리를 **벡터 DB**에 저장한다.
3. 현재 목표에 맞는 정리를 **의미 검색**(semantic search, 즉 RAG)으로 찾는다.
4. LLM이 후보 전술 시퀀스를 생성한다.
5. **Lean 4 컴파일러**가 후보들을 검증한다(거짓말 불가).
6. 통과하는 후보를 채택한다.

이 사이클이 — **여러분이 따름정리 1을 풀 때 머릿속에서 한 일**의 자동화이다. '아, 정리 1-(ii)를 두 번 쓰고 (i)을 한 번 쓰면 되겠다'는 학생의 직관이, AlphaProof에서는 ' $dvd\_add$와 $Dvd.Dvd.mul\_left$를 검색해 조립하라'는 검색 결과로 나타난다.

차이는 단 하나 — **여러분은 커피로 작동하고, AlphaProof는 전기로 작동한다**. 같은 일을 한다.

## 7. 한 절 요약

이 절에서 한 일을 6개 항목으로 압축한다.

1. **가분성은 '존재 명제'이다**. $a \mid b \iff \exists c,\ b = ac$. 정의를 풀고(`obtain`) 닫는(`refine`) 것이 모든 가분성 증명의 기본 동작이다.
2. **정리 1의 (i)·(ii)·(iii)**은 가분성의 세 레고 블록이다. 이후 모든 정리는 이것을 조합한다. 따름정리 1이 그 첫 '조립' 사례이다.
3. **나눗셈 알고리즘**은 ' $a = dq + r$, $0 \le r < d$ '를 만족하는 $q, r$이 유일하게 존재한다고 말한다. ' $0 \le r$ ' 조건의 차이로 언어별 mod 연산자에 차이가 발생한다 — 보안 코드의 흔한 함정.
4. **합동 vs mod** — 앞은 관계, 뒤는 값. 둘은 종이 다르다. **정리 3·4**가 둘을 잇는 다리이며, 정리 4의 ' $a = b + km$ ' 한 줄이 모든 합동 증명의 출발점이다.
5. **정리 5**는 합동이 $+$, $\cdot$에서 보존됨을 말한다. 이 덕분에 '모듈로 $m$ 대수'가 가능해진다. 단, 양변을 같은 수로 나누는 것은 일반적으로 안 된다($\gcd(c, m) = 1$일 때만 가능).
6. **$\mathbb{Z}_m$**은 교환 고리(commutative ring)를 이룬다. $(\mathbb{Z}_m, +_m)$은 모든 $m$에 대해 교환군이다. 곱셈 역원은 $\gcd(a, m) = 1$일 때만 존재하며, $m$이 소수이면 모든 0이 아닌 원소에 역원이 존재해 **$\mathbb{Z}_p$가 체**가 된다. 이것이 현대 암호학의 무대이다.

다음 절(§4.2)에서는 **'빠른 나머지 지수승'**을 만든다. RSA의 3분의 1이다.

## 8. 자기 점검

이 절을 제대로 이해했는지 다음 다섯 질문에 한 줄로 답해 보라. 각 답은 토글 안에 숨겨 두었다.

**1. ' $3 \mid 12 = 4$ ' 같은 표현은 왜 잘못되었는가?**

<details>
<summary>정답</summary>

좌변은 명제(참/거짓)이고 우변은 값(정수)이다. 종이 다른 두 대상이 같다고 할 수 없다.
</details>

**2. Lean 4에서 ' $a \mid b$ '라는 가설을 받았을 때, 이 정보를 사용 가능한 형태로 꺼내는 전술 한 단어는?**

<details>
<summary>정답</summary>

`obtain ⟨c, hc⟩ := h`. 즉 `obtain`. 가설에 숨어 있는 '존재' 증인을 꺼낸다.
</details>

**3. ' $-11 = 3 \cdot (-3) - 2$ '은 왜 ' $-11$을 3으로 나눈 결과'로 인정되지 않는가?**

<details>
<summary>정답</summary>

나눗셈 알고리즘이 요구하는 ' $0 \le r < d$ ' 조건을 위반한다. 나머지 $r = -2$가 음수이다. 정답은 ' $-11 = 3 \cdot (-4) + 1$ ' (몫 $-4$, 나머지 1).
</details>

**4. ' $a \equiv b \pmod m$ '이 명제인가 값인가? 그리고 ' $a \;\mathrm{mod}\; m$ '은?**

<details>
<summary>정답</summary>

전자는 명제(관계). 두 수에 대해 참/거짓을 묻는다. 후자는 값(함수). 한 수를 받아 한 수를 돌려준다. 정리 3·4가 두 표현을 연결한다.
</details>

**5. $\mathbb{Z}_m$에서 $a$의 곱셈 역원이 존재할 조건을 한 줄로 쓰라.**

<details>
<summary>정답</summary>

$\gcd(a, m) = 1$. 즉 $a$와 $m$이 서로소일 때만. 특히 $m$이 소수이면 모든 0이 아닌 원소에 역원이 존재해 $\mathbb{Z}_m$이 체가 된다.
</details>
