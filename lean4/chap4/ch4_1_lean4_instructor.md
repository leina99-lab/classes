## §1. 들어가며

§4.1 강의에서는 **가분성**(divisibility)이라는 정수론의 가장 기초적인 관계를 다룹니다. "a가 b를 나눈다"는 표현, 또는 "b가 a의 배수다", "b는 a로 나누어떨어진다" — 모두 같은 말이고, 기호로는 `a ∣ b`라고 적습니다.

[WATCH] 여기서 학생들이 자주 헷갈리는 게 있어요. `a ∣ b`는 **특수 기호 ∣**입니다. 키보드의 단순 막대기 `|`(파이프, Shift + \)와 모양은 비슷한데 다른 글자예요. Lean 4 편집기에서 입력할 때는 `\|` 또는 `\dvd`를 치고 Enter를 누르면 자동으로 변환됩니다. 이 차이로 첫 강의에서 30분씩 막히는 학생들이 종종 있어요. 미리 짚어 두세요.

본 강의를 마치고 나면 여러분은 다음 다섯 가지를 할 수 있게 됩니다.

1. Lean 4에서 가분성 `a ∣ b`가 어떻게 정의되어 있는지 압니다.
2. 가분성의 자명한 사실(`a ∣ 0`, `a ∣ a`, `1 ∣ a`)을 직접 증명할 수 있습니다.
3. 가분성의 결합 성질(합, 차, 곱, 선형 결합, 추이성)을 Mathlib의 보조 정리로 닫을 수 있습니다.
4. 나눗셈 알고리즘의 두 정리(`Nat.div_add_mod`, `Nat.mod_lt`)를 활용할 수 있습니다.
5. Mathlib의 `Int.ModEq`로 합동 관계를 다루는 도입을 압니다(본격은 §4.4 자료).

## §2. 가분성의 정의

§4.1 강의에서 본 정의를 다시 적습니다.

**정의** 정수 `a`, `b`에 대해, `b = a * k`인 정수 `k`가 존재하면 "`a`가 `b`를 나눈다"고 하고 `a ∣ b`로 씁니다.

Lean 4에서는 이 정의가 Mathlib에 다음과 같은 형태로 이미 들어 있어요.

```
a ∣ b ↔ ∃ k, b = a * k
```

즉 "어떤 `k`가 있어서 `b = a * k`이다"가 `a ∣ b`의 정의 그 자체입니다. 본 자료에서 `a ∣ b`를 보일 때, 여러분이 할 일은 **그런 `k`를 직접 제시하는 것**이에요. 이를 "**증인**(witness)을 제시한다"고 부릅니다.

[ANALOGY] 증인 제시라는 표현이 처음에는 좀 어색하실 텐데, 법정 비유를 떠올리시면 이해가 쉬워요. "12는 3의 배수다"라고 주장하려면, 법정에서 "그 증인이 누구냐"고 묻는 거예요. 답은 "4"입니다. "3 곱하기 4가 12이니까, 4가 그 증거다." 이렇게 구체적으로 가리키는 게 증인 제시입니다.

[Q] 그러면 이건 어떨까요? "7은 21을 나눈다"의 증인은 무엇일까요? (3초 대기) 그래요, `k = 3`입니다. 7 × 3 = 21이니까.

[Q] 또 하나. "5는 12를 나누지 않는다"는 어떻게 증명할까요? (5초 대기) 이건 좀 더 까다로워요. 증인이 존재하지 않음을 보여야 하니까. 다행히 작은 수에 대해서는 Lean 4가 직접 계산으로 즉결합니다. 곧 보겠습니다.

## §3. 가장 단순한 시연 - `3 ∣ 12`

가장 단순한 사례로 시작합니다.

**주장** `3 ∣ 12`이다.

[Q] 자, `12 = 3 * k`인 `k`를 찾아 봅시다. 어떤 수일까요? (3초 대기) 답은 `k = 4`. 12 = 3 × 4이니까요.

Lean 4 코드로 옮기면 이렇게 됩니다.

```lean
import Mathlib

example : (3 : Nat) ∣ 12 := by
  -- 증인 k = 4를 제시: 12 = 3 * 4
  exact ⟨4, by decide⟩
```

[DEMO] 자, 여기서 실제로 편집기를 열어서 시범을 보입니다. 한 줄씩 입력하면서 InfoView가 어떻게 바뀌는지 함께 봅시다.

먼저 `example : (3 : Nat) ∣ 12 := by`를 입력합니다. 커서를 `by` 다음에 놓으면 오른쪽 InfoView에 무엇이 보이죠?

```
⊢ (3 : Nat) ∣ 12
```

이게 우리의 **목표**입니다. `⊢` 기호 다음에 적힌 게 우리가 증명해야 할 명제예요.

[WATCH] 학생들이 이때 `(3 : Nat)`이라는 표기에 종종 당황합니다. 이건 "3을 자연수로 해석하라"는 타입 지정이에요. Lean 4는 엄격한 타입 시스템을 가지고 있어서, 같은 숫자 3도 자연수 3인지, 정수 3인지, 실수 3인지 명시해야 할 때가 있습니다. 자연수와 정수의 차이가 §4.1에서 결정적이니까, 이 표기에 익숙해지셔야 합니다.

[STUDENT TRY] 자, 이제 여러분이 직접 해 보세요. 1분 드릴게요. 위 코드를 그대로 따라쳐서 컴파일이 통과되는지 확인하고, 그 다음 `(5 : Nat) ∣ 25`도 같은 방식으로 증명해 보세요. 증인은 `k = 5`겠죠? (1분 대기)

다 하셨어요? 잘 되셨을 거예요. 안 되신 분 손 들어 주세요. ... (오류 보면서) 아, `∣` 대신 `|`를 쓰셨군요. 다시 한 번 강조합니다 — `\|` Enter로 변환하셔야 합니다.

이제 `exact ⟨4, by decide⟩`을 봅니다. 두 가지 새 요소가 있어요.

**꺽쇠 묶음 `⟨..., ...⟩`** 이건 "**구조체**나 **존재**(`∃`) 같은 짝 정보를 한꺼번에 묶어 제공한다"는 기호입니다. 가분성 `3 ∣ 12`의 정의가 `∃ k, 12 = 3 * k`이므로, 두 정보를 함께 제공해야 합니다. 첫째, 증인 `k`(여기서는 `4`). 둘째, 그 `k`로 등식이 성립한다는 증명(여기서는 `by decide`). 이 둘을 `⟨4, by decide⟩` 한 묶음으로 전달합니다.

[ANALOGY] 비유하자면 "여기 4라는 증인이 있어요. 이 사람이 진실을 말한다는 증거(by decide)도 같이 가져왔어요." 이렇게 한꺼번에 패키지로 내미는 거죠.

**`decide` 전술** 작은 수의 직접 계산으로 참거짓을 판정합니다. `12 = 3 * 4`는 단순 계산이니까 `decide`가 즉결합니다.

[AI] 잠깐, 여기서 흥미로운 점이 있어요. 우리가 방금 본 `decide`는 사실 컴퓨터의 계산 능력으로 명제를 판정하는 거예요. 이게 바로 AI가 수학을 다루는 가장 기초적인 방식 중 하나입니다. "유한한 경우는 모두 컴퓨터로 직접 검사하자"는 발상. 이걸 SAT solver, SMT solver라고 부르는 도구들이 더 정교하게 다루는데, 모두 같은 철학에서 출발해요.

### 부정 형태도 봅시다.

```lean
example : ¬ ((3 : Nat) ∣ 10) := by
  decide
```

`¬`는 부정 기호입니다. "`3 ∣ 10`이 거짓이다"는 명제예요. 작은 수의 부정도 `decide`가 직접 계산으로 즉결합니다.

[Q] 그러면 이걸 종이에서 어떻게 증명할까요? 종이에서는 "12 = 3 × 4"처럼 증인을 제시하는 게 아니라, "10을 3으로 나누면 3 나머지 1이라서, 3의 배수가 아니다"라고 말합니다. 즉 종이의 직관과 `decide`의 동작이 같아요. 둘 다 계산으로 확인하는 거니까요.

### 코드 1·2의 InfoView 정밀 관찰

이제 코드 한 줄씩 누를 때마다 InfoView에 무엇이 보이는지 정밀하게 관찰합시다.

**코드 1**

```lean
example : (3 : Nat) ∣ 12 := by
```

```
-- AFTER `:= by`:
--   ⊢ (3 : Nat) ∣ 12
```

목표 안에 자유 변수가 없습니다. `(3 : Nat) ∣ 12`는 닫힌 명제예요.

```lean
  exact ⟨4, by decide⟩
```

`⟨4, by decide⟩`의 두 성분:
- 첫 성분 `4`: 증인 `k`.
- 둘째 성분 `by decide`: 등식 `12 = 3 * 4`의 증명. `12 = 12`로 환원되어 `decide`가 즉결.

```
-- AFTER `exact ⟨4, by decide⟩`:
--   (No goals)
```

목표가 모두 닫히면 InfoView에 "No goals"라고 나옵니다. 이게 증명 완료의 신호예요.

[JOKE] "No goals"를 처음 봤을 때 저는 인생의 목표가 없는 것 같다는 우울한 느낌을 받았었어요. 그런데 알고 보니 좋은 거였죠. 증명 끝났다는 뜻이니까.

**코드 2** (부정)

```lean
example : ¬ ((3 : Nat) ∣ 10) := by
  decide
```

`decide`가 부정 명제도 직접 계산으로 판정합니다. 가분성 명제와 그 부정은 작은 자연수에서 결정 가능하기 때문입니다.

## §4. 자명한 사실 세 가지

가분성의 가장 기초적인 사실 세 가지입니다. 모두 증인 제시 한 줄로 닫힙니다.

**자명 사실 1.** 모든 자연수 `a`에 대해 `a ∣ 0`입니다.

[Q] 왜일까요? (3초 대기) 그래요, `0 = a * 0`이니까, 증인 `k = 0`을 제시하면 끝.

```lean
theorem a_dvd_zero (a : Nat) : a ∣ 0 := by
  -- 증인 k = 0을 제시: 0 = a * 0
  exact ⟨0, by ring⟩
```

[WATCH] 여기서 학생들이 종종 의아해해요. "0이 어떻게 모든 수의 배수인가요? 0을 무엇으로 나눠도 0인 건 알겠는데, 그게 '나누어떨어진다'와 무슨 관계죠?" 이 질문이 나오면 정의로 돌아가서 설명합니다. 정의는 "`b = a * k`인 `k`가 존재하면 `a ∣ b`"입니다. `b = 0`이면 `0 = a * 0`이라는 `k = 0`이 항상 있죠. 그러니까 0은 모든 수의 배수입니다. 직관과 정의가 일치하는 좋은 사례예요.

`by ring`은 다항식 항등식 자동 검증입니다. `0 = a * 0`은 곱셈의 영원 성질로부터 즉시 따라오는 항등식이므로 `ring`이 처리합니다.

**자명 사실 2.** 모든 자연수 `a`에 대해 `a ∣ a`입니다.

이유: `a = a * 1`이므로, 증인 `k = 1`을 제시.

```lean
theorem a_dvd_self (a : Nat) : a ∣ a := by
  exact ⟨1, by ring⟩
```

**자명 사실 3.** 모든 자연수 `a`에 대해 `1 ∣ a`입니다.

이유: `a = 1 * a`이므로, 증인 `k = a`를 제시.

```lean
theorem one_dvd_a (a : Nat) : 1 ∣ a := by
  exact ⟨a, by ring⟩
```

[Q] 세 정리를 한꺼번에 비교해 봅시다. 증인의 차이가 보이세요? `a ∣ 0`은 증인이 `0`, `a ∣ a`는 `1`, `1 ∣ a`는 `a`. 각 정리의 진술을 보면서 "어떤 등식을 만들어야 하는지" 손으로 그려 보면 증인이 자연스럽게 떠오릅니다. 이게 가분성 직접 증명의 핵심 기술이에요.

[STUDENT TRY] 자, 도전 과제. `2 ∣ 6`을 증인 제시 형태로 증명해 보세요. 증인은 무엇일까요? (30초 대기) ... 그래요, `k = 3`. 잘 하셨어요.

[AI] 여기서 잠깐 멈춰 흥미로운 점을 짚고 갑니다. 최근 GPT-5나 Claude 같은 대형 언어 모델이 수학 문제를 풀 때, 내부적으로 이런 "증인 제시" 발상을 자주 활용해요. 존재 명제를 만나면 자동으로 "어떤 구체적 값을 줄까"를 탐색하죠. AI의 수학적 추론 능력이 점점 좋아지는 핵심 중 하나가 바로 이런 형식 증명의 패턴을 학습하는 것이에요. 우리가 오늘 배우는 게 그래서 AI 시대에 더 중요해지고 있는 겁니다.

### 일반 패턴 정리

가분성 `a ∣ b`를 직접 보이는 형태:

```lean
example (...) : a ∣ b := by
  exact ⟨<증인 k>, by <등식 검증>⟩
```

`<증인 k>`는 `b = a * k`를 성립시키는 정수입니다. `<등식 검증>`은 그 등식의 증명입니다. 등식이 다항식 항등식이면 `ring`, 단순 계산이면 `decide` 또는 `rfl`이 사용됩니다.

[Q] 이 세 도구(`ring`, `decide`, `rfl`)의 차이가 뭘까요? 한 번 정리해 보면 — `rfl`은 "양변이 정의상 똑같다", `decide`는 "작은 수의 직접 계산으로 판정", `ring`은 "다항식 항등식 자동 검증"입니다. 약한 것부터 강한 것 순서로 `rfl < decide < ring`이라고 생각하시면 됩니다.

---

자유 변수 `a`가 가정에 들어와 있어요. 목표는 그 임의의 `a`에 대한 가분성. `exact ⟨0, by ring⟩`이 즉결.

## §5. 결합 성질 (1) - 합과 차

[교수자 멘트] 10분 휴식 후 돌아옵시다. ... (휴식)

자, 다시 시작합니다. 지금까지 우리는 가분성의 "자명한 사실들"을 다뤘어요. 이제부터는 진짜 정리들이 나옵니다. 가분성이 합과 차, 곱에서 어떻게 행동하는지 — 이게 바로 정수론의 출발선이에요.

가분성은 합과 차에 대해 **보존됩니다**. 즉 같은 `a`로 나누어떨어지는 두 수의 합·차도 같은 `a`로 나누어떨어집니다.

**정리(합)** `a ∣ b`이고 `a ∣ c`이면 `a ∣ (b + c)`입니다.

[Q] 종이로 어떻게 증명할까요? (5초 대기) 그래요. `b = a * k₁`, `c = a * k₂`이라 하면, `b + c = a * (k₁ + k₂)`. 따라서 증인 `k₁ + k₂`로 `a ∣ (b + c)`. 정확합니다.

Mathlib에는 이 정리가 `Nat.dvd_add`라는 이름으로 들어 있어요. 진술은 다음과 같습니다.

```
Nat.dvd_add : a ∣ b → a ∣ c → a ∣ (b + c)
```

[ANALOGY] 함수처럼 인수를 받습니다. 입력: 두 개의 가분성 증명. 출력: 합의 가분성 증명. 마치 사물을 받아 가공해 돌려주는 자판기 같다고 생각하시면 됩니다.

```lean
theorem dvd_add_demo (a b c : Nat)
    (h1 : a ∣ b) (h2 : a ∣ c) :
    a ∣ (b + c) :=
  Nat.dvd_add h1 h2
```

[DEMO] 자, 시범 보입니다. 증명 본체가 한 줄이에요. `Nat.dvd_add h1 h2`. 가정으로 받은 두 가분성 증명 `h1`, `h2`를 그대로 `Nat.dvd_add`에 넘기면, 합의 가분성이 돌아옵니다.

여기서 한 가지를 짚어 둡니다. 이 정리는 `:= by`가 아닌 `:=`만으로 본체가 시작해요. 즉 **전술 모드**(tactic mode, `by` 다음)에 들어가지 않고 **표현 모드**(term mode)에서 바로 답을 적었습니다.

[WATCH] 이게 학생들에게 처음에는 좀 혼란스러워요. `:= by ...` 형태에 익숙해진 후에 `:= 답` 형태를 보면 어색하죠. 한 줄짜리 답은 후자가 더 깔끔하다는 점만 기억하세요. 손에 익으면 자연스럽게 두 형태를 오가게 됩니다.

[Q] 그러면 묻겠습니다. `a ∣ b`이고 `a ∣ c`이고 `a ∣ d`이면 `a ∣ (b + c + d)`겠죠? Mathlib 정리만으로 어떻게 증명할까요? (10초 대기) 답: `Nat.dvd_add` 두 번 호출. 한 번은 `b + c`에 적용, 그 결과를 다시 `d`와 함께 또 적용. `Nat.dvd_add (Nat.dvd_add h1 h2) h3` 같은 형태죠.

**정리(차)** `a ∣ b`이고 `a ∣ c`이면 `a ∣ (b - c)`입니다.

[WATCH] 자연수에서는 뺄셈이 위험합니다. 작은 수에서 큰 수를 빼면 0으로 잘립니다. 예를 들어 `Nat` 환경에서 `3 - 5 = 0`이에요. 종이의 직관과 다르죠. 그러므로 차의 가분성은 **정수** `Int`에서 일반적으로 다룹니다.

```lean
theorem dvd_sub_int_demo (a b c : Int)
    (h1 : a ∣ b) (h2 : a ∣ c) :
    a ∣ (b - c) :=
  dvd_sub h1 h2
```

정수 환경에서는 `Nat.dvd_add`가 아니라 일반 환에서 작동하는 `dvd_sub`을 씁니다.

[Q] 둘의 차이가 뭘까요? `Nat.dvd_add`에는 `Nat.` 접두어가 있고 `dvd_sub`에는 없죠. 이유는 `Nat.dvd_add`는 자연수에 특화된 정리이고, `dvd_sub`은 **임의의 환**(ring)에서 작동하는 일반 정리이기 때문이에요. 자연수는 환이 아닙니다(뺄셈이 잘려서요). 그러니까 자연수에서는 `dvd_sub`을 적용하면 보장이 약해지거나 오류가 납니다. 정수, 유리수, 실수, 행렬 같은 환에서만 안전해요.

[ANALOGY] Mathlib의 정리들을 도구 상자에 비유하자면, `Nat.`이 붙은 도구들은 "자연수 전용 박스" 안에 있고, 접두어 없는 도구들은 "범용 박스" 안에 있어요. 같은 일을 하지만 적용 환경이 다르죠.

---

### 종이와 코드의 대응

| 종이 증명 | Lean 4 한 줄 |
|---|---|
| "b = a·k₁, c = a·k₂이라 하면" | (가정 `h1`, `h2`로 자동 표현됨) |
| "b + c = a·(k₁ + k₂)" | (`Nat.dvd_add`가 내부적으로 처리) |
| "따라서 a ∣ (b + c)" | `Nat.dvd_add h1 h2` |

종이의 세 줄이 코드의 한 줄로 압축됩니다. 보조 정리에 일을 맡기는 것의 효율이에요.

[AI] 여기서 잠깐. 최근의 AI 수학 시스템들이 큰 도약을 한 비결 중 하나가 바로 이런 "이미 증명된 보조 정리를 잘 골라 쓰는 능력"입니다. Mathlib에는 약 20만 개의 정리가 있는데, 정확한 정리 하나를 찾아 한 줄로 닫는 게 사실은 가장 어려운 부분이에요. 사람도 어렵고 AI도 어렵습니다. 그래서 사실 우리가 오늘 배우는 게 단순한 "코드 따라치기"가 아니라, 라이브러리에서 필요한 정리를 찾는 감각을 기르는 것이에요.

`[inst : Ring α]`는 "α가 환이라는 인스턴스가 있어야 한다"는 요구. `Int`는 환이므로 만족.

## §6. 결합 성질 (2) - 곱과 추이성

**정리(곱)** `a ∣ b`이면 임의의 `c`에 대해 `a ∣ (b * c)`입니다.

[Q] 종이 증명? (5초) 그래요. `b = a * k`이면 `b * c = (a * k) * c = a * (k * c)`. 증인 `k * c`로 성립.

Mathlib에는 `Dvd.dvd.mul_right`라는 이름으로 있어요.

```lean
theorem dvd_mul_demo (a b c : Nat) (h : a ∣ b) :
    a ∣ (b * c) :=
  Dvd.dvd.mul_right h c
```

[WATCH] 정리 이름이 좀 복잡하죠? `Dvd.dvd.mul_right`. 첫 `Dvd`는 가분성 typeclass의 이름이고, 둘째 `dvd`는 그 안의 관계 이름, 마지막 `mul_right`가 정리 이름입니다. Mathlib은 이름을 점(`.`)으로 계층화해서 정리해요. 처음에는 외우기 힘들지만 패턴에 익숙해지면 자동으로 떠올라요.

`Dvd.dvd.mul_right h c`의 의미는 "`h`라는 가분성에 우측에서 `c`를 곱한 형태의 가분성을 만든다"입니다. 짝꿍 정리 `Dvd.dvd.mul_left`도 있어요. 좌측 곱셈에 씁니다.

```
Dvd.dvd.mul_right : a ∣ b → (c : α) → a ∣ (b * c)
Dvd.dvd.mul_left  : a ∣ b → (c : α) → a ∣ (c * b)
```

[Q] 두 정리의 차이가 어디일까요? (3초) `mul_right`는 `b * c`, `mul_left`는 `c * b`. 곱의 어느 쪽에 새 수가 들어가느냐가 다릅니다. 가환환에서는 `b * c = c * b`이지만 Lean 4는 표현의 차이까지 구분하니까, 정확한 도구를 골라야 해요.

[ANALOGY] 좌우 손잡이 가위 같은 거예요. 어느 손잡이를 쓰느냐가 다른 정리.

**정리(추이성)** `a ∣ b`이고 `b ∣ c`이면 `a ∣ c`입니다.

[Q] 종이 증명? (5초) `b = a * k₁`, `c = b * k₂`이면 `c = (a * k₁) * k₂ = a * (k₁ * k₂)`. 증인 `k₁ * k₂`.

Mathlib에는 `Dvd.dvd.trans`라는 이름으로 있어요.

```lean
theorem dvd_trans_demo (a b c : Nat)
    (h1 : a ∣ b) (h2 : b ∣ c) :
    a ∣ c :=
  Dvd.dvd.trans h1 h2
```

[AI] 가분성 관계가 **추이적**이라는 사실은 후에 §4.3의 최대공약수 이론에서 핵심 역할을 합니다. 사실 추이성이라는 성질은 컴퓨터 과학과 AI 전반에서 중요해요. 그래프, 데이터베이스, 추론 시스템 모두에서 등장하죠. "A → B이고 B → C이면 A → C"라는 단순한 성질이 굉장히 많은 일을 가능하게 합니다.

---

**코드 8** (곱의 가분성)

```lean

```

`h c`로 두 인수를 넘깁니다. `h`는 `a ∣ b`라는 가분성 증명, `c`는 곱해질 수.

**코드 9** (추이성)

```lean

```

가분성 관계의 추이성. 가분성이 자연수 위에서 **부분 순서 관계**를 이루는 핵심 사실 중 하나.

## §7. 결합 성질 (3) - 선형 결합

§4.1 강의의 가분성 핵심 정리입니다. 위에서 본 정리들을 결합해서 만듭니다.

**정리(선형 결합)** `a ∣ b`이고 `a ∣ c`이면 임의의 `m`, `n`에 대해 `a ∣ (m·b + n·c)`입니다.

[Q] 종이 증명? (10초) 단계별로 봅시다.
1. `a ∣ b`이므로 `a ∣ m·b` (곱)
2. `a ∣ c`이므로 `a ∣ n·c` (곱)
3. 두 가분성의 합으로 `a ∣ (m·b + n·c)` (합)

세 단계의 연속 적용이에요. Mathlib에 직접 단일 정리로 있는지 모르겠지만, 위 세 가지 정리(`Dvd.dvd.mul_left`, `Nat.dvd_add`)를 차례로 적용하면 충분히 만들 수 있어요.

```lean
theorem dvd_linear_combination (a b c m n : Nat)
    (h1 : a ∣ b) (h2 : a ∣ c) :
    a ∣ (m * b + n * c) := by
  -- m * b에 a가 나누어짐 (b의 좌측 곱)
  have hb : a ∣ (m * b) := Dvd.dvd.mul_left h1 m
  -- n * c에 a가 나누어짐
  have hc : a ∣ (n * c) := Dvd.dvd.mul_left h2 n
  -- 두 가분성의 합
  exact Nat.dvd_add hb hc
```

[DEMO] 여기서 시범 보입니다. 본 정리는 세 줄에 걸친 **연속 적용**이에요. `have`로 보조 사실을 두 개 비축하고, `exact`로 결론을 내립니다.

`have <이름> : <명제> := <증명>`은 본 자료에서 매우 중요한 구문입니다. "이런 명제를 이런 이름으로 손에 쥔다"는 의미예요. 후속 줄에서 그 이름을 호명해 씁니다.

[ANALOGY] `have`는 마치 부엌에서 재료를 미리 손질해 놓는 거와 같아요. "양파를 다지고", "고기를 양념하고", 그 다음 "두 재료를 합쳐서 볶는다." 각 단계가 다음 단계의 재료가 되죠.

[Q] 한 가지 묻겠습니다. `Dvd.dvd.mul_left h1 m`을 보세요. 여기서 `m`이 왼쪽 자리예요. 그러면 결과는 `a ∣ (m * b)`. 정리 이름이 `mul_left`인 이유가 새 수 `m`이 왼쪽에 붙기 때문이에요. 명료한 명명입니다.

---

### 종이와 코드의 대응

| 종이 | Lean 4 한 줄 |
|---|---|
| "a ∣ b이므로 a ∣ m·b" | `have hb : a ∣ (m * b) := Dvd.dvd.mul_left h1 m` |
| "a ∣ c이므로 a ∣ n·c" | `have hc : a ∣ (n * c) := Dvd.dvd.mul_left h2 n` |
| "두 가분성의 합" | `exact Nat.dvd_add hb hc` |

종이의 세 줄이 코드의 세 줄과 한 줄씩 짝을 이뤄요. 본 자료에서 처음 보는 "정확히 한 줄씩 대응"의 사례입니다.

## §8. 나눗셈 알고리즘

[교수자 멘트] 10분 휴식 후 다시 시작합니다. ... (휴식)

§4.1 강의의 또 하나의 기둥 정리예요.

**정리(나눗셈 알고리즘)** 양의 정수 `b > 0`과 임의의 자연수 `a`에 대해, 유일한 `q`(몫)와 `r`(나머지)이 존재해서

```
a = b · q + r,   0 ≤ r < b.
```

[Q] 이 정리, 초등학교 때부터 익숙하시죠? "17 나누기 5는 몫 3 나머지 2." 17 = 5·3 + 2이고 2가 5보다 작죠. 이게 나눗셈 알고리즘입니다.

[ANALOGY] 사실 "알고리즘"이라는 이름이 좀 거창해요. 그냥 "나누면 몫과 나머지가 나온다"는 사실이거든요. 그런데 이 단순한 사실이 정수론 전체의 토대입니다. 합동 관계, 유클리드 호제법, 모듈러 산술 모두 이 한 정리에서 출발해요.

Lean 4와 Mathlib에서는 이 정리가 **두 개의 분리된 정리**로 들어 있어요.

**정리 1.** `Nat.div_add_mod`. 진술:

```
Nat.div_add_mod : ∀ (m k : Nat), k * (m / k) + m % k = m
```

말로 풀면 "어떤 자연수 `m`을 `k`로 나누면, `k * (몫) + (나머지) = m`이 성립한다". 종이의 `a = b · q + r`을 옮긴 것이에요.

```lean
theorem div_mod_decomposition (a b : Nat) :
    b * (a / b) + a % b = a :=
  Nat.div_add_mod a b
```

본 정리는 인수만 넘기면 끝.

[WATCH] 학생들이 종종 이 정리에 가정이 없다는 점에 놀라요. "b = 0일 때는 어떻게 되나요?" 답: Lean 4의 정의에서 `m / 0`과 `m % 0`이 잘 짜여 있어서, 합이 항상 `m`이 되도록 처리됩니다. 그러니까 가정 없이도 항상 성립해요. 일종의 정의의 우아함이죠.

**정리 2.** `Nat.mod_lt`. 진술:

```
Nat.mod_lt : ∀ (x : Nat) {y : Nat}, 0 < y → x % y < y
```

말로 풀면 "나누는 수 `y`가 양수이면, 나머지 `x % y`는 `y`보다 작다". 종이의 `r < b`를 옮긴 것이에요.

```lean
theorem mod_lt_divisor (a b : Nat) (hb : 0 < b) :
    a % b < b :=
  Nat.mod_lt a hb
```

`hb : 0 < b`라는 가정이 핵심입니다. `b = 0`이면 정리가 성립하지 않아요(0으로 나눌 수 없음).

[Q] 흥미로운 점: `{y : Nat}`이 중괄호로 묶여 있어요. 이게 뭘까요? (3초) **암묵 인수**(implicit argument)예요. 호출 시 명시적으로 넘기지 않고 Lean 4가 문맥에서 추론합니다. `Nat.mod_lt a hb`로 `a`(피제수)와 `hb`(양수성 가정)만 넘기면, `y`는 `hb`의 타입 `0 < y`에서 Lean 4가 자동으로 추론하는 거죠.

[AI] 암묵 인수는 Lean 4가 똑똑하게 작동하는 비결 중 하나입니다. 사람이 다 적기 귀찮은 부분을 컴파일러가 채워 줘요. 이게 잘 작동하기 때문에 코드가 짧고 읽기 쉬워요. AI 시스템이 코드를 자동 생성할 때도 이런 자동 추론이 핵심 기능입니다.

**시연** 17을 5로 나누는 경우. 몫 3, 나머지 2.

```lean
example : 17 = 5 * (17 / 5) + 17 % 5 := by
  decide

example : 17 / 5 = 3 := by decide
example : 17 % 5 = 2 := by decide
```

세 정리 모두 `decide`로 즉결합니다. 작은 수이므로 직접 계산이 가장 단순해요.

[STUDENT TRY] 자, `25 = 7 * (25 / 7) + 25 % 7`을 증명해 보세요. 그리고 `25 / 7`과 `25 % 7`의 값도 따로 검증해 보세요. (2분 대기)

## §9. 가분성과 나머지

가분성과 나머지의 관계를 짚습니다.

**핵심 정리** 자연수 `a`, `b`에 대해 다음 세 가지가 Mathlib에 들어 있어요.

```
Nat.mod_eq_zero_of_dvd  : m ∣ n → n % m = 0
Nat.dvd_of_mod_eq_zero  : n % m = 0 → m ∣ n
Nat.dvd_iff_mod_eq_zero : m ∣ n ↔ n % m = 0
```

[Q] 세 정리 모두 **`m`의 양수성을 요구하지 않습니다**. 왜 그럴까요? (5초)

답: Lean 4의 자연수 나머지 정의에서 `n % 0 = n`이고, `0 ∣ n`은 `n = 0`과 동치이므로 두 사실이 자연스럽게 맞물려요. 즉 `m = 0`일 때조차 양방향 동치가 성립합니다.

[WATCH] 이 점이 특히 중요해요. 저도 한동안 `0 < a` 가정이 필요할 거라고 잘못 생각했었어요. Mathlib을 깊이 들여다보면 가정 없이 작동하도록 정의가 잘 짜여 있다는 걸 발견했죠. 항상 `#check`로 정리의 정확한 시그니처를 확인하는 습관이 중요합니다.

**양방향 동치 (가장 짧은 형태)**

```lean
theorem dvd_iff_mod_eq_zero (a b : Nat) :
    a ∣ b ↔ b % a = 0 :=
  Nat.dvd_iff_mod_eq_zero
```

본 자료에서 가장 짧은 정리예요. Mathlib에 정확히 같은 진술이 있으므로 호명만 합니다.

[ANALOGY] "이 정리, 옆방에 가서 가져다 줘요"라고 부탁하는 것과 같아요. 그 정리가 정확히 거기 있으니까.

**양방향 동치 (constructor로 미시 전개)**

```lean
example (a b : Nat) : a ∣ b ↔ b % a = 0 := by
  constructor
  · intro h
    exact Nat.mod_eq_zero_of_dvd h
  · intro h
    exact Nat.dvd_of_mod_eq_zero h
```

같은 정리를 두 단방향으로 분해해 보인 형태. 새 요소가 둘 있어요.

**`constructor`** `↔`(쌍방향 함의)나 `∧`(합접) 같은 두 성분 명제를 두 부목표로 분해합니다. 본 코드에서는 `↔`를 `→`(정방향)와 `←`(역방향) 두 함의로 분해해요.

**`intro h`** 함의 `P → Q`의 가정 `P`를 잡아 새 가정 `h`로 만들고, 목표를 `Q`로 좁힙니다.

[Q] `constructor` 후에 InfoView에 무엇이 보일까요? (3초) 두 부목표가 위 아래로 펼쳐집니다. 첫 번째는 `a ∣ b → b % a = 0`, 두 번째는 `b % a = 0 → a ∣ b`. 각각을 `·`(점) 줄에서 처리합니다.

**단방향 (가분성 → 나머지 0)**

```lean
theorem dvd_to_mod_zero (a b : Nat) (h : a ∣ b) :
    b % a = 0 :=
  Nat.mod_eq_zero_of_dvd h
```

**단방향 (나머지 0 → 가분성)**

```lean
example (a b : Nat) (h : b % a = 0) : a ∣ b :=
  Nat.dvd_of_mod_eq_zero h
```

**rw 중심 대안 (forward 방향)**

```lean
example (a b : Nat) (h : a ∣ b) : b % a = 0 := by
  rw [← Nat.dvd_iff_mod_eq_zero]
  exact h
```

[DEMO] `← Nat.dvd_iff_mod_eq_zero`의 `←`이 핵심입니다. 동치 정리를 **역방향**으로 적용해서 목표 `b % a = 0`을 `a ∣ b`로 다시 쓰는 거예요. 그러면 가정 `h`와 정확히 일치하니까 `exact h`로 닫힙니다.

[ANALOGY] 양방향 동치 정리는 양방향 도로 같아요. `→` 방향과 `←` 방향이 모두 가능. `rw [...]`은 정방향(좌→우), `rw [← ...]`은 역방향(우→좌). 같은 도로를 어느 방향으로 갈지를 선택하는 거죠.

종이 증명의 "`a ∣ b ↔ a로 나눈 나머지가 0`"이라는 직관이, Lean 4에서는 정확히 `Nat.dvd_iff_mod_eq_zero`라는 한 정리로 표현됩니다.

## §10. 모듈러 합동의 도입

§4.4 강의에서 본격적으로 다룰 **합동** 관계를, §4.1에서는 도입만 합니다.

**정의** 정수 `a`, `b`, `m`(`m > 0`)에 대해 `m ∣ (a - b)`이면 "`a`와 `b`는 `m`을 법으로 합동"이라 하고 `a ≡ b (mod m)`으로 씁니다.

[ANALOGY] 합동을 직관적으로 이해하시려면 시계를 떠올리세요. 12시간 시계에서 13시는 사실 1시와 "같은 자리"에 있어요. 그래서 `13 ≡ 1 (mod 12)`라고 씁니다. 시계의 한 바퀴(12시간)는 우리 눈에 보이지 않게 흘러간 것뿐, 같은 시각이라는 의미.

[Q] 그러면 15시는 시계에서 몇 시일까요? (3초) 3시. 즉 `15 ≡ 3 (mod 12)`.

Lean 4와 Mathlib에서는 이 정의가 `Int.ModEq m a b`라는 형태로 들어 있어요.

```lean
example : Int.ModEq 5 17 2 := by
  -- 17 ≡ 2 (mod 5). 즉 5 ∣ (17 - 2) = 15.
  decide

example : ¬ Int.ModEq 5 17 3 := by
  decide
```

작은 수의 합동 여부는 `decide`가 직접 계산으로 판정합니다.

**합동의 세 성질** 본 자료에서는 진술만 봅니다. 본격적인 증명은 §4.4 자료에서 봐요.

```lean
-- 반사성
example (m a : Int) : Int.ModEq m a a :=
  Int.ModEq.refl a

-- 대칭성
example (m a b : Int) (h : Int.ModEq m a b) : Int.ModEq m b a :=
  Int.ModEq.symm h

-- 추이성
example (m a b c : Int)
    (h1 : Int.ModEq m a b) (h2 : Int.ModEq m b c) :
    Int.ModEq m a c :=
  Int.ModEq.trans h1 h2
```

세 정리 모두 Mathlib에 직접 들어 있어 이름만 호명하면 됩니다.

[AI] 합동 관계가 정수론에서 핵심이듯, AI에서도 비슷한 "동치 관계"가 핵심입니다. 자연어 처리에서 "같은 의미의 다른 표현"을 처리하는 게 본질적으로 동치 관계의 처리예요. 예를 들어 "이 영화 좋다"와 "이 영화 마음에 든다"가 의미적으로 같다고 분류하는 것. 이런 동치 관계의 세 성질(반사·대칭·추이)이 자연어 분류 시스템의 일관성을 보장하는 토대입니다.

§4.4 자료에서는 본 자료의 `Int.ModEq` 대신 우리만의 정의 `CongMod`을 직접 만들고, 위 세 성질을 직접 증명합니다. 그 시점에 본 자료의 도입이 다리가 돼요.

## §11. 마무리 - 본 자료의 패턴 정리

본 강의에서 익힌 핵심 패턴 다섯 가지를 정리합시다.

[Q] 자, 한번 같이 떠올려 봅시다. 가분성을 직접 증명할 때 우리가 쓴 패턴이 뭐였죠? (5초) 그래요, 증인 제시. `exact ⟨k, by ring⟩` 같은 형태.

**패턴 1. 가분성 직접 증명 (증인 제시)**

```lean
example : a ∣ b := by
  exact ⟨<증인 k>, by <등식 검증>⟩
```

`<등식 검증>`은 `b = a * k`의 증명. 다항식 항등식이면 `ring`, 단순 계산이면 `decide` 또는 `rfl`.

**패턴 2. 결합 정리 직접 호출**

```lean
-- 합
Nat.dvd_add h1 h2

-- 차 (정수 환경)
dvd_sub h1 h2

-- 곱
Dvd.dvd.mul_left  h c  -- a ∣ b → a ∣ (c * b)
Dvd.dvd.mul_right h c  -- a ∣ b → a ∣ (b * c)

-- 추이성
Dvd.dvd.trans h1 h2
```

**패턴 3. 연속 적용 (have로 비축)**

```lean
example ... : a ∣ ... := by
  have h_step1 : ... := <첫 호출>
  have h_step2 : ... := <둘째 호출>
  exact <마지막 결합>
```

**패턴 4. 나눗셈 알고리즘 활용**

```lean
-- a = b·q + r의 표현
Nat.div_add_mod a b   -- 자동으로 b * (a / b) + a % b = a

-- r < b의 표현 (b > 0 가정)
Nat.mod_lt a hb       -- hb : 0 < b
```

**패턴 5. 가분성 ↔ 나머지 0 동치**

```lean
-- 양방향
Nat.dvd_iff_mod_eq_zero

-- 단방향
Nat.mod_eq_zero_of_dvd  -- forward
Nat.dvd_of_mod_eq_zero  -- backward
```

이 다섯 패턴이 본 자료가 다룬 §4.1의 모든 정리를 덮어요. 각 패턴은 "수학적 사실 한 단계가 코드의 한 줄에 대응"하도록 설계되었습니다.

[STUDENT TRY] 마지막 종합 활동. 다음을 증명해 보세요. "`6 ∣ b`이고 `6 ∣ c`이면 `6 ∣ (2b + 3c)`이고, 그러면 `(2b + 3c) % 6 = 0`이다." 두 단계가 결합된 정리예요. 시간은 5분 드립니다. (5분 대기)

[AI] 본 자료를 처음부터 끝까지 손으로 한 번 따라쳐 보면, Lean 4의 기초 문법, 가분성 정의, Mathlib의 주요 가분성 정리들에 자연스럽게 익숙해질 거예요. 그리고 무엇보다 중요한 건 — AI 시대에 우리가 어떻게 수학과 컴퓨터 과학을 결합해 일할 수 있는지에 대한 감각을 얻으셨을 거라는 점입니다. Lean 4는 그 결합의 가장 직접적인 도구 중 하나예요.

다음 단계는 §4.2의 **정수의 표현**입니다. 이번에는 가분성보다는 자릿수와 진법 변환을 다뤄요.

## 부록 A. 자주 나오는 학생 질문과 답변

**Q1. `a ∣ b`의 `∣`을 어떻게 입력하나요?**  
A: `\|`를 치고 Enter. 또는 `\dvd`를 치고 Enter. 단순 `|`(파이프)는 안 됩니다.

**Q2. `decide`와 `ring`의 차이가 뭐예요?**  
A: `decide`는 작은 수의 직접 계산. `ring`은 다항식 항등식 자동 검증. `0 = a * 0` 같은 항등식에는 `ring`을, `12 = 3 * 4` 같은 구체 계산에는 `decide`를 씁니다.

**Q3. Mathlib 정리 이름은 어떻게 외워야 하나요?**  
A: 외우는 게 아니라 검색하는 거예요. VSCode 환경이면 `#check <이름>`으로 시그니처 확인, 또는 Mathlib4 문서 사이트(`leanprover-community.github.io/mathlib4_docs`)에서 찾아보세요. 패턴을 알면 자연스럽게 익숙해집니다.

**Q4. `Nat`과 `Int`를 언제 구분해서 써야 하나요?**  
A: 자연수에서는 뺄셈이 잘립니다(`3 - 5 = 0` in `Nat`). 차나 음수가 등장하는 모든 정리는 `Int`에서. 가분성의 합, 곱, 추이성은 `Nat`에서도 OK. 차나 음의 배수 같은 데서는 `Int`로 옮겨야 안전합니다.

**Q5. `have`와 `let`의 차이는요?**  
A: `have`는 "이런 명제를 보였다"는 보조 사실의 도입. `let`은 "이 표현을 이 이름으로 줄여 쓴다"는 정의의 도입. 본 강의에서는 `have`만 사용했어요.

**Q6. 본 자료를 다 따라쳤는데 자꾸 컴파일 오류가 나요.**  
A: 가장 흔한 원인 세 가지: (1) `∣` 대신 `|`을 씀, (2) `import Mathlib`을 빠뜨림, (3) Mathlib 버전이 달라 정리 이름이 다름. 이 세 가지를 먼저 확인하세요.
