## 2.1 서론 — 진법이란 무엇인가

우리는 보통 **10진법**(decimal, base 10)으로 수를 표현한다. 그런데 컴퓨터는 **2진법**(binary, base 2)을, 바이트 표현은 **16진법**(hexadecimal, base 16)을, 초창기 유닉스 시스템은 **8진법**(octal, base 8)을 쓴다. 이 절에서는:

1. 임의의 밑(base) $b > 1$로 정수를 표현하는 방법
2. 밑 사이의 변환 알고리즘
3. 덧셈·곱셈·나눗셈·나머지 지수승의 효율적 알고리즘과 복잡도

를 배운다.

### 2.1.1 왜 이것이 중요한가

컴퓨터 하드웨어는 오로지 0과 1만 다룬다. **소수·정수·문자·이미지·신경망 가중치 모두 2진수 비트열이다**. 이 절에서 배우는 알고리즘은 CPU가 매 clock마다 실행하는 바로 그 연산이며, 암호학의 RSA·AES의 핵심이 2.7절 "빠른 나머지 지수승"이다.

## 2.2 정수의 진법 표현 — 정리 1

### 2.2.1 수학적 진술

> **정리 1**. $b > 1$이 정수라 하자. $n$이 양의 정수이면, $n$은 다음과 같은 **유일한** 형태로 표현할 수 있다.
>
> $$n = a_k b^k + a_{k-1} b^{k-1} + \cdots + a_1 b + a_0$$
>
> 여기서 $k$는 음이 아닌 정수, $a_0, a_1, \dots, a_k$는 $b$ 미만의 음이 아닌 정수, $a_k \neq 0$이다.

이 표현을 $n$의 **밑 $b$ 전개**(base-b expansion) 또는 $(a_k a_{k-1} \cdots a_0)_b$로 쓴다.

### 2.2.2 네 가지 주요 밑

| 밑 $b$ | 이름 | 사용 숫자 |
|--------|------|-----------|
| 2 | **2진법**(binary) | 0, 1 |
| 8 | **8진법**(octal) | 0~7 |
| 10 | **10진법**(decimal) | 0~9 |
| 16 | **16진법**(hexadecimal) | 0~9, A, B, C, D, E, F |

### 2.2.3 예제 1 — 2진법에서 10진법

$(1\;0101\;1111)_2$의 10진 전개는?

**풀이**:
$$1 \cdot 2^8 + 0 \cdot 2^7 + 1 \cdot 2^6 + 0 \cdot 2^5 + 1 \cdot 2^4 + 1 \cdot 2^3 + 1 \cdot 2^2 + 1 \cdot 2^1 + 1 \cdot 2^0$$
$$= 256 + 64 + 16 + 8 + 4 + 2 + 1 = 351$$

### 2.2.4 예제 2 — 8진법에서 10진법

$(7016)_8 = 7 \cdot 8^3 + 0 \cdot 8^2 + 1 \cdot 8 + 6 = 3584 + 8 + 6 = 3598$

### 2.2.5 예제 3 — 16진법에서 10진법

$(2\text{AE0B})_{16} = 2 \cdot 16^4 + 10 \cdot 16^3 + 14 \cdot 16^2 + 0 \cdot 16 + 11 = 175627$

여기서 A=10, B=11, C=12, D=13, E=14, F=15임을 기억하자.

### 2.2.6 Python으로 확인

```python
# 파이썬 기본 내장
print(int('101011111', 2))      # 351
print(int('7016', 8))            # 3598
print(int('2AE0B', 16))          # 175627

# 반대: 10진 → 다른 진법
print(bin(351))                  # '0b101011111'
print(oct(3598))                 # '0o7016'
print(hex(175627))               # '0x2ae0b'
```

## 2.3 밑수 변환 알고리즘

### 2.3.1 10진 → 밑 $b$ 알고리즘

**아이디어**. $n = bq_0 + a_0$ ($0 \le a_0 < b$)에서 $a_0$는 **가장 오른쪽 자릿수**이다. 다음 $q_0$에 같은 과정을 반복하면 오른쪽에서 왼쪽으로 자릿수가 하나씩 얻어진다.

### 2.3.2 알고리즘 1 — 밑 $b$ 전개 (의사코드)

```
procedure base_b_expansion(n, b : positive integers with b > 1)
    q := n
    k := 0
    while q ≠ 0
        a_k := q mod b
        q := q div b
        k := k + 1
    return (a_{k-1}, ..., a_1, a_0)   {왼쪽이 큰 자릿수}
```

### 2.3.3 예제 4 — $(12345)_{10}$의 8진 전개

**풀이**:
```
12345 = 8 · 1543 + 1      ← a_0 = 1
 1543 = 8 ·  192 + 7      ← a_1 = 7
  192 = 8 ·   24 + 0      ← a_2 = 0
   24 = 8 ·    3 + 0      ← a_3 = 0
    3 = 8 ·    0 + 3      ← a_4 = 3
```

나머지를 오른쪽에서 왼쪽으로 읽으면: $(12345)_{10} = (30071)_8$.

### 2.3.4 예제 6 — $(241)_{10}$의 2진 전개

```
241 = 2 · 120 + 1
120 = 2 ·  60 + 0
 60 = 2 ·  30 + 0
 30 = 2 ·  15 + 0
 15 = 2 ·   7 + 1
  7 = 2 ·   3 + 1
  3 = 2 ·   1 + 1
  1 = 2 ·   0 + 1
```

결과: $(241)_{10} = (1111\;0001)_2$.

### 2.3.5 Python 구현

```python
def base_b_expansion(n: int, b: int) -> str:
    """n을 밑 b로 전개하여 문자열로 반환."""
    if n == 0:
        return "0"
    digits = "0123456789ABCDEF"
    result = []
    while n > 0:
        result.append(digits[n % b])
        n //= b
    return "".join(reversed(result))

# 확인
print(base_b_expansion(12345, 8))   # 30071
print(base_b_expansion(241, 2))     # 11110001
print(base_b_expansion(175627, 16)) # 2AE0B
```

### 2.3.6 왜 이 알고리즘이 정확한가 — 정당성 증명

**주장**. 알고리즘이 종료될 때, $n = a_k b^k + \cdots + a_1 b + a_0$.

**증명 스케치** (수학적 귀납법, §5.1에서 다룸).

**귀납 기저**. $n < b$이면 첫 단계에서 $q = 0$이 되고 $a_0 = n$. 즉 $n = a_0$.

**귀납 단계**. $n \ge b$이면 $n = b q_0 + a_0$. $q_0 < n$이므로 귀납 가설에 의해 $q_0 = a_k b^{k-1} + \cdots + a_2 b + a_1$ (단 여기 $a_i$는 알고리즘이 다음에 뽑는 나머지들). 양변에 $b$를 곱하고 $a_0$을 더하면:
$$n = b q_0 + a_0 = a_k b^k + \cdots + a_1 b + a_0 \quad \blacksquare$$

## 2.4 2진·8진·16진 사이의 고속 변환

### 2.4.1 관찰

- **8진수 1자리 = 2진수 3자리** (8 = 2³)
- **16진수 1자리 = 2진수 4자리** (16 = 2⁴)

따라서 2진과 8진, 2진과 16진 사이의 변환은 **3비트 또는 4비트씩 끊어 대응시키는 것**으로 끝난다.

### 2.4.2 대응표

| 10진 | 2진 | 8진 | 16진 |
|------|-----|-----|------|
| 0 | 0000 | 0 | 0 |
| 1 | 0001 | 1 | 1 |
| 2 | 0010 | 2 | 2 |
| 3 | 0011 | 3 | 3 |
| 4 | 0100 | 4 | 4 |
| 5 | 0101 | 5 | 5 |
| 6 | 0110 | 6 | 6 |
| 7 | 0111 | 7 | 7 |
| 8 | 1000 | 10 | 8 |
| 9 | 1001 | 11 | 9 |
| 10 | 1010 | 12 | A |
| 11 | 1011 | 13 | B |
| 12 | 1100 | 14 | C |
| 13 | 1101 | 15 | D |
| 14 | 1110 | 16 | E |
| 15 | 1111 | 17 | F |

### 2.4.3 예제 7

$(11\;1110\;1011\;1100)_2$를 8진과 16진으로 변환하라.

**8진 변환** — 오른쪽에서 3비트씩 끊는다.
```
11 | 1110 | 1011 | 1100   → 재그룹화
 0 011 | 111 | 010 | 111 | 100
   3       7     2     7     4
```
$(37274)_8$.

**16진 변환** — 오른쪽에서 4비트씩 끊는다.
```
11 | 1110 | 1011 | 1100
0011 1110 1011 1100
  3   E    B    C
```
$(3\text{EBC})_{16}$.

### 2.4.4 8진 → 2진: $(765)_8$

각 자리를 3비트로:
```
7 → 111,  6 → 110,  5 → 101
(765)_8 = (1 1111 0101)_2
```

### 2.4.5 Python 구현

```python
def oct_to_bin(oct_str: str) -> str:
    return ''.join(format(int(c), '03b') for c in oct_str).lstrip('0') or '0'

def hex_to_bin(hex_str: str) -> str:
    return ''.join(format(int(c, 16), '04b') for c in hex_str).lstrip('0') or '0'

def bin_to_oct(bin_str: str) -> str:
    # 뒤에서 3자리씩 끊어 변환
    padded = bin_str.zfill((len(bin_str) + 2) // 3 * 3)
    return ''.join(str(int(padded[i:i+3], 2)) for i in range(0, len(padded), 3)).lstrip('0') or '0'

def bin_to_hex(bin_str: str) -> str:
    padded = bin_str.zfill((len(bin_str) + 3) // 4 * 4)
    return ''.join(format(int(padded[i:i+4], 2), 'X') for i in range(0, len(padded), 4)).lstrip('0') or '0'

# 테스트
print(bin_to_oct("11111010111100"))    # 37274
print(bin_to_hex("11111010111100"))    # 3EBC
print(oct_to_bin("765"))                # 111110101
print(hex_to_bin("A8D"))                # 101010001101
```

## 2.5 이진 덧셈 알고리즘

### 2.5.1 알고리즘의 아이디어

$a = (a_{n-1} \cdots a_1 a_0)_2$, $b = (b_{n-1} \cdots b_1 b_0)_2$라 하자. 종이로 덧셈 하듯이:

1. 오른쪽 끝 비트부터: $a_0 + b_0 = c_0 \cdot 2 + s_0$, 여기서 $c_0$는 받아올림
2. 다음 자리: $a_1 + b_1 + c_0 = c_1 \cdot 2 + s_1$
3. 계속 반복
4. 마지막에 $s_n = c_{n-1}$이 최고위 비트가 됨

결과: $a + b = (s_n s_{n-1} \cdots s_1 s_0)_2$.

### 2.5.2 알고리즘 2 — 이진 덧셈 (의사코드)

```
procedure add(a, b : positive integers with binary expansions
              (a_{n-1}...a_0)_2, (b_{n-1}...b_0)_2)
    c := 0
    for j := 0 to n - 1
        d := ⌊(a_j + b_j + c) / 2⌋
        s_j := a_j + b_j + c - 2d
        c := d
    s_n := c
    return (s_n, s_{n-1}, ..., s_0)
```

### 2.5.3 예제 8 — $(1110)_2 + (1011)_2$

```
   1  1  1          ← 받아올림
     1  1  1  0
   + 1  0  1  1
   ──────────────
   1  1  0  0  1    = (11001)_2 = 25 (= 14 + 11)
```

### 2.5.4 복잡도 분석

예제 9. 두 $n$비트 정수를 더하는 데 **O($n$)번**의 비트 덧셈이 필요하다.

**이유**. 각 자릿수마다 상수 번의 비트 연산(덧셈·비교)이 필요하고, 자릿수는 $n$개이므로 총 $O(n)$.

### 2.5.5 Python 구현 (교육용, 비트별로)

```python
def binary_add(a_bits: list, b_bits: list) -> list:
    """a_bits, b_bits는 낮은 자릿수부터 저장된 비트 리스트.
    반환도 같은 형식."""
    n = max(len(a_bits), len(b_bits))
    # 길이 맞추기 (0으로 패딩)
    a = a_bits + [0] * (n - len(a_bits))
    b = b_bits + [0] * (n - len(b_bits))
    s = []
    c = 0
    for j in range(n):
        total = a[j] + b[j] + c
        d = total // 2
        s.append(total - 2 * d)
        c = d
    s.append(c)
    # 선행 0 제거
    while len(s) > 1 and s[-1] == 0:
        s.pop()
    return s

# 테스트: 1110 + 1011 = 11001
a = [0, 1, 1, 1]      # 1110 = 14 (오른쪽이 LSB라 역순)
b = [1, 1, 0, 1]      # 1011 = 11
print(binary_add(a, b))  # [1, 0, 0, 1, 1] = 11001 = 25
```

## 2.6 이진 곱셈 알고리즘

### 2.6.1 아이디어

분배법칙을 쓰면:
$$ab = a(b_0 \cdot 2^0 + b_1 \cdot 2^1 + \cdots + b_{n-1} \cdot 2^{n-1})$$
$$= a b_0 \cdot 2^0 + a b_1 \cdot 2^1 + \cdots + a b_{n-1} \cdot 2^{n-1}$$

- $b_j = 1$이면 해당 항은 $a \cdot 2^j$ (즉 $a$를 $j$비트 **왼쪽으로 시프트**)
- $b_j = 0$이면 0

마지막에 이 **부분곱들을 모두 더한다**.

### 2.6.2 알고리즘 3 — 이진 곱셈 (의사코드)

```
procedure multiply(a, b : positive integers with binary expansions
                   (a_{n-1}...a_0)_2, (b_{n-1}...b_0)_2)
    for j := 0 to n - 1
        if b_j = 1 then c_j := a shifted j places
        else c_j := 0
    p := 0
    for j := 0 to n - 1
        p := add(p, c_j)
    return p
```

### 2.6.3 예제 10 — $(110)_2 \times (101)_2$

$a = 110 = 6$, $b = 101 = 5$.

```
   ab_0 · 2^0 = (110)_2 · 1 · 2^0 = (110)_2
   ab_1 · 2^1 = (110)_2 · 0 · 2^1 = (000)_2
   ab_2 · 2^2 = (110)_2 · 1 · 2^2 = (11000)_2
```

모두 더하면: $(110)_2 + (000)_2 + (11000)_2 = (11110)_2 = 30 = 6 \times 5$. 

### 2.6.4 복잡도 분석

예제 11. 알고리즘 3은 총 **O($n^2$)번**의 비트 연산이 필요하다.

**이유**.
- **시프트**: $j = 0, 1, \dots, n-1$에 대해 최대 $0 + 1 + \cdots + (n-1) = n(n-1)/2 = O(n^2)$비트 이동.
- **덧셈**: 부분곱 $n$개를 모두 더하는데, 각 덧셈이 $O(n) \sim O(2n)$비트 덧셈. 합 $n$번 → $O(n^2)$.

### 2.6.5 최신 결과 — 곱셈은 더 빨라질 수 있는가

전통 알고리즘이 $O(n^2)$이지만:

| 알고리즘 | 연도 | 복잡도 |
|---------|------|--------|
| 전통 알고리즘 (알고리즘 3) | 기원전 | $O(n^2)$ |
| **카라추바**(Karatsuba, §8.3) | 1960 | $O(n^{1.585})$ |
| **톰-쿡**(Toom-Cook) | 1963 | $O(n^{\log_3 5}) \approx O(n^{1.465})$ |
| **쇤하게-슈트라센**(Schönhage-Strassen) | 1971 | $O(n \log n \log\log n)$ |
| **하베이-반 데어 후번**(Harvey-van der Hoeven) | 2019 | $O(n \log n)$ |

마지막 결과는 이론적 하한에 도달한 것이라고 많이 믿어지지만 확실치는 않다. **CPU 실제 구현에는 GMP 같은 라이브러리가 카라추바를 사용한다**.

## 2.7 div와 mod 알고리즘

### 2.7.1 알고리즘 4 — 나눗셈 알고리즘 (의사코드)

```
procedure division_algorithm(a : integer, d : positive integer)
    q := 0
    r := |a|
    while r ≥ d
        r := r - d
        q := q + 1
    if a < 0 and r > 0 then
        r := d - r
        q := -(q + 1)
    return (q, r)   { q = a div d,  r = a mod d }
```

### 2.7.2 아이디어

$a > 0$이면: $r$이 $d$ 미만이 될 때까지 $d$를 계속 뺀다. 뺀 횟수가 $q$, 남은 값이 $r$.

$a < 0$이면: $|a|$에 대해 위 절차를 적용한 뒤 부호 보정. 나머지가 0보다 크면 $r := d - r$, $q := -(q+1)$로 조정해서 $0 \le r < d$를 맞춘다.

### 2.7.3 복잡도

이 **억지 알고리즘**은 $O(q \log a)$비트 연산이다. 각 반복이 $O(\log a)$비트 뺄셈이고 $q$번 반복.

### 2.7.4 더 나은 알고리즘

$q = a \;\mathbf{div}\; d$와 $r = a \;\mathbf{mod}\; d$를 **$O(\log a \cdot \log d)$**비트 연산으로 할 수 있다. Knuth *TAOCP* 권2에 자세히 설명되어 있다. $a, d$가 모두 $n$비트 이하면 $\log a \cdot \log d \le n^2$이므로 **$O(n^2)$**로 나눗셈이 된다.

## 2.8 빠른 나머지 지수승 — 이 절의 클라이맥스

### 2.8.1 동기

암호학에서는 $b^n \;\mathbf{mod}\; m$을 **효율적으로** 계산하는 것이 중요하다. 여기서 $b, n, m$은 큰 정수이다.

**나쁜 방법**. $b^n$을 먼저 계산한 뒤 $m$으로 나눠 나머지를 구한다. $b^n$의 값이 너무 커서(예: $b = m = 2^{1024}$, $n = 2^{1000}$), 저장에 천문학적 메모리가 필요하다.

**좋은 방법**. **누승 지수 $n$의 2진 전개**를 이용한 반복 제곱법(iterated squaring).

### 2.8.2 수학적 아이디어

$n = (a_{k-1} \cdots a_1 a_0)_2$라 하자. 그러면:

$$b^n = b^{a_{k-1} \cdot 2^{k-1} + \cdots + a_1 \cdot 2 + a_0} = b^{a_{k-1} \cdot 2^{k-1}} \cdots b^{a_1 \cdot 2} \cdot b^{a_0}$$

즉 $b, b^2, b^4, b^8, \dots, b^{2^{k-1}}$만 계산한 뒤 $a_j = 1$인 항만 곱하면 된다!

**효율 향상의 핵심**. 각 단계마다 **제곱**하고 **m으로 나눈 나머지**를 즉시 구하면 중간 값이 $m$ 미만으로 유지된다. 메모리 폭발을 막는다.

### 2.8.3 알고리즘 5 — 빠른 나머지 지수승 (의사코드)

```
procedure modular_exponentiation(b : integer,
    n = (a_{k-1} a_{k-2} ... a_1 a_0)_2, m : positive integers)
    x := 1
    power := b mod m
    for i := 0 to k - 1
        if a_i = 1 then x := (x · power) mod m
        power := (power · power) mod m
    return x  { x = b^n mod m }
```

### 2.8.4 예제 12 — $3^{644} \;\mathbf{mod}\; 645$

$644 = (1010000100)_2$이므로 $k = 10$개 비트.

```
i=0: a_0=0 → x=1;        power = 3^2 mod 645 = 9
i=1: a_1=0 → x=1;        power = 9^2 mod 645 = 81
i=2: a_2=1 → x=1·81=81;  power = 81^2 mod 645 = 6561 mod 645 = 111
i=3: a_3=0 → x=81;       power = 111^2 mod 645 = 12321 mod 645 = 66
i=4: a_4=0 → x=81;       power = 66^2 mod 645 = 4356 mod 645 = 486
i=5: a_5=0 → x=81;       power = 486^2 mod 645 = 236196 mod 645 = 126
i=6: a_6=0 → x=81;       power = 126^2 mod 645 = 15876 mod 645 = 396
i=7: a_7=1 → x=81·396 mod 645 = 471;  power = 396^2 mod 645 = 81
i=8: a_8=0 → x=471;      power = 81^2 mod 645 = 111
i=9: a_9=1 → x=(471·111) mod 645 = 36;  power = ...
```

최종: $3^{644} \;\mathbf{mod}\; 645 = 36$.

### 2.8.5 복잡도

알고리즘 5는 $O((\log m)^2 \log n)$비트 연산을 사용한다.

**이유**.
- 루프는 $\log_2 n$번 반복
- 각 반복마다 $O(\log m)$비트 정수의 곱셈 1~2번, 각 곱셈은 $O((\log m)^2)$ (전통 알고리즘)
- 총 $\log n \cdot (\log m)^2 = O((\log m)^2 \log n)$

### 2.8.6 Python 구현

```python
def modular_exponentiation(b: int, n: int, m: int) -> int:
    """알고리즘 5: b^n mod m을 반복 제곱으로 계산."""
    x = 1
    power = b % m
    while n > 0:
        if n & 1:           # 현재 최하위 비트가 1
            x = (x * power) % m
        power = (power * power) % m
        n >>= 1              # n을 오른쪽으로 1비트 시프트 (n // 2)
    return x

# 예제 12
print(modular_exponentiation(3, 644, 645))   # 36
# Python 내장과 일치?
print(pow(3, 644, 645))                       # 36

# 거대한 숫자 테스트 (RSA 스케일)
import secrets
p = secrets.randbits(512)
q = secrets.randbits(512)
n, e = p * q, 65537
msg = 12345
c = modular_exponentiation(msg, e, n)
print(f"암호문 c (일부): {str(c)[:60]}...")
```

### 2.8.7 교수자 주: 이것이 **RSA 암호의 1/3**이다

RSA 암호에서 두 번의 나머지 지수승이 전부이다.
- **암호화**: $c = m^e \;\mathbf{mod}\; n$
- **복호화**: $m = c^d \;\mathbf{mod}\; n$

이 연산을 **초당 수천 번** 효율적으로 실행해야 TLS/HTTPS가 돌아간다. 브라우저의 자물쇠 아이콘 하나가 바로 이 알고리즘에 의존한다.

```lean
-- 빠른 나머지 지수승 (교육용 재귀 구현)
def modPow (b n m : Nat) : Nat :=
  if m = 1 then 0 else
  let rec aux (b n acc : Nat) : Nat :=
    if n = 0 then acc
    else if n % 2 = 1 then
      aux ((b * b) % m) (n / 2) ((acc * b) % m)
    else
      aux ((b * b) % m) (n / 2) acc
  aux (b % m) n 1

#eval modPow 3 644 645     -- 36
```

## 2.10 최신 AI 연결 — 효율적 알고리즘의 중요성

### 2.10.1 신경망의 행렬 곱셈

Transformer 기반 LLM의 핵심 연산은 **큰 행렬 곱셈**이다. $n \times n$ 행렬 두 개의 곱셈은 원래 $O(n^3)$이다.

| 알고리즘 | 복잡도 |
|---------|--------|
| 고전적 | $O(n^3)$ |
| **스트라센**(Strassen) | $O(n^{2.807})$ |
| **코퍼스미스-위노그라드**(Coppersmith-Winograd) | $O(n^{2.373})$ |
| 현재 기록 (2023) | $O(n^{2.371866})$ |

GPT-4 크기의 모델에서 이 지수 차이가 **몇 시간 vs 몇 주**의 학습 시간 차이로 이어진다.

### 2.10.2 양자화(quantization)와 비트 표현

LLM을 휴대폰에서 돌리려면 가중치를 **4비트 정수**로 양자화한다. 이때:

- 원래 가중치(float32): 32비트
- INT4 양자화: 4비트 (1/8 크기)

이 절에서 배운 **비트 표현**의 기초가 양자화의 핵심이다. GGUF 포맷, AWQ, GPTQ 모두 그룹별 비트 할당과 재구성 방식의 차이이다.

### 2.10.3 RAG와 이진 임베딩

**Binary embeddings**(이진 임베딩)은 질의 벡터를 0/1 비트열로 양자화해 **XOR + popcount**로 코사인 유사도를 근사한다.

```python
# 예: 1024차원 벡터를 128바이트(1024비트)로 압축
# 유사도 = 1024 - 2 * popcount(XOR(a, b))

import numpy as np
a = (np.random.randn(1024) > 0).astype(np.uint8)
b = (np.random.randn(1024) > 0).astype(np.uint8)
similarity = 1024 - 2 * np.sum(a ^ b)
print(f"Hamming 유사도: {similarity}")
```

**Quantized RAG**(양자화 RAG)라 불리는 이 기법은 벡터 검색을 **40배 빠르게** 하면서 정확도 손실이 1~3%에 불과하다. 현재 프로덕션 RAG 시스템(예: Cohere Compass, Voyage AI)의 기본 기법이다.

## 2.11 이 절의 핵심 요약

1. 모든 양의 정수는 임의의 밑 $b > 1$로 **유일하게** 표현된다 (정리 1).
2. 밑 $b$ 전개 알고리즘은 " $b$로 나눈 나머지를 오른쪽에서 왼쪽으로" 쌓는다.
3. 2진, 8진, 16진은 서로 **3비트/4비트 덩어리**로 즉시 변환된다.
4. $n$비트 정수의 덧셈은 $O(n)$, 전통 곱셈은 $O(n^2)$, 현대 알고리즘은 $O(n \log n)$.
5. **빠른 나머지 지수승**은 $O((\log m)^2 \log n)$. RSA 암호의 심장.
6. 이 모든 알고리즘의 수학적 정당성은 §4.1의 정리 1, 나눗셈 알고리즘, 정리 5로 증명된다.
