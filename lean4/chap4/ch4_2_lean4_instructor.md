## §1. 들어가며

§4.2 강의에서는 **정수의 표현**과 **진법 변환 알고리즘**을 다룹니다. 우리가 평소 쓰는 10진법뿐만 아니라 2진법, 8진법, 16진법 등 다양한 진법으로 같은 수를 표현할 수 있어요. 진법 사이의 변환과 그 효율적인 알고리즘이 이 절의 중심 주제입니다.

Lean 4에서는 이를 다루기 위해 **`Nat.digits`**라는 표준 API가 Mathlib에 들어 있어요. 본 자료는 이 API의 사용법을 익히고, 모듈러 멱승 알고리즘까지 다룹니다.

본 강의를 마치고 나면 여러분은 다음을 할 수 있게 됩니다.

1. Mathlib의 `Nat.digits` 함수로 자연수를 임의의 진법으로 변환할 수 있어요.
2. `Nat.ofDigits`로 자릿수 리스트를 다시 원래 자연수로 합성할 수 있습니다.
3. 2진법·8진법·16진법으로의 변환 예제를 다룰 수 있어요.
4. 모듈러 멱승(`a^n mod m`)을 효율적으로 계산하는 알고리즘을 Lean 4로 직접 구현할 수 있습니다.

## §2. `Nat.digits`로 진법 변환하기

**정의** Mathlib의 `Nat.digits b n`은 자연수 `n`을 `b`진법으로 표현했을 때의 자릿수 리스트를 돌려줍니다. 단, **낮은 자리부터** 순서로 적혀요.

[Q] "낮은 자리부터"라는 점이 종이의 직관과 다르죠? 종이에서는 1234를 왼쪽부터 1, 2, 3, 4로 적습니다. 그런데 Lean 4는 오른쪽부터요. 왜일까요? (5초)

답: 알고리즘의 자연스러움 때문이에요. 어떤 수를 진법으로 변환할 때 가장 먼저 알게 되는 자릿수는 가장 낮은 자리(즉 `n mod b`)입니다. 그러니까 그 순서대로 적는 게 자연스러워요. 시각적으로는 리스트를 거꾸로 읽으면 됩니다.

[ANALOGY] 동전 세는 걸 떠올려 보세요. 큰 금액을 동전으로 거슬러 줄 때, 보통 작은 동전부터 처리하지 않나요? 23,456원이면 먼저 6, 그 다음 50, 그 다음 400, ... 이런 식으로. Lean 4의 `digits`도 같은 발상이에요.

예를 들어, 십진수 1234는 다음과 같이 표현됩니다.

```
1234 = 1·1000 + 2·100 + 3·10 + 4·1
```

낮은 자리부터 4, 3, 2, 1. 따라서 `Nat.digits 10 1234 = [4, 3, 2, 1]`이에요.

```lean
import Mathlib

example : Nat.digits 10 1234 = [4, 3, 2, 1] := by decide
```

이 한 줄이 위 사실을 컴퓨터가 직접 계산으로 검증한 것입니다.

[DEMO] 자, 편집기를 열고 시범을 보입니다. 다른 수도 한번 해 봐요.

```lean
#eval Nat.digits 10 5678
```

`#eval`은 명령(command)입니다. 정리가 아니라 "이 값을 계산해서 출력하라"는 시연. InfoView 또는 화면 하단에 결과가 표시돼요.

**2진법 시연** 13을 2진법으로 표현하면 `1101₂`입니다. 8 + 4 + 1 = 13.

```
13 = 1·8 + 1·4 + 0·2 + 1·1 = 1101₂
```

낮은 자리부터 1, 0, 1, 1. 따라서 `Nat.digits 2 13 = [1, 0, 1, 1]`.

```lean
example : Nat.digits 2 13 = [1, 0, 1, 1] := by decide
```

[STUDENT TRY] 자, 손계산 활동. 28을 2진법으로 표현하면 어떻게 될까요? (1분 대기) 결과를 종이에 쓴 다음, Lean 4로 검증해 보세요.

답: `28 = 16 + 8 + 4 = 11100₂`. 낮은 자리부터 0, 0, 1, 1, 1. `Nat.digits 2 28 = [0, 0, 1, 1, 1]`.

**16진법 시연** 255 = 16² − 1 = FF₁₆. 두 자리 모두 15.

```lean
example : Nat.digits 16 255 = [15, 15] := by decide
```

Lean 4에서는 16진법의 자릿수가 0~15까지의 **자연수**로 표현돼요. 종이의 `F`(15에 해당)는 그저 `15`로 적힙니다.

[WATCH] 학생들이 종종 "왜 F가 아니라 15죠?"라고 묻습니다. Lean 4의 자릿수는 추상적인 자연수일 뿐이고, F·A·B 같은 16진 표기는 사람의 편의를 위한 표시예요. 형식 증명에서는 추상적 표현이 더 자연스럽습니다.

**8진법 시연** 64 = 8² = 100₈.

```lean
example : Nat.digits 8 64 = [0, 0, 1] := by decide
```

낮은 자리부터 0, 0, 1. 종이의 `100₈`을 거꾸로 읽으면 정확히 이 리스트.

[AI] 진법 변환은 컴퓨터가 메모리에서 데이터를 저장·전송하는 방식의 핵심이에요. 데이터베이스 시스템, 네트워크 프로토콜, 암호화 — 모두 이진 표현을 기반으로 합니다. AI가 학습한 모델 가중치를 저장할 때도 결국 이진 형태이고요. 우리가 오늘 배우는 이 단순한 API가 사실 컴퓨터 과학 전체의 기초입니다.

### 코드 1~5의 InfoView 정밀 관찰

**`Nat.digits`의 정의** Mathlib에는 다음 골격으로 정의되어 있어요.

```
Nat.digits b n :=
  if n = 0 then []
  else (n % b) :: Nat.digits b (n / b)
```

(실제 정의는 종료성 보장을 위해 조금 더 복잡하지만 본질은 위와 같습니다.)

따라서 1234의 분해는 다음과 같이 진행돼요.

```
Nat.digits 10 1234
  = (1234 % 10) :: Nat.digits 10 (1234 / 10)
  = 4 :: Nat.digits 10 123
  = 4 :: 3 :: Nat.digits 10 12
  = 4 :: 3 :: 2 :: Nat.digits 10 1
  = 4 :: 3 :: 2 :: 1 :: Nat.digits 10 0
  = 4 :: 3 :: 2 :: 1 :: []
  = [4, 3, 2, 1]
```

`decide`가 이 사슬을 자동으로 따라갑니다.

[DEMO] 이게 진법 변환 알고리즘의 본질입니다. "나머지를 떼어 내고, 몫으로 다시 시작". 손계산도 정확히 같은 절차로 해요.

## §3. 자릿수에서 원래 수 복원하기 - `Nat.ofDigits`

`Nat.digits`의 역연산이 `Nat.ofDigits`예요. 자릿수 리스트와 진법을 받아 원래 자연수를 돌려줍니다.

**핵심 정리** Mathlib의 `Nat.ofDigits_digits`:

```
Nat.ofDigits_digits : ∀ (b n : Nat), Nat.ofDigits b (Nat.digits b n) = n
```

말로 풀면 "어떤 수를 진법으로 분해했다가 다시 합성하면 원래 수가 된다". 분해 → 복원이 항상 일관됨을 보장합니다.

[ANALOGY] 마치 단풍잎 책갈피처럼, 어떤 색깔의 단풍잎을 보고 (수를 보고) 그것을 분해해 종류별로 모으고, 다시 합치면 원래 단풍잎이 되돌아오는 것과 같아요. 정보를 잃지 않는다는 보장입니다.

```lean
theorem digits_round_trip (n : Nat) :
    Nat.ofDigits 10 (Nat.digits 10 n) = n :=
  Nat.ofDigits_digits 10 n
```

본 정리는 인수 두 개(`10`, `n`)만 넘기면 끝.

**시연** 1234의 자릿수 리스트를 다시 합치면 1234.

```lean
example : Nat.ofDigits 10 [4, 3, 2, 1] = 1234 := by decide
```

내부적으로 `Nat.ofDigits 10 [4, 3, 2, 1]`은 다음과 같이 계산돼요.

```
4 + 10·(3 + 10·(2 + 10·(1 + 10·0)))
= 4 + 10·(3 + 10·(2 + 10·1))
= 4 + 10·(3 + 10·12)
= 4 + 10·123
= 4 + 1230
= 1234.
```

낮은 자리부터 끄집어내어 진법의 거듭제곱과 곱해 누적합니다. 이것이 진법 합성의 본질이에요.

[Q] 왜 `Nat.ofDigits` 알고리즘이 "낮은 자리부터 누적"으로 정의되어 있을까요? (5초) 답: 그게 `Nat.digits`의 역연산이기 때문이에요. 둘이 정확히 거꾸로 작동하니까 round-trip이 성립합니다.

## §4. 자릿수의 개수

자릿수의 개수는 `(Nat.digits b n).length`로 얻습니다.

**시연 모음**

```lean
example : (Nat.digits 10 1234).length = 4 := by decide
example : (Nat.digits 10 9).length    = 1 := by decide
example : (Nat.digits 10 10).length   = 2 := by decide
example : (Nat.digits 10 99).length   = 2 := by decide
example : (Nat.digits 10 100).length  = 3 := by decide
```

[Q] 패턴이 보이세요? (3초) 그래요. 10⁰ ≤ n < 10¹이면 자릿수는 1. 10¹ ≤ n < 10²이면 자릿수는 2. 일반적으로 10^(d−1) ≤ n < 10^d이면 자릿수는 d.

이 사실을 일반적으로 형식화한 정리도 Mathlib에 있어요(예: `Nat.size_le`, `Nat.size_digits`). 본 강의에서는 직접 호출하지 않지만, 더 깊이 들어가고 싶은 학생은 검색해 볼 만합니다.

[AI] 흥미로운 관찰: 자릿수 개수는 그 수의 "크기 정보"입니다. AI 모델이 큰 수치를 처리할 때, 그 수의 자릿수 개수가 메모리 사용량과 처리 시간을 직접 결정해요. 그래서 자릿수 분석은 알고리즘의 효율성을 분석하는 첫 단계입니다. 예를 들어 곱셈 알고리즘의 시간복잡도 O(n)에서 n이 바로 자릿수 개수입니다.

[교수자 멘트] 10분 휴식 후 종합 예제로 들어갑니다. ... (휴식)

**예제 1.** 25를 2진법으로.

```
25 = 16 + 8 + 1 = 1·16 + 1·8 + 0·4 + 0·2 + 1·1 = 11001₂
```

**예제 2.** 100을 2진법으로. 100 = 64 + 32 + 4 = 1100100₂.

낮은 자리부터 0, 0, 1, 0, 0, 1, 1.

```lean
example : Nat.digits 2 100 = [0, 0, 1, 0, 0, 1, 1] := by decide
```

**예제 3.** 4095를 16진법으로. 4095 = 16³ − 1 = FFF₁₆.

```lean
example : Nat.digits 16 4095 = [15, 15, 15] := by decide
```

**예제 4.** 16진수 A2C₁₆을 10진수로.

종이의 A2C₁₆은 `A`(10) `2` `C`(12)인 세 자리. 낮은 자리부터의 리스트는 [12, 2, 10].

```
A2C₁₆ = 10·16² + 2·16 + 12 = 2560 + 32 + 12 = 2604₁₀
```

```lean
example : Nat.ofDigits 16 [12, 2, 10] = 2604 := by decide
```

[WATCH] 학생들이 16진 → 10진 변환에서 자주 헷갈리는 게 자릿수의 순서입니다. 종이의 `A2C`을 보면 `A`가 첫째 자리(높은 자리)인데, Lean 4 리스트는 낮은 자리부터예요. 그래서 `C`(12)가 첫째 원소가 됩니다. 이 순서 뒤집기를 매번 의식해야 합니다.

## §6. 모듈러 멱승 (1) - 작은 수의 직접 계산

§4.2 강의의 또 하나의 기둥 주제는 **모듈러 멱승**(modular exponentiation)입니다. 즉 `a^n mod m`을 효율적으로 계산하는 알고리즘이에요.

[Q] 왜 "효율적"이라는 말을 굳이 붙일까요? (5초) 답: `a^n`을 직접 계산하면 어마어마하게 큰 수가 나옵니다. 예를 들어 `2^1000`은 자릿수가 300개를 넘어요. 그런데 `2^1000 mod 7`은 0과 6 사이의 작은 수죠. 큰 수를 다 계산할 필요 없이, 매 단계마다 mod를 취하면 효율적입니다.

[ANALOGY] 12시간 시계 비유. 13시는 1시, 25시는 1시, 1000시도 어차피 시계로 보면 (1000 mod 12) = 4시. 굳이 1000을 통째로 다루지 말고, 매 시간이 지날 때마다 12로 mod 취하면서 가도 같은 답이 나와요.

Lean 4에서는 작은 수의 경우 `decide`가 직접 계산으로 모듈러 멱승의 값을 판정해 줍니다.

**시연 1.** 3^13 mod 7 = ?

종이로 계산하면 3¹³ = 1594323. 1594323 / 7 = 227760 나머지 3. 따라서 3¹³ mod 7 = 3.

```lean
example : 3 ^ 13 % 7 = 3 := by decide
```

[DEMO] 이걸 시범 보입니다. `decide`가 한 번에 판정해요.

**시연 2.** 페르마 소정리의 사례. p가 소수이고 `gcd(a, p) = 1`이면 `a^(p-1) ≡ 1 (mod p)`.

11은 소수이고 2와 11은 서로소예요. 그러므로 `2^10 ≡ 1 (mod 11)`이어야 합니다.

```lean
example : 2 ^ 10 % 11 = 1 := by decide
```

`decide`로 검증돼요. 종이로는 2¹⁰ = 1024 = 93·11 + 1이므로 나머지 1. 정확히 페르마 소정리.

[AI] 페르마 소정리는 RSA 암호화의 수학적 토대입니다. 인터넷 보안의 가장 흔한 알고리즘이 페르마 소정리에 기반해요. AI에서도 분산 컴퓨팅의 보안 계층에서 등장합니다. 우리가 §4.4에서 본격적으로 이 정리를 다룰 텐데, 오늘은 그 맛만 보는 거예요.

**시연 3.** 더 큰 멱승. 7^222 mod 11 = ?

페르마 소정리에 의해 7^10 ≡ 1 (mod 11)이므로

```
7^222 = 7^(22·10 + 2) = (7^10)^22 · 7^2 ≡ 1^22 · 49 = 49 ≡ 5 (mod 11)
```

```lean
example : 7 ^ 222 % 11 = 5 := by decide
```

`decide`가 작동합니다. 다만 멱승의 지수가 매우 클 경우 `decide`는 시간·메모리가 폭주할 수 있어요. 그 경우에는 `native_decide`(컴파일된 코드로 평가)를 쓰는 편이 안전합니다.

[Q] `decide`와 `native_decide`의 차이가 뭘까요? (3초) 답:
- `decide`: Lean 4 커널이 정의를 한 단계씩 환원해 계산. 정합성 보장 강함. 큰 수에서 느림.
- `native_decide`: 컴파일된 네이티브 코드로 평가. 빠름. 컴파일러 신뢰가 추가됨.

학습 단계에서는 `decide`가 표준이지만, 큰 계산에서는 `native_decide`가 더 실용적이에요.

## §7. 모듈러 멱승 (2) - 빠른 알고리즘 직접 구현

§4.2 강의의 클라이맥스. **빠른 멱승**(fast exponentiation, 또는 반복 제곱법) 알고리즘을 Lean 4로 직접 구현합니다.

**알고리즘 개요** `a^n mod m`을 계산할 때, `n`을 2진법으로 표현하고 비트별로 처리해요. 예를 들어 `a^13 = a^(1101₂) = a^8 · a^4 · a^1`. 즉 `n`이 짝수이면 `(a^(n/2))^2`로 줄이고, 홀수이면 `a · a^(n-1)`로 줄입니다. 매 단계 모듈러 연산을 함께 처리해요.

[ANALOGY] 큰 책을 한 번에 들 수 없으면, 반으로 나눠서 두 번 들고 가요. `a^n`을 한 번에 계산하기 어려우면, `(a^(n/2))^2`로 줄여서 계산하는 거죠. 같은 원리.

```lean
def fastModPow : Nat → Nat → Nat → Nat
  | _,    0,        _ => 1
  | base, exp + 1,  m =>
      if (exp + 1) % 2 = 0 then
        let half := fastModPow base ((exp + 1) / 2) m
        (half * half) % m
      else
        (base * fastModPow base exp m) % m
termination_by _ exp _ => exp
```

[DEMO] 여기서 시범을 자세히 보입니다. 새 요소들이 많아요.

**패턴 매칭으로 정의** `def fastModPow : Nat → Nat → Nat → Nat`은 세 자연수 인수를 받아 자연수를 돌려주는 함수의 선언이에요. `|`로 시작하는 줄들이 **패턴 매칭** 가지입니다.

첫 가지 `| _, 0, _ => 1`은 "어떤 `base`, 지수가 `0`, 어떤 `m`이면 답은 `1`". 종이의 "어떤 수의 0제곱은 1"을 옮긴 것. `_`(언더스코어)는 "이 자리의 값은 안 본다"는 표시.

둘째 가지 `| base, exp + 1, m =>`은 "둘째 인수가 `exp + 1` 형태, 즉 양수"인 경우. 이 가지의 안에서 `exp`라는 새 변수는 "지수에서 1을 뺀 값"을 가리켜요. 이 패턴이 본 코드의 핵심 트릭입니다. 종료성을 자동으로 보장해요.

[WATCH] 학생들이 종종 묻습니다: "왜 그냥 `| base, exp, m =>`이 아니라 `| base, exp + 1, m =>`인가요?" 답은 Lean 4가 종료성을 자동 검증할 수 있도록 하기 위함이에요. `exp + 1` 패턴은 "둘째 인수가 정확히 어떤 자연수에 1을 더한 형태"라고 박아 둡니다. 그러면 재귀 호출에서 둘째 인수가 매번 작아지는 게 자명해져요. 만약 `| base, exp, m =>`로 두면, Lean 4가 "`exp`가 0일 수도 있는데 어떻게 줄어드는가?"라고 묻습니다. 첫 가지가 그 경우를 잡아낸다는 걸 Lean 4가 자동으로 추론하지 못해요. 그래서 `exp + 1` 패턴이 도움이 됩니다.

**짝수·홀수 분기** `if (exp + 1) % 2 = 0 then ... else ...`. 짝수이면 반으로 나누어 한 단계, 홀수이면 1을 빼고 한 단계. 두 분기 모두 결국 더 작은 지수에 대한 재귀 호출로 줄어들어요.

**`termination_by`** 함수가 무한 재귀에 빠지지 않음을 Lean 4에 알리는 구문. `_ exp _ => exp`는 "세 인수 중 둘째 인수 `exp`가 매 호출마다 줄어든다"는 선언이에요. 이 한 줄로 Lean 4가 자동으로 종료성을 검증해 줍니다.

[Q] 본 코드에는 `decreasing_by`가 없죠? 위에서 명시한 `termination_by`만으로 충분한가요? (3초) 답: 그래요, 충분합니다. `exp + 1` 패턴 덕분에 종료성이 자명해져서, 별도의 `decreasing_by` 블록이 필요 없어요. 이전 버전에서는 `decreasing_by ... omega`를 명시했지만, 더 간결한 형태로 정리됐습니다.

**시연** 위에서 본 결과를 `fastModPow`로 검증.

```lean
example : fastModPow 3 13 7 = 3 := by native_decide
example : fastModPow 2 10 11 = 1 := by native_decide
example : fastModPow 7 222 11 = 5 := by native_decide
```

여기서 `decide` 대신 `native_decide`를 쓴다는 점이 중요합니다. `decide`는 Lean 4의 커널이 정의를 한 단계씩 풀어 가며 계산하는데, 큰 수의 재귀에서는 시간이 너무 오래 걸리거나 막힐 수 있어요. `native_decide`는 정의를 네이티브 코드로 컴파일한 후 평가하므로 훨씬 빠르고 안전합니다.

[STUDENT TRY] 자, 도전 활동. 5분 드릴게요. `fastModPow 2 100 13`의 값을 구해 보세요. 종이로도 한번 손계산해 보고(페르마 소정리 활용), Lean 4로도 검증해 보세요. (5분 대기)

힌트: 13은 소수이고 gcd(2, 13) = 1이므로 2^12 ≡ 1 (mod 13). 그러므로 2^100 = 2^(8·12 + 4) = (2^12)^8 · 2^4 ≡ 1·16 ≡ 3 (mod 13).

[AI] 빠른 멱승 알고리즘은 RSA 암호화의 핵심입니다. 우리가 인터넷 뱅킹, HTTPS 연결, 디지털 서명 모든 곳에서 사용하는 알고리즘이에요. AI 시스템들도 분산 처리에서 보안 통신을 할 때 이걸 활용합니다. 즉 오늘 우리가 직접 구현한 100줄짜리 함수가, 실제 세상의 보안 시스템 속에서 매 순간 작동하고 있는 거예요.

### 코드 12의 InfoView 정밀 관찰

```lean
def fastModPow : Nat → Nat → Nat → Nat
```

함수 선언. 세 자연수 인수를 받아 자연수를 돌려줍니다. `→`는 우결합이므로 `Nat → (Nat → (Nat → Nat))`로 읽힌다(커링).

```lean
  | _,    0,        _ => 1
```

**첫 패턴 매칭 가지**. 둘째 인수가 정확히 `0`인 경우. 종이의 `a^0 = 1`을 옮긴 것.

```lean
  | base, exp + 1,  m =>
```

**둘째 패턴 매칭 가지**. 둘째 인수가 `exp + 1` 형태인 경우. 즉 양수인 경우.

`exp + 1`이라는 패턴이 핵심. Lean 4에게 "둘째 인수가 어떤 자연수 `exp`에 1을 더한 형태"라고 명시.

```lean
      if (exp + 1) % 2 = 0 then
        let half := fastModPow base ((exp + 1) / 2) m
        (half * half) % m
```

**짝수 가지**. 지수가 짝수면 반복 제곱.

`a^(2k) = (a^k)^2`. 모듈러 환경에서는 `a^(2k) mod m = ((a^k mod m)^2) mod m`.

`let half := ...` 구문은 임시 변수에 값을 묶어요. 같은 값을 두 번 계산하지 않도록 캐시.

```lean
      else
        (base * fastModPow base exp m) % m
```

**홀수 가지**. 지수가 홀수면 `a · a^(exp)`. 즉 한 번 base를 곱하고 지수를 1 줄임.

여기서 둘째 인수가 `exp`(즉 `(exp + 1) - 1`)인 점에 주목. 이전 인수 `exp + 1`보다 작죠. 종료성 보장.

```lean
termination_by _ exp _ => exp
```

**종료성 명시**. 두 재귀 호출 모두에서 측도가 줄어듦을 자동 확인:
- 짝수 가지: `(exp + 1) / 2 < exp + 1` (참, 자연수 정수 나눗셈)
- 홀수 가지: `exp < exp + 1` (자명히 참)

별도의 `decreasing_by` 블록 필요 없음.

`fastModPow 3 13 7`의 동작을 손으로 추적:

```
13 = 12 + 1 (홀수)  →  3 * fastModPow 3 12 7 % 7
12 = 6 + 6 (짝수)   →  let half = fastModPow 3 6 7; half * half % 7

 2 = 1 + 1 (짝수)   →  let half = fastModPow 3 1 7; half * half % 7
 1 = 0 + 1 (홀수)   →  3 * fastModPow 3 0 7 % 7 = 3 * 1 % 7 = 3

역추적:
1단계: 3
2단계: 3*3 % 7 = 2
3단계: 3*2 % 7 = 6
4단계: 6*6 % 7 = 36 % 7 = 1
5단계: 1*1 % 7 = 1
6단계: 3*1 % 7 = 3

```

**패턴 4. 사용자 정의 재귀 함수**

```lean
def myFunc : <타입> → <타입>
  | <기저 패턴> => <기저 값>
  | <재귀 패턴 (예: x + 1)> => <재귀 호출>
termination_by <어느 인수가 줄어드는가>
```

기저 패턴이 첫 가지에서 잡히고, 재귀 패턴이 둘째 가지에서 잡히며, `termination_by`로 종료성을 명시.

## 부록 A. 자주 나오는 학생 질문

**Q1. `#eval`과 `example`의 차이는요?**  
A: `#eval`은 "이 값을 계산해서 출력하라"는 명령. 결과 확인용. `example`은 "이 명제가 참임을 증명하라"는 정리. 검증용. 둘은 결이 다릅니다.

**Q2. `decide`와 `native_decide`를 언제 구분해 써야 하나요?**  
A: 학습 단계에서는 `decide`가 표준. 큰 수의 사용자 정의 재귀 함수 검증에서는 `native_decide`. 작은 수면 어느 쪽이든 OK.

**Q3. `termination_by`의 정확한 문법은요?**  
A: `termination_by <측도 표현식>`. Lean 4 버전에 따라 `termination_by <인수 이름> => <측도>` 같은 형식도 있어요. 컴파일 오류가 나면 `#help command termination_by`로 확인.

**Q4. 본 자료의 `fastModPow`를 PythonでBの`pow(a, n, m)`과 비교하면요?**  
A: Python의 `pow(a, n, m)`은 내부적으로 똑같은 알고리즘(반복 제곱법)을 사용합니다. 우리가 Lean 4로 구현한 게 그 직접적인 형식 증명 버전이에요.

**Q5. 진법 변환에서 0을 처리할 때 빈 리스트가 나오는 게 맞나요?**  
A: 그렇습니다. `Nat.digits b 0 = []`. 빈 리스트는 "값이 0"으로 해석돼요. `Nat.ofDigits b [] = 0`이 그 짝꿍.
