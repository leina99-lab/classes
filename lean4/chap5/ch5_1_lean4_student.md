## 1. 들어가며

§5.1 강의에서는 **수학적 귀납법**(Mathematical Induction)을 배웠다. 도미노 한 줄을 세워 두고 첫 칸을 미는 것이 **기저 단계**(basis step), 한 칸이 쓰러지면 다음 칸도 쓰러지는 규칙이 **귀납 단계**(inductive step)이다. 이 두 단계가 모두 갖춰지면 무한히 많은 명제가 한꺼번에 증명된다는 것이 핵심이었다.

본 자료에서 할 일은 이 도미노 원리를 **컴퓨터가 한 치의 오차도 없이 검사하는 형태**로 옮기는 것이다. 그 도구가 Lean 4이다.


## 2. Lean 4가 무엇인가

**Lean 4**(린 포)는 **정리 증명 보조기**(theorem prover)의 일종이다. 사람이 수학 증명을 코드로 적어 넣으면, Lean 4가 한 줄 한 줄을 검사하여 그 증명이 정말 맞는지 자동으로 확인해 준다. 한 군데라도 어긋나면 빨간 줄을 띄우고 거부한다. 사람이 놓치는 빈틈을 기계가 잡아 주는 셈이다.

Lean 4를 처음 만났을 때 알아 두어야 할 세 가지가 있다.

첫째, **Mathlib**(매스립)이라는 거대한 표준 라이브러리가 함께 다닌다. Mathlib에는 수학자들이 수십 년에 걸쳐 모은 정리 수만 개가 이미 형식화되어 들어 있다. 우리가 Lean 4 코드를 짤 때 흔히 쓰는 보조 정리들은 거의 다 Mathlib 안에 있다. 본 자료의 첫 줄에 항상 `import Mathlib`이 들어가는 이유이다.

둘째, **InfoView**(인포뷰)라는 화면이 따로 있다. Lean 4 파일을 열고 코드의 어느 위치에 커서를 놓으면, 그 자리에서 "지금 우리가 손에 쥐고 있는 가정은 무엇이고, 지금 증명해야 할 목표는 무엇인가"를 InfoView가 보여 준다. 종이로 증명을 쓸 때 머릿속에 그리던 그림을, Lean 4는 화면 오른쪽에 직접 띄워 준다. 본 자료에서 `-- InfoView:` 라고 주석을 단 부분은 그 시점에 InfoView에 보이는 내용을 의미한다.

셋째, **자동화 전술**(automation tactic)은 가급적 쓰지 않는다. `simp`, `linarith`, `norm_num` 같은 강력한 전술은 한 번에 많은 단계를 건너뛰어 결론을 내려 준다. 편하기는 하지만, 그 안에서 무슨 일이 일어났는지 학습자가 알 수 없게 된다. 본 자료에서는 `rw`(고쳐 쓰기)를 중심으로, 한 단계가 어떤 보조 정리를 호출해 어떤 식으로 식이 바뀌는지를 눈으로 따라갈 수 있도록 작성한다. `omega`(자연수·정수 산술 자동 해결)와 `ring`(다항식 항등식 자동 검증), `decide`(작은 수의 직접 계산)는 한정적으로 허용한다.

## 3. 자연수가 어떻게 만들어지는가

Lean 4에서 **자연수**(natural number)의 이름은 `Nat`이다. 그리고 `Nat`은 다음과 같이 정의되어 있다.

```lean
-- Lean 4 표준 라이브러리의 자연수 정의
inductive Nat where
  | zero : Nat
  | succ (n : Nat) : Nat
```

이 정의를 한 줄씩 읽어 본다.

`inductive Nat where`는 "이제부터 `Nat`이라는 새 자료형을 **귀납적으로**(inductively) 정의한다"는 선언이다. 귀납적으로 정의한다는 말은 "원소를 만드는 방법을 몇 가지만 제시하고, 그 방법들 이외로는 만들 수 없다"는 약속이다.

`| zero : Nat`은 첫 번째 만드는 방법이다. `zero`라는 이름표를 가진 어떤 값이 `Nat`의 원소이다. 이것이 우리가 아는 0에 해당한다.

`| succ (n : Nat) : Nat`은 두 번째 만드는 방법이다. 어떤 자연수 `n`이 이미 있다면, 그것의 **후속자**(successor) `succ n`도 자연수이다. 이것이 "n 다음 수"이다.

이 둘만으로 모든 자연수가 만들어진다.

- 0은 `Nat.zero`
- 1은 `Nat.succ Nat.zero` (영의 다음)
- 2는 `Nat.succ (Nat.succ Nat.zero)` (영의 다음의 다음)
- 3은 `Nat.succ (Nat.succ (Nat.succ Nat.zero))`
- 이하 같은 방식으로 계속

이것이 도미노 비유와 정확히 일치한다. `zero`가 첫 번째 도미노이고, `succ`이 한 칸씩 다음 도미노로 넘어가는 규칙이다. 모든 자연수는 "첫 칸에서 출발해서 `succ`을 몇 번 적용했는가"로 표현된다.

핵심을 한 줄로 다시 쓴다.

> 자연수란, **`zero`에서 출발하여 `succ`을 유한 번 적용해서 얻을 수 있는 모든 값**이다. 그 외에는 자연수가 아니다.

이 정의가 왜 중요한가? 바로 다음 절에서 본다.

## 4. `induction` 전술 - 도미노를 코드로

자연수를 이렇게 두 가지(`zero`와 `succ`)만으로 정의하는 순간, Lean 4의 컴파일러가 **공짜 선물**을 하나 자동으로 만들어 준다. 그 이름은 `Nat.rec`(자연수 재귀자, natural number recursor)이다.

`Nat.rec`은 다음과 같이 말한다.

> 어떤 술어 `P`에 대해, `P 0`이 참이고, 또한 임의의 `n`에 대해 `P n`이 참이라는 가정 아래 `P (n+1)`도 참임을 보일 수 있다면, 모든 자연수 `n`에 대해 `P n`이 참이다.

이것이 §5.1 강의에서 본 **수학적 귀납법의 원리**(Principle of Mathematical Induction, PMI) 그 자체이다. 종이에 적었던 "P(1)을 보이고, P(k)이면 P(k+1)임을 보이면 모든 P(n)" — 글자 하나 다르지 않게 같은 진술이다. 다만 Lean 4의 `Nat`이 1이 아니라 0에서 시작하므로 기저가 `P 0`이다.

실제로 우리가 `Nat.rec`을 직접 호출하지는 않는다. 이는 다소 날것의 형태이다. 대신 `induction`이라는 더 편한 전술을 쓴다. `induction`이 속으로 `Nat.rec`을 호출해 준다.

기본 형태는 다음과 같다.

```lean
-- 자연수 n에 관한 임의의 명제 P n을 귀납법으로 증명하는 일반 패턴
theorem my_theorem (n : Nat) : P n := by
  induction n with
  | zero =>
    -- 여기는 기저 단계이다.
    -- 목표는 P 0 이다. 이것을 직접 증명한다.
    sorry  -- 본 자료에서는 sorry를 절대 쓰지 않는다. 여기에 실제 증명이 들어간다.
  | succ k ih =>
    -- 여기는 귀납 단계이다.
    -- ih(induction hypothesis)는 "P k가 참이라는 가정"이다. 자동으로 주어진다.
    -- 목표는 P (k+1) 이다. ih를 디딤돌 삼아 이것을 증명한다.
    sorry  -- 마찬가지로 실제 증명이 들어간다.
```

`induction n with`는 "변수 `n`에 대해 귀납법을 쓴다"는 선언이다. `with` 다음에 두 갈래가 따라온다.

첫째 갈래 `| zero =>`는 기저 단계이다. 이 갈래의 안에서는 우리의 목표가 `P 0`으로 바뀌어 있다.

둘째 갈래 `| succ k ih =>`는 귀납 단계이다. 이름 `k`는 "임의로 잡은 자연수"를 가리키고, 이름 `ih`는 "그 `k`에 대해 `P k`가 참이라는 가정"을 가리킨다. `ih`라는 이름은 **귀납 가설**(induction hypothesis)의 약자이다. 이 갈래의 안에서는 우리의 목표가 `P (k+1)`로 바뀌어 있다.

여기서 종이 증명과 Lean 4 코드의 첫 번째 정확한 대응이 나타난다.

| 종이 증명 | Lean 4 코드 |
|---|---|
| "P(1)이 참임을 보인다." | `\| zero =>` 갈래 안의 증명 |
| "임의의 k에 대해 P(k)를 가정한다." | `\| succ k ih =>` 갈래에서 `ih`라는 이름으로 자동 주어짐 |
| "P(k+1)을 보인다." | `\| succ k ih =>` 갈래 안의 증명 |
| "PMI에 의해 모든 n에 대해 P(n)이 참." | `induction` 전술이 자동으로 마무리해 줌 |

종이에서 손가락으로 "여기서 IH를 씁니다"라고 짚는 동작이, Lean 4에서는 `ih`라는 이름을 직접 호명하는 한 줄로 표현된다. 이것이 본 자료에서 반복해서 보게 될 패턴이다.

**중요한 약속 하나**. 위 코드에서 `sorry`라는 단어가 두 번 보인다. `sorry`는 "이 자리는 아직 증명하지 않았다"는 자리 표시자이다. 본 자료의 모범 답안에서는 `sorry`를 **절대 쓰지 않는다**. 모든 증명은 완성된 형태로만 제시한다. 워크북에서 학습자가 채워야 할 자리는 `sorry` 대신 `____`(밑줄 네 개)로 표시한다.

## 5. 가장 단순한 증명 - `0 + n = n`

이제 진짜 증명을 하나 처음부터 끝까지 따라간다. 일부러 가장 단순한 것을 골랐다.

**정리** 모든 자연수 `n`에 대해 `0 + n = n`이다.

이 정리는 너무 당연해 보인다. 왜 증명이 필요한가? 답은 Lean 4의 덧셈 정의에 있다.

Lean 4에서 `Nat`의 덧셈 `a + b`는 **두 번째 인수 `b`에 대해 귀납적으로** 정의되어 있다. 구체적으로는 다음 두 규칙이다.

- `a + 0 = a` (정의에 의해 즉시 성립)
- `a + (b+1) = (a + b) + 1` (정의에 의해 즉시 성립)

따라서 `n + 0 = n`은 **정의에 의해 그 자리에서 참**이다. 그러나 `0 + n = n`은 정의가 그렇게 말해 주지 않는다. 첫 번째 인수가 0인 경우는 위 두 규칙에서 직접 나오지 않기 때문이다. 직접 증명이 필요하다.

이것이 컴퓨터가 사람과 다른 점이다. 사람은 "0 더하기 무엇은 그 무엇"이라고 그냥 받아들인다. 컴퓨터는 정의에서 한 걸음 한 걸음 따라가지 않으면 인정해 주지 않는다. 답답할 때가 있지만, 그 답답함이 컴퓨터가 거짓말을 못하는 이유이다.

이제 증명을 본다.

```lean
import Mathlib

-- 정리: 모든 자연수 n에 대해 0 + n = n.
theorem zero_add_nat (n : Nat) : 0 + n = n := by
  induction n with
  | zero =>
    -- 기저 단계.
    -- InfoView 목표:  ⊢ 0 + 0 = 0
    rfl
  | succ k ih =>
    -- 귀납 단계.
    -- InfoView 가정:  k : Nat,  ih : 0 + k = k
    -- InfoView 목표:  ⊢ 0 + (k + 1) = k + 1
    rw [Nat.add_succ]
    -- 위 rw 한 줄로 목표가 다음과 같이 바뀐다.
    -- InfoView 목표:  ⊢ (0 + k) + 1 = k + 1
    rw [ih]
    -- 위 rw로 (0 + k)가 k로 치환되어 목표가 다음과 같이 된다.
    -- InfoView 목표:  ⊢ k + 1 = k + 1
    -- 양변이 같으므로 자동으로 닫힌다.
```

한 줄씩 풀어 본다.

`import Mathlib`은 Mathlib 라이브러리 전체를 불러오는 줄이다. 본 자료의 모든 예제는 첫 줄에 이 한 줄이 들어 있다고 가정한다. 실제 파일에서는 한 번만 적으면 된다.

`theorem zero_add_nat (n : Nat) : 0 + n = n := by`는 정리의 선언이다. 이름은 `zero_add_nat`, 인수는 자연수 `n` 하나, 진술은 `0 + n = n`이다. `:= by` 다음부터가 증명의 본체이다.

`induction n with`로 `n`에 대해 귀납법을 시작한다. 두 갈래가 펼쳐진다.

**기저 단계** `| zero =>`에서는 목표가 `0 + 0 = 0`이다. 위에서 본 정의에 의해 `0 + 0`은 즉시 `0`과 같다. 따라서 양변이 정의상 똑같다. 이런 경우 `rfl`(reflexivity, 반사성)이라는 한 단어로 닫힌다.

> `rfl`이 무엇인가. "이 등식의 양변은 정의상 똑같다"고 선언하는 가장 단순한 전술이다. 양변이 정말 정의상 같다면 통과하고, 다르다면 거부한다.

**귀납 단계** `| succ k ih =>`에서는 두 가지가 손에 들어온다. 첫째, `k`는 우리가 임의로 잡은 자연수이다. 둘째, `ih`는 "그 `k`에 대해 `0 + k = k`가 참이라는 가정"이다. 그리고 목표는 `0 + (k + 1) = k + 1`이다.

`rw [Nat.add_succ]`은 첫 번째 고쳐 쓰기이다. `Nat.add_succ`는 Mathlib에 있는 보조 정리로, 다음을 말한다.

```
Nat.add_succ : ∀ (n m : Nat), n + (m + 1) = (n + m) + 1
```

이 등식을 좌변에서 우변 방향으로 적용하여, 우리 목표 안의 `0 + (k + 1)`을 `(0 + k) + 1`로 바꾼다.

`rw [ih]`은 두 번째 고쳐 쓰기이다. `ih`는 `0 + k = k`라는 가정이다. 이를 적용하여 목표 안의 `0 + k`를 `k`로 바꾼다.

이제 목표는 `k + 1 = k + 1`이다. 양변이 글자 그대로 같으므로 `rw` 전술이 끝나는 시점에 자동으로 닫힌다.

여기서 한 가지를 짚어 둔다.

> 종이 증명에서 "여기서 귀납 가설을 사용했습니다"라고 손가락으로 짚는 그 동작이, Lean 4에서는 `rw [ih]`라는 한 줄이다. 종이의 손가락과 코드의 한 줄이 정확히 같은 일을 한다.

이 패턴(`rfl`로 기저를 닫고, `rw [...]`와 `rw [ih]`로 귀납을 닫는 패턴)을 본 자료에서 반복적으로 사용한다.

## 6. 다음 빈칸 - `n + 0 = n`

방금 증명한 `0 + n = n`과 거울 쌍둥이 정리를 학습자가 직접 손으로 따라가 본다.

**정리** 모든 자연수 `n`에 대해 `n + 0 = n`이다.

앞서 본 정의를 다시 본다. `n + 0`은 정의에 의해 즉시 `n`이다. 따라서 이 정리는 사실 귀납법 없이 `rfl` 한 줄로도 닫을 수 있다. 그러나 본 절에서는 `0 + n = n`과 같은 모양의 귀납 증명을 일부러 시도해 본다. 같은 패턴을 한 번 더 손에 익히기 위해서이다.

```lean
import Mathlib

theorem add_zero_nat (n : Nat) : n + 0 = n := by
  induction n with
  | zero =>
    -- InfoView 목표:  ⊢ 0 + 0 = 0
    rfl
  | succ k ih =>
    -- InfoView 가정:  k : Nat,  ih : k + 0 = k
    -- InfoView 목표:  ⊢ (k + 1) + 0 = k + 1
    rw [Nat.succ_add]
    -- 위 rw로 목표가 다음과 같이 바뀐다.
    -- InfoView 목표:  ⊢ (k + 0) + 1 = k + 1
    rw [ih]
    -- 위 rw로 (k + 0)이 k로 치환되어 목표가 다음과 같이 된다.
    -- InfoView 목표:  ⊢ k + 1 = k + 1
    -- 자동으로 닫힌다.
```

이번에 새로 등장한 보조 정리는 `Nat.succ_add`이다. 진술은 다음과 같다.

```
Nat.succ_add : ∀ (n m : Nat), (n + 1) + m = (n + m) + 1
```

`Nat.add_succ`와 비슷하지만 변수의 위치가 다르다는 점에 주의한다. `Nat.add_succ`는 **두 번째 인수**의 `+1`을 바깥으로 빼는 정리이고, `Nat.succ_add`는 **첫 번째 인수**의 `+1`을 바깥으로 빼는 정리이다.

두 정리를 한 줄에 정리한다.

| 보조 정리 | 진술 | 어디에 쓰는가 |
|---|---|---|
| `Nat.add_succ` | `n + (m + 1) = (n + m) + 1` | 두 번째 인수의 `+1`을 빼낼 때 |
| `Nat.succ_add` | `(n + 1) + m = (n + m) + 1` | 첫 번째 인수의 `+1`을 빼낼 때 |

이 두 정리는 본 자료에서 자주 등장하므로, 두 이름을 머릿속에 짝지어 두면 좋다.

## 7. 합 공식 (1) - 홀수의 합

§5.1 강의의 시범 예제였다. 진술부터 다시 본다.

**정리** 모든 자연수 `n`에 대해 `1 + 3 + 5 + ... + (2n-1) = n²`이다. 단, 합의 항이 0개일 때(즉 `n = 0`)는 합도 0, 우변도 `0² = 0`이다.

Lean 4에서 "여러 항의 합"은 `Finset`(피니셋, 유한집합)의 합 표기를 쓴다. 홀수의 합은 다음과 같이 쓴다.

```lean
∑ k ∈ Finset.range n, (2 * k + 1)
```

이 식의 뜻을 천천히 풀어 둔다.

`Finset.range n`은 "`0`부터 `n-1`까지의 유한집합", 즉 `{0, 1, 2, ..., n-1}`이다. 원소가 `n`개이다.

`∑ k ∈ Finset.range n, (2 * k + 1)`은 "`k`가 `Finset.range n`의 원소 전부를 한 번씩 돌 때, `2 * k + 1`의 합"이다. `k`가 0, 1, ..., (n-1)을 차례로 대입하면 `2*k + 1`은 1, 3, 5, ..., (2n-1)이 된다. 결국 처음 `n`개의 홀수의 합과 같다.

이제 정리의 Lean 4 진술과 증명이다.

```lean
import Mathlib

open Finset

-- 정리: 처음 n개의 홀수의 합은 n의 제곱이다.
theorem sum_odd_eq_sq (n : Nat) :
    (∑ k ∈ Finset.range n, (2 * k + 1)) = n ^ 2 := by
  induction n with
  | zero =>
    -- 기저 단계.
    -- InfoView 목표:  ⊢ (∑ k ∈ Finset.range 0, (2 * k + 1)) = 0 ^ 2
    -- Finset.range 0은 공집합이므로 합은 0이다. 우변 0^2도 0이다.
    simp
  | succ k ih =>
    -- 귀납 단계.
    -- InfoView 가정:  k : Nat,
    --                 ih : (∑ j ∈ Finset.range k, (2 * j + 1)) = k ^ 2
    -- InfoView 목표:  ⊢ (∑ j ∈ Finset.range (k + 1), (2 * j + 1)) = (k + 1) ^ 2
    rw [Finset.sum_range_succ]
    -- 위 rw로 목표가 다음과 같이 바뀐다.
    -- InfoView 목표:  ⊢ (∑ j ∈ Finset.range k, (2 * j + 1)) + (2 * k + 1) = (k + 1) ^ 2
    rw [ih]
    -- 위 rw로 합 자리에 ih의 우변 k^2이 들어가서 목표가 다음과 같이 된다.
    -- InfoView 목표:  ⊢ k ^ 2 + (2 * k + 1) = (k + 1) ^ 2
    ring
```

세 가지 새 요소가 등장하였다. 하나씩 풀어 본다.

**`open Finset`** 한 줄. 이 한 줄을 두면 `Finset.range`나 `Finset.sum_range_succ` 같은 이름들을 매번 `Finset.`이라는 접두어 없이 짧게 쓸 수 있게 된다. 본 자료에서는 가독성을 위해 그래도 정리 이름은 `Finset.`을 붙여 적었다.

**`simp` 전술** 기저 단계에 등장하였다. 본 자료 §2에서 "자동화 전술은 가급적 쓰지 않는다"고 말해 두었는데, 여기서 한 가지 예외를 둔다. 빈 합(즉 `Finset.range 0`에서의 합)이 0과 같다는 사실은 사실 Mathlib에 있는 보조 정리 `Finset.sum_range_zero`로 직접 처리할 수 있다. 그러나 빈 합 처리는 너무 빈번해서 `simp`이 자동으로 처리해 주도록 두는 편이 코드가 깔끔해진다. 학습자는 `simp`을 "공집합 합 같은 사소한 정의 풀이를 한 방에 처리해 주는 도구"로만 받아들이면 충분하다.

**`Finset.sum_range_succ`** 보조 정리. 이 정리가 본 절의 핵심 도구이다. 진술은 다음과 같다.

```
Finset.sum_range_succ :
  ∀ (f : Nat → α) (n : Nat),
    (∑ k ∈ Finset.range (n + 1), f k) = (∑ k ∈ Finset.range n, f k) + f n
```

말로 풀어 쓰면 "0부터 n까지의 합은, 0부터 n-1까지의 합에 마지막 항 `f n`을 더한 것"이다. 종이 증명에서 "1+3+5+...+(2k+1) = (1+3+5+...+(2k-1)) + (2k+1)" 라고 마지막 항을 분리하던 그 한 단계가, Lean 4에서는 `Finset.sum_range_succ` 한 줄로 표현된다.

**`ring` 전술** 귀납 단계의 마지막 줄이다. `ring`은 "이 등식이 다항식 항등식으로서 성립함을 자동으로 검증해 달라"는 전술이다. 마지막에 남은 등식 `k^2 + (2k+1) = (k+1)^2`은 단순한 완전제곱식이다. 손으로도 펼칠 수 있지만, 이런 단순 대수 정리는 `ring`이 자동으로 검증해 준다.

여기서 종이 증명과 Lean 4 코드의 두 번째 정확한 대응이 나타난다.

| 종이 증명 단계 | Lean 4 한 줄 |
|---|---|
| 기저 P(0): 빈 합은 0, 우변도 0 | `simp` |
| "1+3+...+(2k+1) = (1+3+...+(2k-1)) + (2k+1)" | `rw [Finset.sum_range_succ]` |
| "귀납 가설로 앞 부분을 k²으로 치환" | `rw [ih]` |
| "k² + (2k+1) = (k+1)²은 완전제곱" | `ring` |

종이의 네 단계가 코드의 네 줄과 정확히 한 줄씩 짝을 이룬다. 본 자료 §5에서 약속한 "한 줄씩 대응"이 합 공식에서도 그대로 작동한다는 것을 본다.

## 8. 합 공식 (2) - 가우스의 합

이번에는 가우스의 합이다.

**정리** 모든 자연수 `n`에 대해 `0 + 1 + 2 + ... + n = n(n+1)/2`이다.

이 정리를 Lean 4로 옮길 때 한 가지 문제가 있다. `n(n+1)/2`의 나눗셈 `/2` 때문이다. Lean 4의 `Nat` 위에서 `/`는 **정수 나눗셈**(integer division)이다. 항상 깔끔하게 나눠떨어지지는 않으므로, 다루기가 까다롭다.

해법은 단순하다. **양변에 2를 곱한 형태로 진술하면** 나눗셈을 피할 수 있다. 즉 다음 형태로 옮긴다.

**진술(Lean 4판)** 모든 자연수 `n`에 대해 `2 * (0 + 1 + 2 + ... + n) = n * (n + 1)`이다.

수학적으로는 같은 정리이다. 표현만 자연수 친화적으로 바꾼 것이다. 도구에 맞게 옷을 갈아입힌 셈이다.

이제 코드를 본다.

```lean
import Mathlib

open Finset

-- 정리: 0부터 n까지의 합에 2를 곱하면 n(n+1)과 같다.
theorem two_mul_sum_range (n : Nat) :
    2 * (∑ k ∈ Finset.range (n + 1), k) = n * (n + 1) := by
  induction n with
  | zero =>
    -- 기저 단계.
    -- InfoView 목표:  ⊢ 2 * (∑ k ∈ Finset.range 1, k) = 0 * (0 + 1)
    -- Finset.range 1 = {0}이므로 합은 0이다. 우변도 0이다.
    simp
  | succ k ih =>
    -- 귀납 단계.
    -- InfoView 가정:  k : Nat,
    --                 ih : 2 * (∑ j ∈ Finset.range (k + 1), j) = k * (k + 1)
    -- InfoView 목표:  ⊢ 2 * (∑ j ∈ Finset.range (k + 2), j) = (k + 1) * (k + 1 + 1)
    rw [Finset.sum_range_succ]
    -- 위 rw로 목표가 다음과 같이 바뀐다.
    -- InfoView 목표:
    --   ⊢ 2 * ((∑ j ∈ Finset.range (k + 1), j) + (k + 1)) = (k + 1) * (k + 1 + 1)
    -- 분배 법칙으로 2 * (... + (k+1)) = 2 * (...) + 2 * (k+1) 이며,
    -- 앞부분 2 * (...) 자리에 ih의 우변 k*(k+1)을 넣을 수 있다.
    -- 이 모든 정리를 ring이 자동으로 처리해 준다. 단, ih를 어딘가에서 써야 한다.
    have h := ih
    -- 위 have로 h라는 이름으로 ih의 등식을 한 번 꺼내 놓는다.
    -- InfoView 가정:  ..., ih : ..., h : 2 * (∑ j ∈ Finset.range (k + 1), j) = k * (k + 1)
    linarith [h]
```

여기서 새 요소가 두 개 등장한다.

**`have h := ih`** 한 줄. `have`는 "보조 사실 하나를 도입한다"는 전술이다. `have <이름> := <항>`의 형태이다. 이 줄에서는 `ih`라는 가정의 내용을 `h`라는 새 이름으로 손에 한 번 더 꺼내 놓는다.

왜 이 동작이 필요한가? 곧 이어 호출할 `linarith`이 "현재 가정 목록에서 산술 등식·부등식을 모아 자동으로 추론"하는 전술인데, `ih`라는 이름의 가정도 자동으로 같이 살펴 주기는 한다. 그러나 본 자료에서는 "어떤 가정을 쓰고 있는지 코드에 명시적으로 남겨 두는" 습관을 들이기 위해 `have h := ih`로 한 번 더 꺼내 놓고, `linarith [h]`라고 명시한다. 이 한 줄이 "여기서 귀납 가설을 사용했습니다"의 손가락 짚기이다.

**`linarith` 전술** 본 자료 §2에서 "자동화 전술 사용은 가급적 피한다"고 했는데 여기서 한 번 등장한다. `linarith`은 "선형 산술 부등식·등식의 자동 증명"을 담당한다. 우리가 처한 상황은 다음과 같다.

- 손에 든 등식: `2 * (sum_part) = k * (k + 1)` (이름 `h`)
- 보이고 싶은 등식: `2 * (sum_part + (k + 1)) = (k + 1) * (k + 2)`

좌변을 분배 법칙으로 펼치면 `2 * sum_part + 2 * (k + 1)`이고, `h`에 의해 `2 * sum_part = k * (k + 1)`이다. 그러므로 좌변은 `k * (k + 1) + 2 * (k + 1) = (k + 1)(k + 2)`. 이것은 일종의 선형 산술 결합이다. `linarith [h]`이 이 모두를 자동으로 결합해 준다.

만약 더 명시적으로 손으로 펼치고 싶다면 다음과 같이도 쓸 수 있다.

```lean
  | succ k ih =>
    rw [Finset.sum_range_succ]
    rw [Nat.mul_add]   -- 2 * (sum + (k+1)) = 2 * sum + 2 * (k+1)
    rw [ih]            -- 2 * sum 자리에 k * (k+1)이 들어감
    ring               -- k * (k+1) + 2 * (k+1) = (k+1) * (k+2) 검증
```

두 형태 중 어느 쪽을 쓸지는 학습자의 취향이다. 본 자료에서는 위쪽 `linarith` 버전을 기본으로 한다.

마지막으로 §7과 동일한 표를 가우스 합에 대해서도 작성해 둔다.

| 종이 증명 단계 | Lean 4 한 줄 |
|---|---|
| 기저 P(0): 빈 합 또는 단항 합은 0, 우변도 0 | `simp` |
| "0+1+...+(k+1) = (0+1+...+k) + (k+1)" | `rw [Finset.sum_range_succ]` |
| "귀납 가설을 한 번 꺼내고" + "선형 결합" | `have h := ih; linarith [h]` |

## 9. 합 공식 (3) - 제곱의 합

이제 본격적인 합 공식 세 개로 들어간다. 진술부터 다시 본다.

**정리** 모든 자연수 `n`에 대해 `0² + 1² + 2² + ... + n² = n(n+1)(2n+1)/6`이다.

가우스의 합에서 했던 처방과 똑같이, 자연수 나눗셈을 피하기 위해 **양변에 6을 곱한 형태**로 진술한다.

**진술(Lean 4판)** 모든 자연수 `n`에 대해 `6 · (0² + 1² + ... + n²) = n(n+1)(2n+1)`이다.

이제 코드를 본다.

```lean
import Mathlib

open Finset

-- 정리: 0²부터 n²까지의 합에 6을 곱하면 n(n+1)(2n+1)과 같다.
theorem sum_sq (n : Nat) :
    6 * (∑ k ∈ Finset.range (n + 1), k ^ 2) = n * (n + 1) * (2 * n + 1) := by
  induction n with
  | zero =>
    -- 기저 단계.
    -- InfoView 목표:  ⊢ 6 * (∑ k ∈ Finset.range 1, k^2) = 0 * (0 + 1) * (2 * 0 + 1)
    -- Finset.range 1 = {0}, 그 위에서 k^2의 합은 0. 우변도 0. simp이 처리.
    simp
  | succ k ih =>
    -- 귀납 단계.
    -- InfoView 가정:  k : Nat,
    --                 ih : 6 * (∑ j ∈ Finset.range (k + 1), j^2)
    --                        = k * (k + 1) * (2 * k + 1)
    -- InfoView 목표:  ⊢ 6 * (∑ j ∈ Finset.range (k + 2), j^2)
    --                    = (k + 1) * (k + 1 + 1) * (2 * (k + 1) + 1)
    rw [Finset.sum_range_succ]
    -- 위 rw로 좌변 안의 합이 분리되어 목표가 다음과 같이 된다.
    -- InfoView 목표:
    --   ⊢ 6 * ((∑ j ∈ Finset.range (k + 1), j^2) + (k + 1)^2)
    --       = (k + 1) * (k + 2) * (2 * (k + 1) + 1)
    rw [mul_add]
    -- 위 rw로 6을 분배하여 목표가 다음과 같이 된다.
    -- InfoView 목표:
    --   ⊢ 6 * (∑ j ∈ Finset.range (k + 1), j^2) + 6 * (k + 1)^2
    --       = (k + 1) * (k + 2) * (2 * (k + 1) + 1)
    rw [ih]
    -- 위 rw로 좌변의 첫 항(6 * 합)이 ih의 우변으로 치환된다.
    -- InfoView 목표:
    --   ⊢ k * (k + 1) * (2 * k + 1) + 6 * (k + 1)^2
    --       = (k + 1) * (k + 2) * (2 * (k + 1) + 1)
    ring
```

§7·§8에서 익힌 합 공식 패턴 그대로이다. 중요한 차이점은 `rw [ih]` 직전에 **`rw [mul_add]` 한 줄이 끼어든다**는 것이다.

**`mul_add`** 보조 정리. 진술은 다음과 같다.

```
mul_add : ∀ (a b c : α), a * (b + c) = a * b + a * c
```

분배 법칙 그 자체이다. 가우스의 합(§8)에서는 좌변에 `linarith`을 호출하여 분배 처리를 자동으로 맡겼지만, 본 정리에서는 좌변에 `mul_add`로 명시적으로 분배를 풀어 두고, 그 다음 `rw [ih]`로 첫 항을 치환한다. 마지막 다항식 항등식은 `ring`이 닫는다.

> 본 자료에서 권장하는 합 공식 표준 절차는 네 줄 패턴이다.
>
> `rw [Finset.sum_range_succ]` → `rw [mul_add]` → `rw [ih]` → `ring`
>
> 가우스의 합(§8)에서 보았던 `linarith` 버전은 같은 일을 한 줄에 묶는 우회로이다. 본 절부터는 네 줄 표준 형태로 통일한다.

종이 증명과 Lean 4 코드의 대응표를 다시 정리한다.

| 종이 증명 단계 | Lean 4 한 줄 |
|---|---|
| 기저 P(0): 0² = 0, 우변도 0 | `simp` |
| "합 마지막 항(k+1)² 분리" | `rw [Finset.sum_range_succ]` |
| "6을 분배 법칙으로 풀기" | `rw [mul_add]` |
| "귀납 가설로 첫 항 치환" | `rw [ih]` |
| "남은 다항식 등식 검증" | `ring` |

종이의 다섯 단계가 코드의 다섯 줄과 정확히 한 줄씩 짝을 이룬다.

## 10. 합 공식 (4) - 세제곱의 합

**정리** 모든 자연수 `n`에 대해 `0³ + 1³ + ... + n³ = (n(n+1)/2)²`이다.

이번에도 자연수 나눗셈을 피하기 위해 양변에 적절한 상수를 곱한다. 우변에 `/2`가 들어 있고 그 전체가 제곱되어 있으므로, 양변에 `4`(즉 `2²`)를 곱하면 우변이 `(n(n+1))²`가 되어 깔끔해진다.

**진술(Lean 4판)** 모든 자연수 `n`에 대해 `4 · (0³ + 1³ + ... + n³) = (n(n+1))²`이다.

코드는 §9와 같은 구조이다. 상수가 `6`에서 `4`로 바뀌고, 우변의 형태만 다르다.

```lean
import Mathlib

open Finset

-- 정리: 0³부터 n³까지의 합에 4를 곱하면 (n(n+1))²과 같다.
theorem sum_cube (n : Nat) :
    4 * (∑ k ∈ Finset.range (n + 1), k ^ 3) = (n * (n + 1)) ^ 2 := by
  induction n with
  | zero =>
    -- InfoView 목표: ⊢ 4 * (∑ k ∈ Finset.range 1, k^3) = (0 * (0 + 1))^2
    simp
  | succ k ih =>
    -- ih : 4 * (∑ j ∈ Finset.range (k + 1), j^3) = (k * (k + 1))^2
    -- 목표: 4 * (∑ j ∈ Finset.range (k + 2), j^3) = ((k+1) * (k+2))^2
    rw [Finset.sum_range_succ]
    rw [mul_add]
    rw [ih]
    -- 남은 등식: (k*(k+1))^2 + 4*(k+1)^3 = ((k+1)*(k+2))^2
    -- 다항식 항등식. ring이 검증.
    ring
```

§9의 `sum_sq`와 글자 단위로 비교해 보면, 코드 구조가 정확히 같다. 단지 상수와 우변의 다항식만 다르다. **본 자료에서 합 공식의 표준 절차 네 줄은 이렇게 보편적이다.**

남은 다항식 등식 `(k(k+1))² + 4(k+1)³ = ((k+1)(k+2))²`이 정말 항등식인지 한번 펼쳐 본다.

```
좌변 = k²(k+1)² + 4(k+1)³
     = (k+1)² [k² + 4(k+1)]
     = (k+1)² (k² + 4k + 4)
     = (k+1)² (k + 2)²
     = ((k+1)(k+2))²
     = 우변.
```

`ring`이 이 정리를 자동으로 처리한다.

## 11. 합 공식 (5) - 등비급수

**정리** `r ≠ 1`인 실수 `r`과 모든 자연수 `n`에 대해

```
1 + r + r² + ... + rⁿ = (rⁿ⁺¹ - 1) / (r - 1)
```

이 정리는 자연수가 아닌 **실수** `Real` 위에서 작동한다. `r - 1 ≠ 0`이라는 가정이 핵심이며, 우변이 분수이므로 나눗셈을 자유롭게 다룰 수 있는 환경이 필요하다.

```lean
import Mathlib

open Finset

-- 정리: r ≠ 1일 때, 1 + r + ... + rⁿ = (r^(n+1) - 1) / (r - 1).
theorem geom_sum (r : Real) (hr : r ≠ 1) (n : Nat) :
    (∑ k ∈ Finset.range (n + 1), r ^ k) = (r ^ (n + 1) - 1) / (r - 1) := by
  -- 분모가 0이 아니라는 사실을 먼저 손에 쥔다.
  have hrm1 : r - 1 ≠ 0 := sub_ne_zero.mpr hr
  induction n with
  | zero =>
    -- 기저 단계.
    -- InfoView 목표:  ⊢ (∑ k ∈ Finset.range 1, r^k) = (r^1 - 1) / (r - 1)
    -- 좌변: r^0 = 1. 우변: (r - 1) / (r - 1) = 1.
    simp
    field_simp
  | succ k ih =>
    -- ih : (∑ j ∈ Finset.range (k + 1), r^j) = (r^(k+1) - 1) / (r - 1)
    -- 목표: (∑ j ∈ Finset.range (k + 2), r^j) = (r^(k+2) - 1) / (r - 1)
    rw [Finset.sum_range_succ]
    -- InfoView 목표:
    --   ⊢ (∑ j ∈ Finset.range (k + 1), r^j) + r^(k+1) = (r^(k+2) - 1) / (r - 1)
    rw [ih]
    -- InfoView 목표:
    --   ⊢ (r^(k+1) - 1) / (r - 1) + r^(k+1) = (r^(k+2) - 1) / (r - 1)
    -- 양변에 분모 (r - 1)이 들어 있는 등식이다. field_simp이 분모를 곱해 없애 준다.
    field_simp
    -- InfoView 목표 (분모가 사라진 형태):
    --   ⊢ (r^(k+1) - 1) + r^(k+1) * (r - 1) = r^(k+2) - 1
    -- 이는 순수한 다항식 등식. ring이 검증한다.
    ring
```

세 가지 새 요소가 등장하였다.

**`sub_ne_zero.mpr`** 보조 정리. 진술은 다음과 같다.

```
sub_ne_zero : ∀ {α : Type*} [inst : SubtractionMonoid α] {a b : α},
              a - b ≠ 0 ↔ a ≠ b
```

`↔`(쌍방향 함의)는 두 명제가 서로 동치임을 말한다. 그 안에는 두 방향의 함의가 들어 있는데, `.mpr`(modus ponens reverse)이 "오른쪽에서 왼쪽으로"의 방향을 가리킨다. 우리는 가정 `hr : r ≠ 1` (즉 `a ≠ b` 형태, `a = r`, `b = 1`)로부터 결론 `r - 1 ≠ 0` (즉 `a - b ≠ 0` 형태)을 얻고 싶다. 그러므로 `.mpr`이다.

`.mp` (modus ponens, 정방향)와 `.mpr` (역방향)는 Mathlib에서 자주 등장하는 표기이므로 기억해 두면 좋다.

**`field_simp`** 전술. 분수가 들어간 등식·부등식에서 분모를 곱해 없애는 전술이다. 분모가 0이 아니라는 사실들(`hrm1 : r - 1 ≠ 0` 등)이 가정 목록에 있어야 작동한다. 본 자료에서는 분수가 등장하는 등비급수와 같은 환경에서만 쓴다.

> `field_simp`은 자동화 전술이지만, 분수 처리에는 사실상 표준 도구이다. 본 자료의 자동화 최소화 원칙에서 한 가지 더 양보한 부분이다.

**`ring`** 전술. 분모가 사라진 후의 다항식 등식을 자동 검증한다. 이전 합 공식들과 같은 역할이다.

종이 증명과 Lean 4 코드의 대응표.

| 종이 증명 단계 | Lean 4 한 줄 |
|---|---|
| "분모 r-1이 0이 아님 명시" | `have hrm1 : r - 1 ≠ 0 := sub_ne_zero.mpr hr` |
| 기저 P(0): r⁰ = 1 = (r-1)/(r-1) | `simp; field_simp` |
| "합의 마지막 항 r^(k+1) 분리" | `rw [Finset.sum_range_succ]` |
| "귀납 가설로 앞 부분 치환" | `rw [ih]` |
| "양변에 분모 곱해 없앰" | `field_simp` |
| "남은 다항식 등식 검증" | `ring` |

## 12. 부등식 (1) - `n < 2ⁿ` (`n ≥ 1`)

이번에는 부등식이다. 가장 단순한 형태부터 들어간다.

**정리** 모든 자연수 `n ≥ 1`에 대해 `n < 2ⁿ`이다.

이 정리는 `n = 0`에서는 성립하지 않는다(`0 < 2⁰ = 1`이므로 `0 < 1`은 참이긴 하지만, 종종 의미상 1부터 다루는 형태가 더 자연스럽다). 본 자료에서는 강의 진술에 맞추어 `1 ≤ n`이라는 가정을 명시적으로 받는다.

기저가 `0`이 아니라 `1`이라는 점이 새로운 도전이다. 지금까지 본 `induction n with | zero => ... | succ k ih => ...` 형태는 항상 `0`에서 시작한다. 시작점을 옮기려면 다른 도구가 필요하다. 그 이름이 `Nat.le_induction`이다.

`Nat.le_induction`은 다음과 같이 말한다.

> `n₀`에서 시작하는 술어 `P`에 대해, `P n₀`이 참이고, 또한 임의의 `k ≥ n₀`에 대해 `P k`이면 `P (k+1)`도 참이라면, 모든 `n ≥ n₀`에 대해 `P n`이 참이다.

`induction n, hn using Nat.le_induction with` 형태로 호출한다. `hn`은 "`n ≥ n₀`이라는 가정"을 가리킨다. 두 갈래가 펼쳐진다.

- `| base =>` 갈래: 목표는 `P n₀`이다. 즉 기저 단계이다.
- `| succ k hk ih =>` 갈래: `hk`는 "`k ≥ n₀`이라는 가정"이고, `ih`는 귀납 가설 `P k`이다. 목표는 `P (k+1)`이다.

이제 코드를 본다.

```lean
import Mathlib

-- 정리: n ≥ 1인 모든 자연수 n에 대해 n < 2^n이다.
theorem n_lt_two_pow (n : Nat) (hn : 1 ≤ n) : n < 2 ^ n := by
  induction n, hn using Nat.le_induction with
  | base =>
    -- 기저 단계.
    -- InfoView 목표:  ⊢ 1 < 2 ^ 1
    -- 2^1 = 2 이므로 1 < 2. 작은 수의 직접 계산이므로 decide로 처리한다.
    decide
  | succ k hk ih =>
    -- 귀납 단계.
    -- InfoView 가정:  k : Nat,  hk : 1 ≤ k,  ih : k < 2 ^ k
    -- InfoView 목표:  ⊢ k + 1 < 2 ^ (k + 1)
    -- 핵심 아이디어:
    --   k + 1 ≤ 2 * k        (k ≥ 1 이므로 k + 1 ≤ k + k = 2k)
    --        < 2 * 2 ^ k     (ih에 의해 k < 2^k 이고, 2 > 0이므로 양변에 2를 곱하면 부등식 유지)
    --        = 2 ^ (k + 1)   (지수 법칙)
    have h1 : k + 1 ≤ 2 * k := by omega
    have h2 : 2 * k < 2 * 2 ^ k := by linarith [ih]
    calc k + 1 ≤ 2 * k       := h1
      _        < 2 * 2 ^ k   := h2
      _        = 2 ^ (k + 1) := by rw [pow_succ]; ring
```

새 요소가 세 개 등장하였다. 차근차근 풀어 본다.

**`decide` 전술** 기저 단계에 등장하였다. `decide`는 "이 명제는 유한 시간에 직접 계산해서 참거짓을 판정할 수 있다"고 선언하는 전술이다. `1 < 2 ^ 1`은 계산하면 `1 < 2`이고, 이는 명확히 참이다. 컴퓨터가 직접 계산해서 즉결한다.

> 본 자료 §2에서 "자동화 전술은 가급적 쓰지 않는다"고 했는데, `decide`는 한 가지 예외이다. 이유는 `decide`가 "복잡한 추론"이 아니라 "단순한 계산"이기 때문이다. 작은 수에 대한 사실은 계산으로 확인하는 편이 가장 명료하다.

**`omega` 전술** `have h1 : k + 1 ≤ 2 * k := by omega` 줄에 등장하였다. `omega`는 자연수·정수에 대한 선형 산술 자동 결정 전술이다. 우리가 가진 가정 `hk : 1 ≤ k`와 목표 `k + 1 ≤ 2 * k`는 모두 선형 산술 사실이다. 사람이 풀면 "`hk`에서 `k ≥ 1`, 따라서 `2k = k + k ≥ k + 1`"인데, `omega`가 이를 자동으로 검증해 준다.

> `omega`는 본 강의의 자동화 정책에서 공식 허용 도구이다. 자연수·정수의 선형 산술이 등장할 때마다 등장한다.

**`calc` 블록** 부등식 사슬을 시각적으로 한 줄씩 보여 주는 도구이다. `calc` 다음에 시작 식을 적고, 그 아래 줄들에 `_  <기호> <다음 식>  := <이유>` 형태로 한 줄씩 이어 간다. 위 코드에서 우리는 `k + 1`에서 시작해서 `≤ 2 * k`, `< 2 * 2 ^ k`, `= 2 ^ (k + 1)` 세 단계를 거쳐 결론에 도달한다. 종이에 부등식 사슬을 적을 때와 정확히 같은 구조이다.

마지막 줄 `_ = 2 ^ (k + 1) := by rw [pow_succ]; ring`을 풀어 본다. 이 줄에서 우리는 `2 * 2^k = 2^(k+1)`임을 보여야 한다. 보조 정리 `pow_succ`의 진술은 다음과 같다.

```
pow_succ : ∀ (a : α) (n : Nat), a ^ (n + 1) = a ^ n * a
```

이를 적용하면 목표의 우변 `2 ^ (k + 1)`이 `2 ^ k * 2`로 바뀐다. 그러면 남는 등식은 `2 * 2^k = 2^k * 2`이고, 이는 곱셈의 교환으로 즉시 참이다. `ring`이 자동으로 처리한다.

부등식의 종이 증명과 Lean 4 코드의 대응을 표로 정리한다.

| 종이 증명 단계 | Lean 4 한 줄 |
|---|---|
| 기저 P(1): 1 < 2 직접 계산 | `decide` |
| "k ≥ 1이므로 k+1 ≤ 2k" | `have h1 ... := by omega` |
| "ih의 k < 2^k 양변에 2를 곱해 2k < 2·2^k" | `have h2 ... := by linarith [ih]` |
| "2 · 2^k = 2^(k+1)" | `_ = 2^(k+1) := by rw [pow_succ]; ring` |
| 세 부등식을 사슬로 잇기 | `calc` 블록 |

## 13. 부등식 (2) - `2ⁿ < n!` (`n ≥ 4`)

이번에는 시작점이 `4`인 부등식이다. 기저점만 다르고 골격은 §12와 같다.

**정리** 모든 자연수 `n ≥ 4`에 대해 `2ⁿ < n!`이다.

기저 단계는 `n = 4`일 때 `2⁴ = 16 < 24 = 4!`을 확인한다. 귀납 단계는 핵심 부등식 사슬 `2^(k+1) = 2 · 2^k < 2 · k! ≤ (k+1) · k! = (k+1)!`을 잇는 것이다.

```lean
import Mathlib

-- 정리: n ≥ 4인 모든 자연수 n에 대해 2^n < n!이다.
theorem pow_two_lt_fac (n : Nat) (hn : 4 ≤ n) : 2 ^ n < n.factorial := by
  induction n, hn using Nat.le_induction with
  | base =>
    -- 기저 단계.
    -- InfoView 목표:  ⊢ 2 ^ 4 < Nat.factorial 4
    -- 2^4 = 16, 4! = 24. 16 < 24. 직접 계산.
    decide
  | succ k hk ih =>
    -- 귀납 단계.
    -- InfoView 가정:  k : Nat,  hk : 4 ≤ k,  ih : 2^k < k.factorial
    -- InfoView 목표:  ⊢ 2 ^ (k + 1) < (k + 1).factorial
    -- 핵심 사슬:
    --   2^(k+1) = 2 · 2^k < 2 · k! ≤ (k+1) · k! = (k+1)!
    have h1 : 2 ^ (k + 1) = 2 * 2 ^ k := by
      rw [pow_succ]
      ring
    have h2 : (2 : Nat) * 2 ^ k < 2 * k.factorial := by
      -- ih에 의해 2^k < k.factorial. 양변에 2(양수)를 곱하면 부등식 유지.
      have := ih
      nlinarith
    have h3 : 2 * k.factorial ≤ (k + 1) * k.factorial := by
      -- k ≥ 4이므로 k + 1 ≥ 5 ≥ 2. 따라서 2 ≤ k + 1.
      have hk1 : 2 ≤ k + 1 := by omega
      exact Nat.mul_le_mul_right _ hk1
    have h4 : (k + 1) * k.factorial = (k + 1).factorial := by
      rw [Nat.factorial_succ]
    -- 네 보조 사실을 합치면 결론이 나온다. omega가 선형 결합으로 닫는다.
    omega
```

다섯 줄에 다섯 개의 정리를 인용한다.

**`pow_succ`**. `a^(n+1) = a^n * a`. 이미 §12에서 보았다.

**`nlinarith`**. **비선형** 산술 자동화이다. `linarith`이 선형 결합만 다룬다면, `nlinarith`은 곱셈을 포함한 비선형 결합을 시도한다. 본 자료에서는 양수의 곱셈으로 부등식이 보존되는 단계에서 한 번 등장한다.

> `nlinarith`도 자동화 전술이다. 본 자료의 원칙은 "쓸 수 있으면 `omega`나 `linarith`을, 그것으로 안 될 때만 `nlinarith`을"이다. 자동화의 강도 순서로는 `decide` < `omega` < `linarith` < `nlinarith` 정도이다.

**`Nat.mul_le_mul_right`**. 한쪽이 고정되고 다른 쪽이 ≤ 관계일 때 곱셈으로 ≤가 유지됨을 말한다. 진술은 다음과 같다.

```
Nat.mul_le_mul_right : ∀ (k : Nat) {m n : Nat}, m ≤ n → m * k ≤ n * k
```

말로 풀면 "`m ≤ n`이면 양변에 같은 `k`를 곱해도 부등식이 유지된다"이다. 우리 코드에서는 `2 ≤ k + 1`이라는 부등식의 양변에 `k.factorial`을 곱하기 위해 사용한다.

**`Nat.factorial_succ`**. 진술은 다음과 같다.

```
Nat.factorial_succ : ∀ (n : Nat), (n + 1).factorial = (n + 1) * n.factorial
```

이것이 계승의 정의 그 자체이다. 우리는 마지막 단계에서 `(k+1) * k! = (k+1)!`을 보이기 위해 이 정리를 적용한다.

**`omega`**. 마지막 한 줄. 네 개의 보조 사실(`h1`, `h2`, `h3`, `h4`)이 가정에 모여 있고, 이들을 선형 결합하면 결론 `2^(k+1) < (k+1)!`이 나온다.

이 정리를 통과시키는 골격은 §12의 `n < 2ⁿ`과 매우 비슷하다. 차이는 **기저점이 1이 아니라 4**이고, **사슬에 등호 단계(`Nat.factorial_succ`)가 추가**된다는 점뿐이다.

## 14. 부등식 (3) - 베르누이 부등식

§5.1 강의의 절정 중 하나였다.

**정리(베르누이 부등식)** 실수 `x ≥ -1`과 모든 자연수 `n`에 대해 `(1 + x)ⁿ ≥ 1 + nx`이다.

이 정리는 자연수가 아닌 **실수** `Real` 위에서 작동한다. 자연수 `n`이 곱셈에 등장하지만, 식 전체는 실수의 환경에 있다. 자연수에서 실수로 변환되는 지점을 다루는 새 도구 `push_cast`가 등장한다.

```lean
import Mathlib

-- 정리(베르누이): x ≥ -1인 실수 x와 자연수 n에 대해 (1 + x)^n ≥ 1 + n*x.
theorem bernoulli (x : Real) (hx : -1 ≤ x) (n : Nat) :
    (1 + x) ^ n ≥ 1 + n * x := by
  induction n with
  | zero =>
    -- 기저 단계.
    -- InfoView 목표:  ⊢ (1 + x) ^ 0 ≥ 1 + ↑0 * x
    -- 좌변: (1+x)^0 = 1. 우변: 1 + 0*x = 1. 양변이 1로 같음. simp이 처리.
    simp
  | succ k ih =>
    -- 귀납 단계.
    -- InfoView 가정:  k : Nat,
    --                 ih : (1 + x) ^ k ≥ 1 + ↑k * x
    -- InfoView 목표:  ⊢ (1 + x) ^ (k + 1) ≥ 1 + ↑(k + 1) * x
    -- 핵심: (1+x)^(k+1) = (1+x)^k * (1+x) ≥ (1 + kx)(1+x) = 1 + (k+1)x + k·x²
    --        그리고 k·x² ≥ 0이므로 위는 ≥ 1 + (k+1)x.
    -- 사전 준비 두 가지를 먼저 손에 쥔다.
    have h1x : 0 ≤ 1 + x := by linarith
    have hkx_sq : 0 ≤ (k : Real) * x ^ 2 := by
      apply mul_nonneg
      · positivity
      · exact sq_nonneg x
    -- 지수 법칙으로 좌변을 분리한다.
    rw [pow_succ]
    -- 자연수 캐스팅(↑)을 실수의 연산으로 푼다.
    push_cast
    -- 이제 식 전체가 자연스러운 실수의 표현이다. calc 블록으로 사슬을 잇는다.
    calc (1 + x) ^ k * (1 + x)
        _ ≥ (1 + k * x) * (1 + x)     := by gcongr
        _ = 1 + (k + 1) * x + k * x ^ 2 := by ring
        _ ≥ 1 + (k + 1) * x             := by linarith
```

새 요소가 여섯 개 등장하였다. 차근차근 풀어 본다.

**`linarith`**. 선형 산술 자동화. `hx : -1 ≤ x`로부터 `0 ≤ 1 + x`를 즉시 얻는다.

**`positivity`**. 양수성(0보다 큼 또는 0보다 작지 않음)을 자동 판정하는 전술. 자연수의 캐스팅 `(k : Real)`이 항상 `0` 이상이라는 사실을 `positivity`가 즉시 처리해 준다.

**`sq_nonneg`**. 진술은 다음과 같다.

```
sq_nonneg : ∀ (a : α), 0 ≤ a ^ 2
```

"임의의 수의 제곱은 0 이상"이라는 가장 기본적인 부등식이다.

**`mul_nonneg`**. 두 음이 아닌 수의 곱이 음이 아니라는 정리. `0 ≤ a → 0 ≤ b → 0 ≤ a * b`.

**`push_cast`**. 자연수 캐스팅 `↑`을 실수의 표현 안으로 밀어 넣는 전술이다. 무슨 말인가? 우리 진술의 우변에 `1 + n * x`라는 식이 있는데, 여기서 `n`은 자연수 `Nat`이고 `x`는 실수 `Real`이다. 둘이 곱해지려면 `n`을 실수로 변환(캐스팅)해야 한다. Lean 4는 이를 `↑n` 또는 `(n : Real)`로 표시한다.

`succ` 갈래에 들어왔을 때 자연수 `n`이 `k + 1`로 바뀌면, 캐스팅 표현은 `↑(k + 1)`이 된다. 이 형태에서는 `k`와 `1` 각각에 대해 따로 다룰 수가 없다. `push_cast`이 `↑(k + 1) = ↑k + 1`로 풀어서, 식 전체가 실수의 자연스러운 표현 `1 + (↑k + 1) * x`로 변신한다.

**`gcongr`** ("generalized congruence", 일반화된 동치 변환) 전술. 부등식의 한쪽 변에서 비슷한 구조의 항을 다른 부등식으로 교체할 때 사용한다.

우리 `calc`의 첫 줄에서 좌변은 `(1 + x)^k * (1 + x)`이다. 이를 `(1 + k * x) * (1 + x)`로 부등식 `≥`로 잇고 싶다. 변화한 곳은 첫 인수 `(1 + x)^k`에서 `1 + k * x`로의 변환뿐이고, 둘째 인수 `(1 + x)`는 그대로이다. 이 한쪽만의 부등식 변환을 `gcongr`이 자동으로 찾아 준다. `gcongr`은 가정 목록에서 필요한 부등식(여기서는 `ih : (1+x)^k ≥ 1 + k*x`)과 비음수성(여기서는 `h1x : 0 ≤ 1 + x`)을 자동으로 골라 결합한다.

이 정리는 본 자료에서 가장 복잡한 코드이다. 각 줄이 어떤 일을 하는지 표로 다시 정리한다.

| 줄 | 액션 |
|---|---|
| `have h1x : 0 ≤ 1 + x := by linarith` | `hx`에서 비음수성 추출 |
| `have hkx_sq : 0 ≤ k * x^2 := ...` | 마지막 `linarith` 호출을 위한 비음수성 비축 |
| `rw [pow_succ]` | `(1+x)^(k+1) = (1+x)^k * (1+x)` |
| `push_cast` | 자연수 캐스팅을 실수 표현으로 정리 |
| `calc (1+x)^k * (1+x) ≥ (1+kx)(1+x)` | IH로 첫 인수 교체 (`gcongr`) |
| `_ = 1 + (k+1)x + k·x²` | 다항식 전개 (`ring`) |
| `_ ≥ 1 + (k+1)x` | `k·x² ≥ 0`으로 항 삭제 (`linarith`) |

마지막 줄에서 `linarith`은 가정 목록에 있는 `hkx_sq : 0 ≤ k * x^2`를 자동으로 살펴 결론을 도출한다. 우리가 두 줄 위에서 `hkx_sq`를 미리 비축한 이유가 바로 이것이다.

## 15. 가분성 (1) - `3 ∣ (n³ + 2n)` (자연수)

이제 **가분성**(divisibility) 정리로 넘어간다. 가분성이란 "어떤 수가 다른 수로 나누어떨어진다"는 관계이다. Lean 4에서 "`a`가 `b`를 나눈다"는 명제는 `a ∣ b`(특수 기호 ∣, 단순 막대기 `|`가 아님)로 쓴다.

**정리** 모든 자연수 `n`에 대해 `3 ∣ (n³ + 2n)`이다.

본래 §5.1 강의의 진술은 "`3 | (n³ - n)`"이었다. 그러나 자연수 `Nat`에서는 뺄셈이 위험하다. `a - b`에서 `a < b`이면 결과가 0으로 잘려 버린다. 그러므로 `(n³ - n)`의 뺄셈이 들어간 형태는 자연수 위에서 다루기에 까다롭다. 그래서 **등가 형태**인 `(n³ + 2n)`을 자연수 친화 버전으로 다룬다.

왜 이 둘이 같은가? `n³ - n`과 `n³ + 2n`의 차이는 `3n`이고, `3n`은 자명하게 3의 배수이다. 따라서 "`3 | (n³ - n)`"과 "`3 | (n³ + 2n)`"은 서로 같은 명제이다. 같은 정리가 옷만 갈아입은 셈이다.

이제 코드를 본다.

```lean
import Mathlib

-- 정리: 3이 n³ + 2n을 나눈다 (모든 자연수 n에 대해).
theorem three_dvd_n3_add_2n (n : Nat) : 3 ∣ (n ^ 3 + 2 * n) := by
  induction n with
  | zero =>
    -- 기저 단계.
    -- InfoView 목표:  ⊢ 3 ∣ (0 ^ 3 + 2 * 0)
    -- 우변은 0이고, 3 ∣ 0은 참이다 (0은 모든 수의 배수).
    decide
  | succ k ih =>
    -- 귀납 단계.
    -- InfoView 가정:  k : Nat,  ih : 3 ∣ (k ^ 3 + 2 * k)
    -- InfoView 목표:  ⊢ 3 ∣ ((k + 1) ^ 3 + 2 * (k + 1))
    -- 핵심: (k+1)³ + 2(k+1) = (k³ + 2k) + 3(k² + k + 1)
    -- 즉 "ih가 책임지는 조각" + "명백한 3의 배수 조각"으로 분해한다.
    have key : (k + 1) ^ 3 + 2 * (k + 1) = (k ^ 3 + 2 * k) + 3 * (k ^ 2 + k + 1) := by
      ring
    rw [key]
    -- 위 rw로 목표가 다음과 같이 바뀐다.
    -- InfoView 목표:  ⊢ 3 ∣ ((k ^ 3 + 2 * k) + 3 * (k ^ 2 + k + 1))
    -- 첫 항은 ih가 보장하는 3의 배수, 둘째 항은 명백한 3의 배수.
    exact Nat.dvd_add ih (Dvd.intro (k ^ 2 + k + 1) rfl)
```

새 요소가 네 개 등장하였다. 한꺼번에 풀어 본다.

**가분성 기호 `∣`** 단순 막대기 `|`(파이프)와 모양은 비슷하지만 다른 기호이다. Lean 4에서 `\|` 또는 `\dvd`(엔터)로 입력한다. `3 ∣ n`은 "3이 n을 나눈다"는 명제이다. 본 자료에서는 일관되게 `∣`(특수 기호)를 쓴다.

**`have key : ... := by ring` 패턴** 보조 사실을 도입할 때 자주 쓰는 패턴이다. 위 코드에서 우리는 다음 다항식 항등식이 필요하다.

```
(k + 1) ^ 3 + 2 * (k + 1) = (k ^ 3 + 2 * k) + 3 * (k ^ 2 + k + 1)
```

이는 단순히 좌변을 전개해서 정리하면 우변이 됨을 확인할 수 있는, 순수한 다항식 등식이다. `ring`이 자동으로 검증해 준다. `have key : ... := by ring` 한 줄로 이 등식을 `key`라는 이름으로 손에 쥔다.

**`rw [key]`** 그렇게 얻은 `key`를 좌변에서 우변 방향으로 적용한다. 목표가 다시 쓰여서, 우리가 다루고 싶은 "두 조각의 합" 형태로 바뀐다.

**`Nat.dvd_add`** Mathlib의 핵심 보조 정리 중 하나이다. 진술은 다음과 같다.

```
Nat.dvd_add : ∀ {k m n : Nat}, k ∣ m → k ∣ n → k ∣ (m + n)
```

말로 풀면 "같은 `k`로 나누어떨어지는 두 수 `m`, `n`의 합도 `k`로 나누어떨어진다"이다. 이것이 우리가 분해해서 얻은 두 조각을 결합하는 마지막 한 줄이다.

`Nat.dvd_add`는 두 개의 가분성 증명을 인수로 받는다. 첫째 인수는 `ih`(이미 손에 있는 가정: `3 ∣ (k³ + 2k)`)이고, 둘째 인수는 `3 ∣ 3 * (k² + k + 1)`이다. 둘째 인수는 `Dvd.intro (k^2 + k + 1) rfl`이라는 짧은 표현으로 만들었다.

**`Dvd.intro x rfl`** 가분성을 직접 구성하는 표현이다. `Dvd.intro x rfl : a ∣ (a * x)` 형태이다. 즉 "`a * x`는 `a`로 나누어떨어진다"는 자명한 사실을 표현한다. 우리는 `3 ∣ 3 * (k^2 + k + 1)`을 보이고 싶고, 이는 `Dvd.intro (k^2 + k + 1) rfl`로 즉시 구성된다.

가분성 정리의 종이 증명과 Lean 4 코드의 대응을 정리한다.

| 종이 증명 단계 | Lean 4 한 줄 |
|---|---|
| 기저 P(0): 0³ + 2·0 = 0이고 3 ∣ 0 | `decide` |
| "(k+1)³ + 2(k+1)을 전개해서 정리" | `have key : ... := by ring` |
| "두 덩어리(IH가 책임지는 것과 명백한 3의 배수)로 쪼개기" | `rw [key]` |
| "두 3의 배수의 합은 3의 배수" | `Nat.dvd_add ih (Dvd.intro _ rfl)` |

## 16. 가분성 (2) - `7 ∣ (11ⁿ − 4ⁿ)` (정수)

이번에는 뺄셈이 들어가는 경우이다. 자연수에서는 위험하므로 **정수** `Int`로 진술을 옮긴다.

**정리** 모든 자연수 `n`에 대해 `7 ∣ (11ⁿ - 4ⁿ)`이다 (정수환 ℤ에서).

자연수에서 뺄셈을 피하기 위해 우변의 식 자체는 정수의 형태로 둔다. 이는 §5.1 강의의 `3 ∣ (n³ - n)`을 정수 버전으로 다룬 것과 같은 처방이다.

핵심 아이디어는 §5.1 강의에서 본 **표준 트릭** "a · aᵏ - b · bᵏ = a(aᵏ - bᵏ) + (a-b)bᵏ"이다. 우리 경우 `a = 11`, `b = 4`이므로 `11 - 4 = 7`이 약수로 떨어진다.

```lean
import Mathlib

-- 정리: 7이 11^n - 4^n을 나눈다 (정수 위에서, 모든 자연수 n에 대해).
theorem seven_dvd_11n_sub_4n (n : Nat) :
    (7 : Int) ∣ ((11 : Int) ^ n - 4 ^ n) := by
  induction n with
  | zero =>
    -- 기저 단계.
    -- InfoView 목표:  ⊢ (7 : Int) ∣ (11 ^ 0 - 4 ^ 0)
    -- 11^0 = 4^0 = 1 이므로 차는 0. 7 ∣ 0은 참.
    decide
  | succ k ih =>
    -- 귀납 단계.
    -- InfoView 가정:  k : Nat,  ih : (7 : Int) ∣ (11 ^ k - 4 ^ k)
    -- InfoView 목표:  ⊢ (7 : Int) ∣ (11 ^ (k + 1) - 4 ^ (k + 1))
    -- 핵심 분해:
    --   11^(k+1) - 4^(k+1) = 11 * (11^k - 4^k) + 7 * 4^k
    have key : (11 : Int) ^ (k + 1) - 4 ^ (k + 1)
             = 11 * (11 ^ k - 4 ^ k) + 7 * 4 ^ k := by
      ring
    rw [key]
    -- 위 rw로 목표가 다음과 같이 바뀐다.
    -- InfoView 목표:  ⊢ (7 : Int) ∣ (11 * (11^k - 4^k) + 7 * 4^k)
    -- 첫 항은 "ih가 보장하는 7의 배수"의 11배, 둘째 항은 명백한 7의 배수.
    exact dvd_add (Dvd.dvd.mul_left ih 11) (Dvd.intro (4 ^ k) rfl)
```

§11과 거의 같은 구조이지만 두 가지가 다르다.

**자연수가 아닌 정수에서 작업** 가분성 결합 정리가 자연수 전용 `Nat.dvd_add`가 아니라 정수에서도 통용되는 `dvd_add`이다. 이는 임의의 환(ring)에서 작동하는 일반 정리이다. `(11 : Int) ^ n`처럼 명시적으로 정수임을 지정해 주는 표기를 사용한다.

**`Dvd.dvd.mul_left`** 새로 등장한 표현이다. `Dvd.dvd.mul_left ih 11`은 "`ih`가 보장하는 가분성에 11배를 곱한 형태의 가분성"을 만든다. 우리 코드에서 `ih`는 `7 ∣ (11^k - 4^k)`이고, 이로부터 `7 ∣ 11 * (11^k - 4^k)`를 만들기 위해 `Dvd.dvd.mul_left ih 11`을 사용한다.

남은 부분은 §11과 같다. `ring`이 핵심 다항식 분해를 자동으로 검증하고, `rw [key]`로 형태를 바꾸고, `dvd_add`로 두 7의 배수를 결합한다.

§5.1 강의에서 강조한 **표준 트릭의 한 줄 요약**을 다시 적어 둔다.

> `a^(k+1) - b^(k+1) = a · (a^k - b^k) + (a - b) · b^k`

이 분해를 외워 두면, "`(a-b) ∣ (aⁿ - bⁿ)`" 형태의 모든 가분성 정리를 같은 방식으로 풀 수 있다. 시험 직전에 한 번 복습해 두는 것이 좋다.

## 17. 가분성 (3) - `3 ∣ (n³ - n)` (정수, `Int.induction_on`)

이번에는 §11의 자연수 친화 버전이 아니라 **원래의 형태** `3 ∣ (n³ - n)`을 정수 위에서 다룬다. 정수에서는 자유롭게 음수가 가능하다는 점이 차이이다. 그러므로 귀납을 0에서 양·음 두 방향으로 모두 진행해야 한다.

이를 가능하게 하는 도구가 `Int.induction_on`이다.

`Int.induction_on`의 진술은 다음과 같다.

```
Int.induction_on : ∀ {p : Int → Prop} (n : Int),
  p 0 →                                    -- 기저: 0에서 참
  (∀ (k : Nat), p k → p (k + 1)) →        -- 양의 방향 succ
  (∀ (k : Nat), p (-k) → p (-k - 1)) →    -- 음의 방향 pred
  p n
```

세 갈래가 만들어진다. `zero`(기저), `succ`(양의 방향으로 한 칸), `pred`(음의 방향으로 한 칸).

```lean
import Mathlib

-- 정리: 모든 정수 n에 대해 3이 n³ - n을 나눈다.
theorem div3_n3_sub_n_int (n : Int) : (3 : Int) ∣ (n ^ 3 - n) := by
  induction n using Int.induction_on with
  | zero =>
    -- 기저 단계.
    -- InfoView 목표:  ⊢ (3 : Int) ∣ (0^3 - 0)
    -- 우변은 0. 3 ∣ 0은 참.
    decide
  | succ k ih =>
    -- 양의 방향 단계.
    -- InfoView 가정:  k : Nat,
    --                 ih : (3 : Int) ∣ ((k : Int)^3 - k)
    -- InfoView 목표:  ⊢ (3 : Int) ∣ (((k : Int) + 1)^3 - ((k : Int) + 1))
    -- 핵심 분해:
    --   (k+1)³ - (k+1) = (k³ - k) + 3(k² + k)
    have key : ((k : Int) + 1) ^ 3 - ((k : Int) + 1)
             = ((k : Int) ^ 3 - (k : Int)) + 3 * ((k : Int) ^ 2 + (k : Int)) := by
      ring
    rw [key]
    exact dvd_add ih (Dvd.intro ((k : Int) ^ 2 + (k : Int)) rfl)
  | pred k ih =>
    -- 음의 방향 단계.
    -- InfoView 가정:  k : Nat,
    --                 ih : (3 : Int) ∣ ((-(k : Int))^3 - (-(k : Int)))
    -- InfoView 목표:  ⊢ (3 : Int) ∣ ((-(k : Int) - 1)^3 - (-(k : Int) - 1))
    -- 핵심 분해:
    --   (-k-1)³ - (-k-1) = ((-k)³ - (-k)) - 3(k² + k)
    have key : (-(k : Int) - 1) ^ 3 - (-(k : Int) - 1)
             = ((-(k : Int)) ^ 3 - (-(k : Int))) - 3 * ((k : Int) ^ 2 + (k : Int)) := by
      ring
    rw [key]
    exact dvd_sub ih (Dvd.intro ((k : Int) ^ 2 + (k : Int)) rfl)
```

새 요소가 세 개 등장하였다.

**`Int.induction_on`** 정수 위의 귀납법 도구이다. 세 갈래 `zero`(기저, `n = 0`), `succ`(양의 방향, `n` 양수), `pred`(음의 방향, `n` 음수)을 모두 채워야 한다. 양의 방향은 자연수의 `succ`과 같은 모양으로 진행하고, 음의 방향은 음수가 한 칸씩 더 작아지는 방향이다.

**`dvd_sub`** 보조 정리. `Nat.dvd_add` 또는 `dvd_add`의 뺄셈 짝꿍이다. 진술은 다음과 같다.

```
dvd_sub : ∀ {α : Type*} [inst : Ring α] {a b c : α}, a ∣ b → a ∣ c → a ∣ b - c
```

자연수 환경에서는 뺄셈이 위험하므로 일반적으로 `Nat.dvd_sub`이 작동하지 않거나 부가 조건을 요구한다. 그러나 우리는 정수 환경에 있으므로 `dvd_sub`이 자유롭게 작동한다.

**음의 방향 분해의 부호** `(-k-1)³ - (-k-1) = ((-k)³ - (-k)) - 3(k² + k)`을 손으로 펼쳐 본다.

```
(-k-1)³ = -(k+1)³ = -(k³ + 3k² + 3k + 1) = -k³ - 3k² - 3k - 1
(-k-1)³ - (-k-1) = (-k³ - 3k² - 3k - 1) - (-k - 1)
                 = -k³ - 3k² - 3k - 1 + k + 1
                 = -k³ - 3k² - 2k
```

한편

```
((-k)³ - (-k)) - 3(k² + k) = (-k³ + k) - 3k² - 3k
                            = -k³ + k - 3k² - 3k
                            = -k³ - 3k² - 2k.
```

양변이 일치한다. `ring`이 이를 자동으로 검증한다.

종이 증명과 Lean 4 코드의 대응은 §15와 거의 같지만 두 가지 차이가 있다. 첫째, 갈래가 두 개(`zero`/`succ`)가 아닌 세 개(`zero`/`succ`/`pred`)이다. 자연수 귀납과 정수 귀납이 같은 갈래 이름 `zero`·`succ`을 공유한다는 점에 주의한다. 정수 귀납만의 새 갈래가 `pred`이다. 둘째, 마지막 가분성 결합에서 양의 방향은 `dvd_add`, 음의 방향은 `dvd_sub`을 쓴다.

## 18. `revert` 기법 - 더 강한 귀납 가설을 만들기

이번 절은 다소 다른 결의 기법이다. 어떤 귀납 증명에서는 단순히 `induction n with` 형태로 시작하면 귀납 가설이 너무 약해서 다음 단계로 진행이 안 된다. 그럴 때 사용하는 표준 기법이 **`revert`**(되돌리기)이다.

문제의 정리부터 본다.

**정리(자연수 덧셈의 교환 법칙)** 모든 자연수 `n`, `m`에 대해 `n + m = m + n`이다.

이 정리를 첫 시도로 다음과 같이 증명해 본다(실패 사례).

```lean
-- 실패 사례. 따라치지 않는다.
theorem add_comm_fail (n m : Nat) : n + m = m + n := by
  induction n with
  | zero =>
    -- 목표: 0 + m = m + 0. 양변을 단순화하여 m = m으로 만들면 된다.
    sorry  -- (어떻게든 처리 가능)
  | succ k ih =>
    -- 가정 ih : k + m = m + k
    -- 목표: (k + 1) + m = m + (k + 1)
    -- 여기서 ih를 적용하려면 좌변에 k + m이 나타나야 한다.
    -- rw [Nat.succ_add] → 목표: (k + m) + 1 = m + (k + 1)
    -- rw [ih] 가능. → (m + k) + 1 = m + (k + 1)
    -- rw [Nat.add_succ]를 거꾸로 적용? 다소 복잡하다.
    sorry
```

이 시도가 결국 통하지 않거나 통하더라도 어색한 이유는, 귀납 시작 시점에 `m`이라는 변수가 **고정된 채로** 가정에 묶여 있기 때문이다. `induction n with`로 분리되는 순간, `ih`는 "고정된 그 특정 `m`에 대해 `k + m = m + k`"만 알려 준다. 그러나 우리는 `m`이 임의로 바뀌어도 좋은 형태의 IH가 필요하다.

해법은 귀납 직전에 `m`을 **목표 안으로 다시 밀어 넣는** 것이다. 그러면 IH가 `ih : ∀ m, k + m = m + k`라는 더 강한 형태로 손에 들어온다.

```lean
import Mathlib

-- 정리: 자연수 덧셈은 교환 가능하다.
theorem add_comm_nat (n m : Nat) : n + m = m + n := by
  revert m
  -- revert로 m을 다시 목표 안으로 밀어 넣었다.
  -- InfoView 목표:  ⊢ ∀ m, n + m = m + n
  induction n with
  | zero =>
    -- InfoView 목표:  ⊢ ∀ m, 0 + m = m + 0
    intro m
    -- 임의의 m을 잡는다.
    -- InfoView 목표:  ⊢ 0 + m = m + 0
    simp
  | succ k ih =>
    -- ih : ∀ m, k + m = m + k (강해진 귀납 가설)
    intro m
    -- 새 m을 잡는다.
    -- InfoView 목표:  ⊢ (k + 1) + m = m + (k + 1)
    rw [Nat.succ_add]
    rw [ih m]
    rw [Nat.add_succ]
```

세 가지 새 요소이다.

**`revert m`** 전술. 가정에 있던 변수 `m`을 다시 목표 안으로 밀어 넣어, 목표를 `∀ m, ...`의 형태로 바꾼다. 

**`intro m`** 전술. `∀ m, ...` 형태의 목표에서 임의의 `m`을 잡아 가정에 추가하고, 목표 안의 `m`은 그 잡힌 변수의 이름이 된다. `revert`의 정확한 역동작이다.

**`ih m`** 표현. `ih`가 `∀ m, k + m = m + k` 형태일 때, `ih m`은 `k + m = m + k`(현재 잡은 `m`에 대한 사실)이다. 즉 보편 양화 가정에 인수를 넘긴 표현이다.

종이의 손가락 짚기에서 "이제 m을 임의로 잡습니다"라고 말하는 그 순간이, Lean 4에서는 `revert m` + `intro m` 한 쌍이다.

`revert m` 패턴은 §5.2의 강한 귀납법에서도 자주 쓰인다. 강한 귀납법은 종종 "임의의 m에 대한 어떤 부등식을 보이는데, 그 부등식 안의 변수가 m이 아니라 m보다 작은 어떤 k에 대해 작용해야 하는 형태"이다. 이때 변수를 다시 목표 안으로 밀어 넣는 `revert` 기법이 결정적인 역할을 한다.

## 19. 마무리 - 본 자료의 패턴 정리

본 자료에서 익힌 핵심 패턴 일곱 가지를 정리한다.

**패턴 1. `induction`의 두 갈래 형식**

```lean
theorem ... (n : Nat) : P n := by
  induction n with
  | zero => <기저: P 0의 증명>
  | succ k ih => <귀납: ih : P k 를 디딤돌로 P (k+1)의 증명>
```

**패턴 2. `Nat.le_induction`(시작점이 0이 아닐 때)**

```lean
theorem ... (n : Nat) (hn : n₀ ≤ n) : P n := by
  induction n, hn using Nat.le_induction with
  | base => <기저: P n₀의 증명>
  | succ k hk ih => <귀납: hk : n₀ ≤ k, ih : P k 를 디딤돌로 P (k+1)의 증명>
```

**패턴 3. 합 공식 표준 4·5줄 절차**

```lean
| succ k ih =>
  rw [Finset.sum_range_succ]   -- 마지막 항 분리
  rw [mul_add]                 -- (배수가 있을 때) 분배
  rw [ih]                      -- 귀납 가설로 앞 부분 치환
  ring                         -- 다항식 항등식 자동 검증
```

분수가 들어가면 `ring` 직전에 `field_simp` 한 줄 추가.

**패턴 4. 가분성 표준 4줄 절차 (자연수)**

```lean
| succ k ih =>
  have key : <(k+1)에 대한 식> = <k에 대한 식> + <명백한 d의 배수> := by ring
  rw [key]
  exact Nat.dvd_add ih (Dvd.intro _ rfl)
```

정수 환경에서는 `Nat.dvd_add` 대신 `dvd_add`. 곱 형태가 다르면 `Dvd.dvd.mul_left`나 `Dvd.dvd.mul_right`로 조정.

**패턴 5. 부등식 사슬 표준 (`calc` 블록)**

```lean
| succ k hk ih =>
  have h1 : ... := by omega        -- 또는 linarith
  have h2 : ... := by linarith [ih]
  calc <시작> ≤ ... := h1
    _         < ... := h2
    _         = <목표> := by rw [...]; ring
```

비선형 결합이 필요하면 `linarith` 대신 `nlinarith`.

**패턴 6. 정수 위의 귀납법 (`Int.induction_on`)**

```lean
theorem ... (n : Int) : P n := by
  induction n using Int.induction_on with
  | zero => <기저: P 0>
  | succ k ih => <양의 방향: P k → P (k+1)>
  | pred k ih => <음의 방향: P (-k) → P (-k-1)>
```

양의 방향은 `dvd_add`, 음의 방향은 `dvd_sub`을 짝짓는 것이 보통.

**패턴 7. `revert`로 IH 강화하기**

```lean
theorem ... (n m : Nat) : P n m := by
  revert m            -- m을 목표 안으로 밀어 넣음
  induction n with
  | zero =>
    intro m; <증명>
  | succ k ih =>
    intro m
    -- ih : ∀ m, P k m (강해진 형태)
    ...
```

이 일곱 패턴이 본 자료가 다룬 §5.1의 모든 정리를 덮는다. 각 패턴은 "수학 증명의 그 단계가 코드의 그 한 줄에 정확히 대응"하도록 설계되었다.

본 자료를 처음부터 끝까지 손으로 한 번 따라쳐 보면, Lean 4의 기초 문법, `induction`의 작동 방식, `Nat.le_induction`과 `Int.induction_on`의 분기 처리, Mathlib의 주요 보조 정리들(`Nat.add_succ`, `Nat.succ_add`, `Finset.sum_range_succ`, `mul_add`, `Nat.dvd_add`, `dvd_add`, `dvd_sub`, `pow_succ`, `Nat.factorial_succ`, `sub_ne_zero`, `sq_nonneg`, `mul_nonneg`)에 자연스럽게 익숙해질 것이다.

다음 단계는 §5.2의 **강한 귀납법**(strong induction)이다. 같은 도미노 원리를 다루지만 "바로 앞 칸 하나"가 아니라 "그 앞 모든 칸"을 디딤돌로 쓰는 형태이다. 본 자료 §18의 `revert` 기법이 §5.2의 결정적인 다리가 된다. §5.2 짝꿍 자료에서 만난다.
