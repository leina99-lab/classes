# `myMax`의 정확성 증명

> Lean 4 + Mathlib4
> 리스트의 최댓값 함수가 '진짜로' 최댓값을 돌려준다는 것을 형식 증명으로 확인한다

---

1. myMax의 정의 — 함께 펼쳐 보기
증명을 읽기 전에, 정리가 다루는 함수 myMax가 어떻게 정의되어 있는지부터 명확히 해 두자. 코드의 흐름(split, myMax [a] = a 같은 등식의 사용)으로 미루어 다음의 정의가 가장 자연스럽다.
leandef myMax : List Nat → Nat
  | []        => 0
  | a :: rest => if a ≥ myMax rest then a else myMax rest
읽어 보면 직관적이다.

빈 리스트의 최댓값은 0(자연수의 최솟값)으로 약속한다.
머리(head) a와 꼬리(tail) rest가 있는 경우, 머리와 꼬리의 최댓값을 비교해 더 큰 쪽을 택한다.

특히 한 가지를 짚어 둔다 — myMax [a]는 정의를 한 번 펼치면 if a ≥ myMax [] then a else myMax [], 즉 if a ≥ 0 then a else 0이 된다. 자연수에서 a ≥ 0은 항상 참이므로 결과는 항상 a이다. 따라서 myMax [a] = a는 rfl 수준의 정의적 동등성이다. 증명 안에서 show a ≥ x로 직접 바꿔 쓸 수 있는 것은 이 때문이다.

## 1. `myMax`의 정의 — 함께 펼쳐 보기

증명을 읽기 전에, 정리가 다루는 함수 `myMax`가 어떻게 정의되어 있는지부터 명확히 해 두자. 코드의 흐름(`split`, `myMax [a] = a` 같은 등식의 사용)으로 미루어 다음의 정의가 가장 자연스럽다.

```lean
def myMax : List Nat → Nat
  | []        => 0
  | a :: rest => if a ≥ myMax rest then a else myMax rest
```

읽어 보면 직관적이다.

- 빈 리스트의 최댓값은 0(자연수의 최솟값)으로 약속한다.
- 머리(head) `a`와 꼬리(tail) `rest`가 있는 경우, **머리와 꼬리의 최댓값을 비교**해 더 큰 쪽을 택한다.

특히 한 가지를 짚어 둔다 — `myMax [a]`는 정의를 한 번 펼치면 `if a ≥ myMax [] then a else myMax []`, 즉 `if a ≥ 0 then a else 0`이 된다. 자연수에서 `a ≥ 0`은 항상 참이므로 결과는 항상 `a`이다. 따라서 **`myMax [a] = a`는 `rfl` 수준의 정의적 동등성**이다. 증명 안에서 `show a ≥ x`로 직접 바꿔 쓸 수 있는 것은 이 때문이다.

## 2. 증명할 정리 — 의미를 풀어 읽기

```lean
theorem myMax_is_ge (L : List Nat) (x : Nat) (h : x ∈ L) :
    myMax L ≥ x
```

세 가지 매개변수를 받는다.

- `L : List Nat` — 자연수의 리스트.
- `x : Nat` — 어떤 자연수.
- `h : x ∈ L` — ' $x$가 리스트 $L$의 원소이다'라는 가설.

그리고 결론은 `myMax L ≥ x`. 즉 '`myMax L`은 $x$보다 작지 않다'.

가설 `x ∈ L`이 핵심이다. 이 가설 없이는 '아무 자연수 $x$에 대해 `myMax L ≥ x`'를 증명할 수 없다(거대한 $x$가 있으면 거짓). 가설은 $x$의 범위를 '리스트 안의 원소'로 제한한다.

---

## 3. 증명 전략 — 리스트 귀납법

리스트는 두 가지 모양 중 하나이다.

- **빈 리스트**: `[]`
- **머리 + 꼬리**: `a :: rest`

따라서 ' $L$에 관한 모든 명제'는 **리스트 귀납법**으로 다루는 것이 자연스럽다. 정수에 관한 귀납법(0과 succ)을 리스트로 옮긴 형태이다.

```
기저 단계 (nil): L = []인 경우 명제가 성립함을 보인다
귀납 단계 (cons): L = a :: rest이고 'rest에 대해 명제가 성립한다'를 가정하고
                  L에 대해서도 성립함을 보인다
```

Lean 4에서 `induction L with`를 쓰면 자동으로 두 분기가 생긴다.

```lean
induction L with
  | nil =>
      ...  -- 기저 단계
  | cons a rest ih =>
      ...  -- 귀납 단계, 'ih'는 귀납 가설(induction hypothesis)
```

귀납 가설 `ih`는 **'`x ∈ rest`이면 `myMax rest ≥ x`**'라는 동일 형태의 사실이다. 결론을 한 단계 작은 리스트(`rest`)에 적용한 모양.

그런데 이 증명에는 한 가지 추가 트릭이 들어 있다. **귀납 단계에서 `rest`를 다시 두 가지 경우로 나눈다**. 즉 '꼬리가 비어 있는가, 아닌가'에 따라 `myMax`의 분기 구조가 다르기 때문이다. 이를 위해 `cases rest with`를 한 번 더 쓴다.

전체 증명의 골격은 다음과 같다.

```
induction L with
  | nil       =>  ...                        ← 기저 단계
  | cons a rest ih =>
       cases rest with
       | nil   =>  ...                       ← L = [a]
       | cons b bs =>
            simp only [myMax]
            split
            · ...                            ← a ≥ myMax(b::bs) 분기
            · ...                            ← a < myMax(b::bs) 분기
```

세 끝점 + 한 분기 = 네 잎(leaf) 노드, 그 각각이 두 부분으로 더 쪼개져 총 일곱 개의 작은 증명이 모인다. 이 '트리'를 머릿속에 그리고 시작하면 코드 한 줄씩 정확히 어디로 가고 있는지 잃지 않는다.

## 4. 단계 1 — 기저 단계 (`L = []`)

```lean
| nil =>
    simp at h
```

기저 단계에서 가설은 `h : x ∈ []`이다. 그런데 빈 리스트에는 어떤 원소도 들어 있지 않다. 따라서 `x ∈ []`는 **거짓**이다. 거짓 가설을 가지고 있다는 것은 — 무엇이든 증명할 수 있다는 뜻이다(고전 논리의 기본). 결론 `myMax [] ≥ x`도 자동으로 따라온다.

`simp at h`는 다음의 일을 한다.

1. `List.not_mem_nil`이라는 보조 정리('빈 리스트의 원소가 아니다')를 가설 `h`에 적용한다.
2. `h`를 `False`로 단순화한다.
3. 거짓 가설이 발견되면 목표가 자동으로 닫힌다.

> **참고** —  더 미시적으로 풀고 싶다면 `cases h`를 써도 된다(생성자가 없으므로 즉시 닫힘).

InfoView로 추적하면 다음과 같다.

```
[induction nil 진입 직후]
h : x ∈ []
⊢ myMax [] ≥ x

[simp at h 후]
                    ← 가설 자체가 닫혀 목표 자동 종료
```

기저 단계 완료.

## 5. 단계 2 — 귀납 단계 진입

```lean
| cons a rest ih =>
    cases rest with
    ...
```

`cons a rest ih`로 진입하면 다음 상태가 된다.

```
a : Nat
rest : List Nat
ih : x ∈ rest → myMax rest ≥ x
h : x ∈ a :: rest
⊢ myMax (a :: rest) ≥ x
```

`ih`가 **'`x`가 `rest`에 있으면, `myMax rest`는 `x` 이상**'이라는 보조 사실이다. 우리가 결론을 만들 때 이 도구를 어떻게든 사용해야 한다.

다음으로 `cases rest with`. 이는 `rest` 자체를 두 모양 중 하나로 분리한다.

- `rest = nil` — `L = a :: []`, 즉 길이 1짜리 리스트.
- `rest = b :: bs` — `L = a :: b :: bs`, 즉 길이 2 이상의 리스트.

이 분리가 왜 필요한가? `myMax`가 '비어 있지 않은 꼬리'와 '비어 있는 꼬리'를 사실상 다르게 다루기 때문이다(꼬리가 비면 `myMax rest = 0`이 자명하지만, 비어 있지 않으면 `myMax rest`가 진짜 비교 대상). 두 경우의 증명 구조가 다르므로 갈라서 다룬다.

## 6. 단계 3 — `L = [a]`인 경우

```lean
| nil =>
    show a ≥ x
    rw [List.mem_singleton] at h
    exact le_of_eq h
```

여기서 `cases rest`의 `nil` 가지로 들어왔다. 이때 상태는 다음과 같다.

```
a : Nat
ih : x ∈ [] → myMax [] ≥ x   ← 자명. 사용 안 함
h : x ∈ a :: []
⊢ myMax (a :: []) ≥ x
```

`a :: []`는 표기상 `[a]`와 같다.

### 6.1 `show a ≥ x` — 목표를 단순한 형태로

목표는 `myMax [a] ≥ x`. 그런데 §1에서 본 바와 같이 **`myMax [a] = a`는 정의적 동등성**이다. 따라서 목표를 `a ≥ x`로 '다시 써'도 된다. Lean에서는 `show`라는 전술이 정확히 이 일을 한다.

```
[show a ≥ x 후]
⊢ a ≥ x
```

`show`는 **'현재 목표가 이것과 정의적으로 같다**'고 주장하면서 모양을 바꾼다. 정의적으로 다르면 즉시 오류가 난다.

### 6.2 `rw [List.mem_singleton] at h` — 멤버십을 등식으로

가설 `h : x ∈ [a]`는 어떻게 사용해야 할까? Mathlib에는 다음 정리가 있다.

```lean
List.mem_singleton : x ∈ [a] ↔ x = a
```

'하나짜리 리스트의 원소이다'와 '그 하나와 같다'는 동치라는 뜻이다. `rw`로 이 동치를 가설에 적용하면 가설이 등식으로 바뀐다.

```
[rw [List.mem_singleton] at h 후]
h : x = a
⊢ a ≥ x
```

이제 가설이 ' $x = a$'라는 단순한 등식이 되었다. 목표 ' $a \ge x$'는 이 등식에서 즉시 따라 나온다.

### 6.3 `exact le_of_eq h` — 등식에서 부등식으로

`le_of_eq`라는 보조 정리가 있다.

```lean
le_of_eq : a = b → a ≤ b
```

'같으면 작거나 같다'. 단순하지만 자주 쓴다. 그런데 우리 목표는 `a ≥ x`, 즉 `x ≤ a`이고, 가설은 `x = a`이다. `le_of_eq h`를 적용하면 `x ≤ a`가 나온다 — 정확히 우리 목표의 형태이다(' $a \ge x$'와 ' $x \le a$'는 표기 차이뿐).

```
[exact le_of_eq h 후]
                    ← 목표 종료
```

`L = [a]` 경우 완료.

## 7. 단계 4 — `L = a :: b :: bs`인 경우 진입

```lean
| cons b bs =>
    simp only [myMax]
    split
```

이제 가장 흥미로운 분기이다. 진입 시 상태:

```
a, b : Nat
bs : List Nat
ih : x ∈ b :: bs → myMax (b :: bs) ≥ x
h : x ∈ a :: b :: bs
⊢ myMax (a :: b :: bs) ≥ x
```

**귀납 가설 `ih`가 처음으로 의미를 가진다** — `b :: bs`(비어 있지 않은 꼬리)에 적용 가능하다.

### 7.1 `simp only [myMax]` — 정의 한 번 펼치기

`myMax`의 정의를 한 번 펼쳐 본다. `myMax (a :: b :: bs)`는 정의에 의해

```
if a ≥ myMax (b :: bs) then a else myMax (b :: bs)
```

이 된다. `simp only [myMax]`는 **'`myMax`의 정의 등식만 사용해서 단순화**'를 의미한다(다른 보조 정리를 쓰지 않음).

```
[simp only [myMax] 후]
⊢ (if a ≥ myMax (b :: bs) then a else myMax (b :: bs)) ≥ x
```

### 7.2 `split` — `if` 분기 갈라내기

목표 안에 `if-then-else`가 들어 있다. 이걸 다룰 때는 두 가지 경우를 따로 본다.

- **조건이 참**일 때 — `if`가 첫 번째 가지(`a`)로 평가됨.
- **조건이 거짓**일 때 — `if`가 두 번째 가지(`myMax (b :: bs)`)로 평가됨.

`split` 전술이 정확히 이 일을 한다. 목표가 두 개로 갈라진다.

```
[split 후 — 첫 분기]
(이름 없는 가설) : a ≥ myMax (b :: bs)
⊢ a ≥ x

[split 후 — 둘째 분기]
(이름 없는 가설) : ¬ (a ≥ myMax (b :: bs))
⊢ myMax (b :: bs) ≥ x
```

각 분기에서 '`if` 조건의 참/거짓'이 가설로 추가되었다. 하지만 이름이 안 붙어 있어 직접 사용하기 불편하다. 그래서 다음 줄에서 `rename_i`로 이름을 붙인다.

> **참고** — 본 강의는 자동화 전술을 지양하지만 `split`은 '정의 펼치기' 수준의 단순한 도구이며 `if` 처리에 사실상 표준이다. 직접 풀고 싶다면 `by_cases h_cond : a ≥ myMax (b :: bs)`를 써도 같은 효과를 얻는다.

## 8. 단계 5 — 분기 1: `a ≥ myMax (b :: bs)`

```lean
· rename_i hge
  rw [List.mem_cons] at h
  cases h with
  | inl h_eq =>
      rw [h_eq]
  | inr h_in =>
      exact Nat.le_trans (ih h_in) hge
```

이 분기의 직관 — **`a`가 꼬리의 최댓값보다 크거나 같으니, `myMax (a :: b :: bs)`의 값은 `a`이다.** 따라서 ' $a \ge x$'를 보이면 끝.

### 8.1 `rename_i hge` — 가설 이름 붙이기

`split` 직후 만들어진 무명 가설 `a ≥ myMax (b :: bs)`에 `hge`라는 이름을 붙인다. 이제 직접 호출 가능하다.

```
[rename_i hge 후]
hge : a ≥ myMax (b :: bs)
h : x ∈ a :: b :: bs
⊢ a ≥ x
```

### 8.2 `rw [List.mem_cons] at h` — 멤버십을 '이거 또는 저거'로

다음 보조 정리가 있다.

```lean
List.mem_cons : x ∈ a :: l ↔ x = a ∨ x ∈ l
```

' $x$가 머리이거나, 꼬리에 들어 있다'. 가분성이 '존재'를 키워드로 가졌다면, 멤버십은 '선언'(disjunction)을 키워드로 가진다. `rw`로 이 동치를 가설에 적용한다.

```
[rw [List.mem_cons] at h 후]
hge : a ≥ myMax (b :: bs)
h : x = a ∨ x ∈ b :: bs
⊢ a ≥ x
```

가설이 **'$x$가 $a$이거나, $x$가 꼬리 안에 있다**'로 바뀌었다. 두 가지 경우를 별도로 다뤄야 한다.

### 8.3 `cases h with` — 선언을 두 갈래로

`A ∨ B` 형태의 가설을 두 case로 가른다.

- `inl h_eq` — 왼쪽이 참인 경우, 즉 `h_eq : x = a`.
- `inr h_in` — 오른쪽이 참인 경우, 즉 `h_in : x ∈ b :: bs`.

'inl/inr'은 'injection left/right'의 약자로, 어느 쪽 가지에서 왔는지를 가리킨다.

#### 8.3.1 `inl h_eq` — $x$가 머리 자체인 경우

```lean
| inl h_eq =>
    rw [h_eq]
```

`h_eq : x = a`. 목표는 `a ≥ x`. 단순한 치환이면 끝난다.

```
[rw [h_eq] 후]
⊢ a ≥ a       ← rfl로 자동 종료(rw가 자동으로 닫는다)
```

`rw`가 등식 양변이 같아지는 순간 목표를 자동으로 닫아 준다. 별도 `exact rfl`이 필요 없다.

#### 8.3.2 `inr h_in` — $x$가 꼬리에 있는 경우

```lean
| inr h_in =>
    exact Nat.le_trans (ih h_in) hge
```

상태:

```
hge : a ≥ myMax (b :: bs)
h_in : x ∈ b :: bs
⊢ a ≥ x
```

세 도구를 손에 쥐었다 — 귀납 가설 `ih`, 가설 `hge`, 가설 `h_in`. 이걸 어떻게 조립하는가?

먼저 `ih h_in`을 만든다. 귀납 가설 `ih : x ∈ b :: bs → myMax (b :: bs) ≥ x`에 `h_in`을 '적용'하면(함수 적용), `myMax (b :: bs) ≥ x`라는 사실이 즉시 얻어진다.

```
ih h_in : myMax (b :: bs) ≥ x
hge     : a ≥ myMax (b :: bs)
                   ↓
부등식 추이성 (transitivity): a ≥ myMax (b :: bs) ≥ x
                   ↓
결론: a ≥ x
```

이 '추이로 잇기'를 한 번에 해 주는 도구가 `Nat.le_trans`이다.

```lean
Nat.le_trans : a ≤ b → b ≤ c → a ≤ c
```

' $x \le \mathrm{myMax}(b::bs) \le a$'에서 ' $x \le a$'를 즉시 얻는다. 코드의 `Nat.le_trans (ih h_in) hge`가 정확히 이 동작이다(`≤`와 `≥`는 인자 순서가 반대일 뿐 같은 도구).

분기 1 완료.

## 9. 단계 6 — 분기 2: `a < myMax (b :: bs)`

```lean
· rename_i hlt
  rw [List.mem_cons] at h
  cases h with
  | inl h_eq =>
      rw [h_eq]
      exact Nat.le_of_lt (Nat.lt_of_not_le hlt)
  | inr h_in =>
      exact ih h_in
```

이 분기의 직관 — **`a`가 꼬리의 최댓값보다 작으니, `myMax (a :: b :: bs)`의 값은 `myMax (b :: bs)`이다.** 따라서 ' $\mathrm{myMax}(b::bs) \ge x$'를 보이면 끝.

### 9.1 `rename_i hlt` + `rw [List.mem_cons] at h` + `cases h`

분기 1과 동일한 세 단계로, 진입 상태가 다음과 같이 정돈된다.

```
hlt : ¬ (a ≥ myMax (b :: bs))
h_eq : x = a              (왼쪽 case)
또는
h_in : x ∈ b :: bs        (오른쪽 case)
⊢ myMax (b :: bs) ≥ x
```

분기 1과 비교했을 때 **목표가 `a ≥ x`가 아니라 `myMax (b :: bs) ≥ x`**로 바뀌었다는 것이 결정적 차이이다(`if` 분기가 두 번째 가지로 평가되기 때문).

### 9.2 `inl h_eq` — $x$가 머리 자체인 경우

```lean
| inl h_eq =>
    rw [h_eq]
    exact Nat.le_of_lt (Nat.lt_of_not_le hlt)
```

`h_eq : x = a`로 치환하면 목표가 단순해진다.

```
[rw [h_eq] 후]
hlt : ¬ (a ≥ myMax (b :: bs))
⊢ myMax (b :: bs) ≥ a
```

이제 `hlt`가 ' $a \ge \mathrm{myMax}(b::bs)$가 거짓'이라고 말한다. 자연수에서 ' $a \ge m$이 거짓'은 곧 ' $a < m$', 즉 ' $m > a$'이다. 이걸 두 단계로 변환한다.

#### 단계 ⓐ — `Nat.lt_of_not_le`로 '부정'을 '엄격 부등식'으로

```lean
Nat.lt_of_not_le : ¬ (a ≤ b) → b < a
```

' $a \le b$가 거짓이면, $b < a$이다'. 자연수에서 두 수의 비교는 항상 결정되므로, ' $\le$의 부정'은 ' $>$'와 같다.

`hlt`는 ' $\mathrm{myMax}(b::bs) \le a$가 거짓' 형태이다(`a ≥ m` = `m ≤ a`). 따라서 `Nat.lt_of_not_le hlt`는 ' $a < \mathrm{myMax}(b::bs)$'를 만든다.

#### 단계 ⓑ — `Nat.le_of_lt`로 '엄격'을 '느슨'으로

```lean
Nat.le_of_lt : a < b → a ≤ b
```

' $a < b$이면 $a \le b$'. 자명하지만 자주 쓴다.

' $a < \mathrm{myMax}(b::bs)$'에서 ' $a \le \mathrm{myMax}(b::bs)$'(즉 ' $\mathrm{myMax}(b::bs) \ge a$')를 얻는다. 정확히 우리 목표.

두 단계를 합치면 `Nat.le_of_lt (Nat.lt_of_not_le hlt)`. 이 한 줄에 '부정 → 엄격 → 느슨'의 두 변환이 들어 있다.

### 9.3 `inr h_in` — $x$가 꼬리에 있는 경우

```lean
| inr h_in =>
    exact ih h_in
```

이 분기에서 가장 짧다. 한 줄.

상태:

```
h_in : x ∈ b :: bs
⊢ myMax (b :: bs) ≥ x
```

귀납 가설 `ih : x ∈ b :: bs → myMax (b :: bs) ≥ x`에 `h_in`을 적용하면 즉시 ' $\mathrm{myMax}(b::bs) \ge x$'가 나온다. 이게 그대로 목표이다.

`exact ih h_in`. 끝.

분기 2 완료. 전체 증명 완료.

## 10. 사용된 도구 모음 — 한눈에

이 한 증명에서 다음 보조 정리·전술이 모두 등장했다.

### 10.1 보조 정리

| 이름 | 진술 | 사용처 |
|---|---|---|
| `List.mem_singleton` | $x \in [a] \iff x = a$ | `L = [a]` 분기 |
| `List.mem_cons` | $x \in a :: l \iff x = a \lor x \in l$ | 두 cons 분기 |
| `le_of_eq` | $a = b \to a \le b$ | `L = [a]` 분기 |
| `Nat.le_trans` | $a \le b \to b \le c \to a \le c$ | 분기 1, 추이성 |
| `Nat.le_of_lt` | $a < b \to a \le b$ | 분기 2 |
| `Nat.lt_of_not_le` | $\neg (a \le b) \to b < a$ | 분기 2 |

### 10.2 전술

| 전술 | 역할 |
|---|---|
| `induction L with` | 리스트 귀납법 시작 |
| `cases rest with` | 추가 케이스 분리 |
| `simp only [myMax]` | 정의를 한 번 펼침 |
| `split` | `if-then-else` 분기 |
| `rename_i` | 무명 가설에 이름 부여 |
| `rw` | 등식·동치를 이용한 치환 |
| `exact` | 목표를 정확히 만족하는 항 제시 |
| `show` | 정의적으로 같은 다른 형태로 목표 변경 |

## 11. 학습 포인트 — 이 증명에서 배운 일곱 가지

이 증명을 끝까지 따라가면 다음을 손에 쥔다.

**1. 리스트 귀납법의 기본 골격.** `induction L with | nil => ... | cons a rest ih => ...`. 정수 귀납법(0, succ)의 리스트 버전이다. `ih`가 '한 단계 작은 리스트에서의 동일한 명제'라는 사실을 매번 떠올린다.

**2. 케이스 분리의 '트리'를 머릿속에 그리기.** 귀납 가지 안에서 다시 케이스를 나누면 증명 트리가 깊어진다. 코드를 읽기 전에 트리(잎의 개수, 각 잎이 무엇을 보일지)를 종이에 그리면 길을 잃지 않는다.

**3. `if-then-else`를 다루는 두 손짓.** `split`은 한 줄, `by_cases`는 더 명시적. 두 도구 모두 '조건이 참인 세계'와 '조건이 거짓인 세계'를 따로 다룬다.

**4. 멤버십을 '선언'으로 풀어내기.** `List.mem_cons`로 `x ∈ a :: l`을 `x = a ∨ x ∈ l`로 바꾸는 것이 핵심 도구이다. 거의 모든 '리스트 + $x$' 정리가 이 한 줄에서 출발한다.

**5. 귀납 가설은 '적용'으로 사용한다.** `ih h_in` 한 줄로 새로운 사실을 얻는다. '귀납 가설을 어떻게 쓰는가?' 질문의 답은 **'필요한 가설을 만들어 적용한다**'이다.

**6. 부등식의 변환 도구들을 알아 두기.** `Nat.le_trans`(추이), `Nat.le_of_lt`(엄격→느슨), `Nat.lt_of_not_le`(부정→엄격), `le_of_eq`(등식→부등식). 부등식 증명의 절반은 이 네 도구의 적절한 조합이다.

**7. 정의적 동등성을 활용하는 `show`.** 목표가 '정의를 풀면 같은' 다른 형태로 보이고 싶을 때 `show`가 깔끔하다. `myMax [a]`를 `a`로 바꾸는 자리가 그 예이다.

## 12. 더 가 보기 — '있다'를 마저 보이는 짝 정리

이 정리는 '`myMax L`이 모든 원소 이상이다'를 말했다. '최댓값임'을 완전히 증명하려면 짝이 되는 정리가 더 필요하다.

> **(짝 정리)** $L$이 비어 있지 않으면, **`myMax L`은 $L$ 안에 들어 있다**. 즉 $\mathrm{myMax}\ L \in L$.

이 짝 정리도 같은 패턴 — 리스트 귀납법 + 이중 케이스 + `split` + `mem_cons` — 으로 증명한다. 워크북 연습 문제로 도전해 볼 만하다.

이 두 정리를 합치면 **'`myMax L`이 $L$의 진짜 최댓값**'이 형식적으로 증명되었다고 말할 수 있다 — `myMax`가 사양(specification)을 만족하는, **검증된 함수**가 된 것이다.

## 13. 한 단계 더 — AI 응용으로의 다리

자동 증명기 **AlphaProof**는 정확히 이런 류의 정리를 자동으로 푼다. 그 동작을 한 줄로 요약하면 — **'Mathlib에 있는 비슷한 정리를 검색해, 적합한 보조 정리를 조립한다**'(RAG 기반 자동 증명).

이 증명에서 `Nat.le_trans`, `Nat.le_of_lt`, `Nat.lt_of_not_le`를 손으로 골라 조합한 동작이, AlphaProof에서는 '부등식 변환 정리들을 의미적으로 검색해 후보 시퀀스를 생성하는' 과정과 정확히 같다. 사람의 직관이 자동화되는 자리가 바로 여기이다.

여러분이 이 증명을 손에 익히면 — 'AlphaProof의 정신적 사촌'이 된 셈이다. 차이는 단 하나, 인간의 뇌는 당분으로 작동하고 AlphaProof는 전기로 작동한다.
