## 1. 왜 함수의 증가를 배우는가?

### 1.1 3.1절에서 남은 질문

3.1절에서 선형 탐색은 O(n), 이진 탐색은 O(log n)이라고 했다. 그런데 O(n)이라는 표기가 정확히 무슨 뜻인가? "대략 n에 비례한다" 정도의 느낌은 있지만, 이것을 수학적으로 엄밀하게 정의해야 한다.

### 1.2 왜 엄밀한 정의가 필요한가?

다음 두 알고리즘의 실행 시간을 비교해 보자:

- 알고리즘 A: 정확히 1000n 단계
- 알고리즘 B: 정확히 n² 단계

n = 10일 때: A = 10,000, B = 100 → B가 100배 빠르다.
n = 100일 때: A = 100,000, B = 10,000 → B가 10배 빠르다.
n = 10,000일 때: A = 10,000,000, B = 100,000,000 → **A가 10배 빠르다!**

어떤 알고리즘이 "더 빠른가"는 **n이 충분히 클 때**의 행동으로 판단해야 한다. 앞에 붙은 상수(1000)는 n이 커지면 중요하지 않게 된다. 이것이 Big-O 표기법의 핵심이다.

### 1.3 핵심 통찰: 상수는 잊고, 증가 속도만 본다

| 함수 | n=10 | n=100 | n=1,000 | n=1,000,000 | 증가 속도 |
|------|------|-------|---------|------------|---------|
| log n | 3.3 | 6.6 | 10 | 20 | 매우 느림 |
| n | 10 | 100 | 1,000 | 1,000,000 | 보통 |
| n log n | 33 | 664 | 10,000 | 20,000,000 | 약간 빠름 |
| n² | 100 | 10,000 | 1,000,000 | 10¹² | 빠름 |
| 2ⁿ | 1,024 | 1.27x10^30 | ... | ... | 폭발적 |

## 2. Big-O 표기법: 상한(Upper Bound)

### 2.1 정의 (Rosen Definition 1)

> $f(n)$이 $\mathcal(g(n))$이라 함은, 양의 상수 $C$와 $k$가 존재하여
> **$모든 n > k에 대해 |f(n)| <= C|g(n)|$** 이 성립하는 것이다.

이 정의를 한 줄씩 풀어 보자:

-"**양의 상수 $C$와 $k$가 존재하여**": 어떤 특정한 숫자 C와 k를 찾을 수 있다
- "**모든 $n > k$에 대해**": n이 k보다 큰 모든 경우에 (n이 충분히 클 때)
- "**$|f(n)| \le C|g(n)|$**": f(n)은 C x g(n)보다 작거나 같다

직관적으로: **f(n)은 g(n)보다 빨리 증가하지 않는다.** g(n)이 f(n)의 "천장"이다.

### 2.2 일상 비유

"이 택배는 **3일 이내에** 도착합니다" — 이것이 상한이다. 실제로는 1일 만에 올 수도 있지만, 절대 3일을 넘지 않는다. Big-O도 마찬가지다: f(n)이 O(n²)이라는 것은 "n²의 상수배보다 빨리 자라지 않는다"는 의미이다. 실제로는 훨씬 느리게 자랄 수도 있다.

### 2.3 Lean 4에서의 형식화

```lean
-- Big-O의 형식 정의
def BigO (f g : Nat → Nat) : Prop :=
  ∃ C : Nat, ∃ k : Nat, C > 0 ∧
    ∀ n : Nat, n > k → f n ≤ C * g n
```

이 정의를 읽어 보자:
- `∃ C : Nat, ∃ k : Nat`: 양의 상수 C와 k가 존재하여
- `C > 0`: C는 양수이고
- `∀ n : Nat, n > k →`: 모든 n > k에 대해
- `f n ≤ C * g n`: f(n) <= C * g(n)이 성립한다

### 2.4 예제 1: f(n) = 3n + 5는 O(n)인가?

**증명:** C = 4, k = 5로 놓자.

n > 5일 때:
- 3n + 5 <= 3n + n = 4n (왜냐하면 n > 5이므로 5 < n)
- 따라서 3n + 5 <= 4n = C * n

C = 4, k = 5가 존재하므로 3n + 5는 O(n)이다.

```lean
-- Lean 4 증명: 3n + 5 는 O(n)
theorem linear_bigO : BigO (fun n => 3 * n + 5) (fun n => n) := by
  use 4, 5     -- C = 4, k = 5
  constructor
  · omega      -- 4 > 0
  · intro n hn
    omega      -- 3n + 5 ≤ 4n when n > 5
```

### 2.5 예제 2: n²는 O(n)인가?

**아니다!** 어떤 C와 k를 잡아도, n이 충분히 크면 n² > Cn이 된다.

증명: 귀류법으로, n² <= Cn이면 n <= C인데, n은 얼마든지 커질 수 있으므로 모순이다.

이것은 직관적으로도 명백하다. n²은 n보다 빨리 자란다.

### 2.6 예제 3: f(n) = 5n² + 3n + 7은 O(n²)인가?

**증명:** C = 6, k = 7로 놓자.

n > 7일 때:
- 3n <= 3n²/n <= n² (왜냐하면 n >= 1)
- 7 <= n <= n² (왜냐하면 n > 7이고 n >= 1)
- 따라서 5n² + 3n + 7 <= 5n² + n² = 6n²

```lean
-- Lean 4 증명 스케치 (실제로는 nlinarith 사용)
theorem quadratic_bigO :
    BigO (fun n => 5 * n^2 + 3 * n + 7) (fun n => n^2) := by
  use 6, 7
  constructor
  · omega
  · intro n hn
    nlinarith  -- 비선형 부등식을 자동 처리
```

### 2.7 Big-O 증명의 일반 전략

1. **주어진 f(n)의 각 항을 g(n)의 배수로 바운드한다**
2. **C를 모든 계수의 합보다 크게 잡는다**
3. **k를 모든 부등식이 성립할 만큼 크게 잡는다**

예: f(n) = a_m * nᵐ + a_{m-1} * n^{m-1} + ... + a_0

각 항 a_i * n^i <= a_i * nᵐ (n >= 1일 때)

따라서 f(n) <= (|a_m| + |a_{m-1}| + ... + |a_0|) * nᵐ

→ C = |a_m| + ... + |a_0|, k = 1로 놓으면 된다.

## 3. Big-Omega: 하한(Lower Bound)

### 3.1 정의 (Rosen Definition 2)

> f(n)이 Omega(g(n))이라 함은, 양의 상수 C와 k가 존재하여
> **모든 n > k에 대해 |f(n)| >= C|g(n)|** 이 성립하는 것이다.

Big-O가 "천장"이라면, Big-Omega는 "바닥"이다.

### 3.2 일상 비유

"이 공사는 **최소 6개월**은 걸립니다" — 이것이 하한이다. 실제로는 1년 걸릴 수도 있지만, 6개월보다 빨리 끝나지는 않는다.

### 3.3 Lean 4에서의 형식화

```lean
def BigOmega (f g : Nat → Nat) : Prop :=
  ∃ C : Nat, ∃ k : Nat, C > 0 ∧
    ∀ n : Nat, n > k → f n ≥ C * g n
```

### 3.4 Big-O와 Big-Omega의 관계

f(n)이 O(g(n))이면 g(n)이 Omega(f(n))이다.

직관적으로: "f가 g 이하"이면 "g가 f 이상"이다.

---

## 4. Big-Theta: 동일한 차수(Same Order)

### 4.1 정의 (Rosen Definition 3)

> f(n)이 Theta(g(n))이라 함은, f(n)이 **O(g(n))이면서 동시에 Omega(g(n))**인 것이다.

즉, 양의 상수 C1, C2, k가 존재하여
**모든 n > k에 대해 C1|g(n)| <= |f(n)| <= C2|g(n)|** 이 성립한다.

### 4.2 일상 비유

"이 여행은 **3시간에서 4시간** 걸립니다" — 상한과 하한이 동시에 있다. f(n)이 Theta(g(n))이라는 것은 "f(n)과 g(n)이 **같은 속도**로 증가한다"는 뜻이다.

### 4.3 Lean 4에서의 형식화

```lean
def BigTheta (f g : Nat → Nat) : Prop :=
  BigO f g ∧ BigOmega f g
```

### 4.4 예제: 3n + 5는 Θ(n)인가?

**그렇다.**
- O(n): 이미 증명했다 (C = 4, k = 5)
- Omega(n): C = 3, k = 0으로 놓으면 3n + 5 >= 3n = 3 * n (모든 n >= 0)
- 따라서 Θ(n)이다.

---

## 5. 세 표기법의 관계 요약

| 표기법 | 의미 | 비유 | 기호 |
|--------|------|------|------|
| **O**(g(n)) | f는 g보다 **느리거나 같다** | 천장 (상한) | <= |
| **Omega**(g(n)) | f는 g보다 **빠르거나 같다** | 바닥 (하한) | >= |
| **Theta**(g(n)) | f와 g는 **같은 속도**이다 | 구간 (양쪽) | = |

**핵심 관계:** f(n)이 Theta(g(n)) ↔ f(n)이 O(g(n)) 이고 f(n)이 Omega(g(n))

이것은 정확히 ↔ (**필요충분조건**)의 구조이다!

## 6. 자주 나오는 증가 함수들의 계층

**느린 것부터 빠른 순서:**

1 < log n < n < n log n < n² < n³ < 2ⁿ < n!

이 순서는 매우 중요하다. 외워두면 좋다.

| 이름 | 함수 | 예시 | n=1,000,000일 때 |
|------|------|------|---------------|
| 상수 | O(1) | 배열 인덱스 접근 | 1 |
| 로그 | O(log n) | 이진 탐색 | 20 |
| 선형 | O(n) | 선형 탐색 | 1,000,000 |
| 선형로그 | O(n log n) | 병합 정렬 | 20,000,000 |
| 이차 | O(n²) | 버블 정렬 | 10¹² |
| 삼차 | O(n³) | 행렬 곱셈 | 10^18 |
| 지수 | O(2ⁿ) | 부분집합 열거 | 약 10^301,030 |
| 팩토리얼 | O(n!) | 순열 열거 | ... |

## 7. Big-O 계산 규칙 (Rosen 정리들)

### 7.1 합 규칙(Sum Rule)

> f1이 O(g1)이고 f2가 O(g2)이면, f1 + f2는 O(max(g1, g2))이다.

직관: 두 작업을 순서대로 수행하면, 전체 시간은 더 오래 걸리는 쪽에 지배된다.

예: O(n) + O(n²) = O(n²)

### 7.2 곱 규칙(Product Rule)

> f1이 O(g1)이고 f2가 O(g2)이면, f1 * f2는 O(g1 * g2)이다.

직관: 중첩 반복문이면 곱해진다.

예: O(n) * O(n) = O(n²) (이중 반복문)

### 7.3 Lean 4로 합 규칙 형식화

```lean
-- 합 규칙: O(f) + O(g) ⊆ O(max(f, g))
-- 간략한 버전: g가 f보다 빠르게 증가할 때
theorem sum_rule (hf : BigO f1 g) (hg : BigO f2 g) :
    BigO (fun n => f1 n + f2 n) g := by
  obtain ⟨C1, k1, hC1, h1⟩ := hf
  obtain ⟨C2, k2, hC2, h2⟩ := hg
  use C1 + C2, max k1 k2
  constructor
  · omega
  · intro n hn
    have hk1 : n > k1 := by omega
    have hk2 : n > k2 := by omega
    have := h1 n hk1
    have := h2 n hk2
    nlinarith
```

## 8. Big-O 빈칸 연습

### 연습 1: 정의 확인

```lean
def BigO (f g : Nat → Nat) : Prop :=
  ∃ C : Nat, ∃ k : Nat, ___ ∧         -- (a) C에 대한 조건?
    ∀ n : Nat, ___ → f n ≤ ___         -- (b) n 조건? (c) 상한?
```

<details>
<summary>정답 보기</summary>

```lean
  ∃ C : Nat, ∃ k : Nat, C > 0 ∧       -- (a) C > 0
    ∀ n : Nat, n > k → f n ≤ C * g n   -- (b) n > k  (c) C * g n
```

</details>

### 연습 2: 증명 완성

```lean
-- 2n + 1 은 O(n) 임을 증명하라
theorem exercise_bigO :
    BigO (fun n => 2 * n + 1) (fun n => n) := by
  use ___, ___    -- (a) C와 k의 값?
  constructor
  · ___           -- (b) C > 0 증명?
  · intro n hn
    ___           -- (c) 부등식 증명?
```

<details>
<summary>정답 보기</summary>

```lean
theorem exercise_bigO :
    BigO (fun n => 2 * n + 1) (fun n => n) := by
  use 3, 1          -- (a) C = 3, k = 1
  constructor
  · omega            -- (b) 3 > 0
  · intro n hn
    omega            -- (c) 2n + 1 ≤ 3n when n > 1
```

</details>

### 연습 3: 참/거짓 판별

다음 각 명제의 참/거짓을 판별하라.

| 명제 | 참/거짓 |
|------|--------|
| n² + n은 O(n²) | ? |
| n³은 O(n²) | ? |
| 2ⁿ은 O(n¹⁰⁰) | ? |
| log n은 O(n) | ? |
| n은 O(n log n) | ? |

<details>
<summary>정답 보기</summary>

| 명제 | 참/거짓 | 이유 |
|------|--------|------|
| n² + n은 O(n²) | 참 | n <= n²이므로 n² + n <= 2n² |
| n³은 O(n²) | **거짓** | n³/n² = n → 무한히 커짐 |
| 2ⁿ은 O(n¹⁰⁰) | **거짓** | 지수 함수는 어떤 다항식보다 빨리 증가 |
| log n은 O(n) | 참 | 로그는 선형보다 느리게 증가 |
| n은 O(n log n) | 참 | n <= n log n (n >= 2일 때) |

</details>

## 9. 핵심 요약

| 개념 | 정의 | 직관 | Lean 4 핵심 |
|------|------|------|----------|
| O(g) | f <= Cg (n > k) | 상한 (천장) | `∃ C k, ∀ n > k, f n ≤ C * g n` |
| Omega(g) | f >= Cg (n > k) | 하한 (바닥) | `∃ C k, ∀ n > k, f n ≥ C * g n` |
| Theta(g) | O이고 Omega | 동일 차수 | `BigO f g ∧ BigOmega f g` |
| 합 규칙 | O(f)+O(g)=O(max) | 느린 쪽이 지배 | `obtain + nlinarith` |
| 곱 규칙 | O(f)*O(g)=O(fg) | 중첩은 곱 | `obtain + nlinarith` |
