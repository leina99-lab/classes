## **0. 도입 — 앤스콤의 사중주**(15분)

### 핵심 메시지

본 차시 전체를 관통하는 첫 메시지: **"통계량은 거짓말한다 — 그래서 시각화한다"**.

학생들이 4주차에서 `describe()`로 평균·표준편차·상관계수를 계산했다. "이 숫자만 보면 충분하지 않은가?"라는 자연스러운 의문에 대해, 1973년 앤스콤이 보여준 사중주가 **결정적 반증**을 제시한다.

### 강조점

1. 통계량 표를 먼저 보여준다 → "네 데이터셋이 같은가?"라고 학생에게 묻는다.
2. 학생 대답을 들은 뒤, 산점도를 보여준다.
3. **"평균, 표준편차, 상관, 회귀식이 전부 같지만 데이터는 완전히 다르다"** 충격을 의도적으로 만든다.

### 학생 예상 질문

**Q: 그러면 통계량은 의미가 없는 것인가?**
A: 통계량은 **요약**이다. 데이터의 일부 측면만 압축한다. 시각화는 압축되기 전의 **전체 모습**을 보여준다. 둘은 **상호 보완**이며, 결코 통계량을 버리라는 의미가 아니다.

**Q: 실무에서도 이런 상황이 정말 자주 발생하는가?**
A: 자주 있다. 특히 (1) 이상치가 평균을 끌어당기는 상황, (2) 비선형 관계(곡선)를 직선으로 오인하는 상황. 머신러닝 모델의 잔차가 패턴을 보이는데도 R²만 보고 만족하는 사례가 흔하다.

### 자주 발생하는 실수

- 학생들이 산점도가 명백히 다른데도 "데이터셋 II도 직선 같다"고 말하는 경우 → "회귀선이 그어져 있어서 그렇게 보일 뿐, 점들의 패턴은 분명히 곡선이다"라고 짚어준다.

### 보충 설명 거리

- **데이터사우루스 12종**(Datasaurus Dozen, 2017): 동일 통계량으로 공룡, 별, 십자가 모양 등 12개 패턴이 나온다 — 더 충격적인 후속 연구.
- 이 사례는 **EDA가 ML 파이프라인의 필수 관문**이라는 차시 결론으로 자연스럽게 연결된다.

## **Part 1. 분포 시각화**(40분)

### 1.1 히스토그램 + KDE (10분)

#### 핵심 메시지

"한 변수의 모양을 본다" — 가장 기본 도구.

#### 강조점

- 가격 분포를 그릴 때 **평균과 중앙값**을 함께 표시한다. **두 선의 위치 차이**가 분포의 비대칭성을 즉각적으로 보여준다.
- 평균 > 중앙값 → 오른쪽 꼬리. 이 관계는 외워둘 가치가 있다.

#### 학생 예상 질문

**Q: bins(구간 수)는 어떻게 정하는가?**
A: 데이터 크기에 따라 다르다. 일반적으로 √n 또는 Sturges 규칙(`bins = log2(n) + 1`)을 시작점으로 한다. seaborn은 `'auto'`로 지능적으로 선택한다. 너무 적으면 분포 모양을 놓치고, 너무 많으면 노이즈가 두드러진다.

**Q: KDE는 어떤 원리로 만들어지는가?**
A: 각 데이터 점에 작은 종 모양(kernel)을 얹고 합산하여 부드러운 밀도 곡선을 만든다. **bandwidth**(대역폭) 파라미터에 따라 곡선이 매끄러워지거나 거칠어진다. 자세한 수학은 통계학 과목에서 다룬다.

### 1.2 박스플롯 (15분)

#### 핵심 메시지

"중앙값·IQR·이상치를 한 그림에" — 그룹 비교의 표준.

#### 강조점

- 5수치 요약을 그림으로 외우게 한다. **칠판에 직접 박스플롯 구조도를 그려가며** 설명하면 효과적이다.
- "박스플롯 읽는 순서 3단계"를 학생들이 따라 읽게 한다: 위치 → 길이 → 이상치.
- 자치구별 박스플롯에서 **이상치가 위로 길게** 늘어진 것을 보고 "왜 위로만 있는가?"라고 묻는다 → 가격은 0 미만이 될 수 없으므로 자연스럽게 위쪽 비대칭이 발생.

#### 자주 발생하는 실수

- 학생들이 박스플롯의 **가운데 선**을 평균이라고 답한다. → "박스플롯은 5수치(min, Q1, Q2, Q3, max)로 정의되며, **평균은 표시되지 않는다**"라고 강조. 평균을 보고 싶으면 `showmeans=True`.
- $300 이상 이상치가 너무 많아 박스가 짜부라져 보이지 않을 때 → **확대본 함께 그리기** 패턴(`<= 300` 필터)을 시연한다.

### 1.3 바이올린 플롯 (10분)

#### 핵심 메시지

"박스플롯이 놓치는 분포 모양을 잡는다."

#### 강조점

- 칠판에 박스플롯과 바이올린의 차이를 그려준다 — 박스 길이는 같은데 가운데가 비어 있는 분포.
- **이봉분포**(bimodal) 개념과 클러스터링/혼합 모델의 연결을 짚어준다.

#### 학생 예상 질문

**Q: 그러면 항상 바이올린만 쓰면 되지 않는가?**
A: 두 가지 이유로 박스플롯도 여전히 유용하다. (1) **카테고리가 많을 때** 바이올린은 너무 두꺼워져 화면이 복잡해진다. (2) **표본이 작으면** KDE 추정이 부정확해 바이올린 모양이 의미가 없다. 작은 그룹은 박스플롯이 더 정직하다.

### 1.4 분포-ML 연결 (5분)

#### 핵심 메시지

"EDA의 발견이 곧 전처리 의사결정이 된다."

#### 강조점

- |skew| > 1을 **임계값**으로 외우게 한다.
- 로그 변환 → 표준화 순서를 강조한다.
- **GPT의 Layer Normalization도 같은 원리**라는 AI 연결 멘트로 흥미를 끈다.

#### 보충 설명 거리

- **Box-Cox**: 양수 데이터에 적용. **Yeo-Johnson**: 음수 포함 가능. 둘 다 `sklearn.preprocessing.PowerTransformer`로 호출 가능.
- 이미지·신경망에서는 **BatchNormalization**이 같은 원리. 학생이 익숙한 응용 사례를 언급하면 추상 개념이 구체화된다.

## **Part 2. 관계 시각화**(40분)

### 2.1 산점도 + 색맹 배려 (10분)

#### 핵심 메시지

"점 1개 = 데이터 1행. 색상에만 의존하지 마라."

#### 강조점

- **`hue` + `style` 동시 사용** 패턴을 처음 보여줄 때 학생들의 반응을 살핀다. 대부분 "둘 중 하나만 쓰면 충분하지 않은가"라고 의문을 가진다.
- 그래프를 **흑백으로 출력**한 예시(또는 회색조 변환)를 보여주면, 색상만으로 분리한 그래프는 그룹이 사라지고, `style=`을 추가한 그래프는 마커 모양으로 여전히 분리된다.

#### 학생 예상 질문

**Q: 색맹 인구가 정말 그렇게 많은가?**
A: 통계가 보여준다. 남성 8%, 여성 0.5%. 30명 반에 남학생 15명이면 통계적으로 약 1.2명이 영향을 받는다. **"나는 색맹이 아니지만, 내 그래프를 보는 사람이 색맹일 수 있다"**가 핵심 인식이다.

### 2.2 상관 ≠ 인과 (5분)

#### 핵심 메시지

"분석가의 직업윤리. 가장 자주 어기는 원칙."

#### 강조점

- "~때문이다" vs "~와 관련이 있다"의 차이를 칠판에 크게 적는다.
- 아이스크림과 익사 사례를 들려준다. 학생들이 큰 인상을 받는다.
- **언어 표현이 분석의 정확성을 결정한다**는 메시지 — 보고서 작성 시 평생 기억해야 할 원칙.

### 2.3 regplot, pairplot (10분)

#### 강조점

- regplot의 **빨간 회귀선과 신뢰구간**을 시각적으로 강조한다.
- 상관계수 절대값 가이드(<0.3, 0.3~0.7, >0.7)를 외우게 한다.
- pairplot은 **시간이 걸리는 작업**임을 미리 안내한다(셀 실행 시 10초 이상). 학생들이 "버그인가?"라고 오해하지 않도록.

### 2.4 상관 히트맵 + 데이터 누수 (15분)

#### 핵심 메시지

"30초 투자로 30시간을 절약한다."

#### 강조점

- **3가지 위험 신호**를 외우게 한다: 데이터 누수, 다중공선성, 약한 상관.
- **`coolwarm`이 색맹 안전**임을 강조 — 빨강과 파랑은 적록 색맹에게도 구분된다.
- `np.triu`로 상삼각 마스크 적용 — 반복 정보 제거.

#### 학생 예상 질문

**Q: 데이터 누수의 실제 사례는?**
A: 환자 진단 모델에서 "처방받은 약" 컬럼을 입력 특성으로 포함시키는 실수가 대표적. 진단(타겟)을 알아야 처방이 결정되는데, 처방을 입력으로 사용하면 **타겟의 정보가 입력에 새어 들어간 것**이다. Kaggle 경쟁의 상위 솔루션이 무효화된 사례도 다수.

**Q: 다중공선성을 PCA로 해결하는 방법은?**
A: 11~12주차의 차원 축소 단원에서 다룬다. 본 차시에서는 "발견하는 도구가 상관 히트맵"이라는 점만 강조한다.

### 3.3 EDA 5단계 체크리스트 (15분)

#### 핵심 메시지

"AutoML도 EDA부터 시작한다. EDA는 사라지지 않는다."

#### 강조점

- 한 장의 대시보드가 **5개 의사결정**을 만든다는 흐름을 강조.
- `Google AutoML`, `H2O.ai`, `Auto-sklearn` 등 자동 ML 도구도 같은 단계를 수행한다는 사실은 학생들에게 "EDA를 배우는 의미"를 확신시켜준다.

#### 학생 예상 질문

**Q: 자동화된 도구가 다 해주면 우리가 굳이 배워야 하는가?**
A: 자동화 도구는 **체크리스트를 자동 수행**하지만, **결과 해석과 도메인 판단은 사람이 한다**. 예를 들어 "음수 나이"를 결측으로 처리할지 데이터 오류로 제거할지는 도메인 지식이 필요하다. 자동화 도구는 옵션을 제시할 뿐, 결정권자는 분석가이다.

### 4.2 PCA + t-SNE (20분)

#### 핵심 메시지

"우리 눈은 2D만 본다. 그러나 데이터는 수백 차원이다."

#### 강조점

- 64차원 손글씨 데이터를 2D로 시각화하는 시연이 가장 인상적이다. 학생들의 반응을 살핀다.
- **PCA vs t-SNE**의 결정적 차이:
  - PCA: 변환 행렬을 가짐 → 새 데이터에도 적용 가능
  - t-SNE: 변환 행렬 없음 → 시각화 전용, 새 데이터 적용 불가
- **t-SNE 거리는 의미가 없다** — 가장 자주 오해되는 점이므로 강조.

#### 보충 설명 거리

- **UMAP**: t-SNE보다 빠르고 글로벌 구조도 일부 보존. 최신 표준 도구. `pip install umap-learn`.
- **임베딩 시각화 사례**: ChatGPT 토큰 임베딩, 단어 임베딩(Word2Vec), 문장 임베딩(Sentence-BERT). 학생들의 흥미를 자극하기 좋다.

### 4.3 XAI 맛보기 + 마무리 (5분)

#### 핵심 메시지

"본 차시의 도구는 ML 파이프라인 전체에 관통한다."

## **마무리** — 그래프 선택 결정 트리

### 핵심 메시지

"본 차시 전체를 한 장에 압축하면 이 결정 트리이다."

### 강조점

- 결정 트리를 학생들이 직접 따라 그리게 한다. 손으로 그리는 행위가 기억의 단서가 된다.
- **3가지 황금 규칙**을 마지막으로 한 번 더 외친다:
  1. 항상 그래프를 먼저 그려라.
  2. `sns.set_palette("colorblind")`을 첫 셀에.
  3. 상관 ≠ 인과.

### 다음 차시 예고

"오늘 발견한 패턴을 모델로 일반화한다 — 머신러닝 워크플로우 시작."

## **시간 관리 팁**

- **앤스콤 사중주에 너무 많이 머물지 않는다** — 15분 이내 마무리. 도입의 흥미 유발이 목적이다.
- **박스플롯 + 바이올린 = 한 묶음으로** 다룬다. 두 도구의 비교가 핵심.
- **EDA 5단계 체크리스트는 절대 줄이지 않는다** — 본 차시의 종착지이다. 시간이 모자라면 PCA/t-SNE를 줄이고 EDA 5단계를 사수.
- **Plotly와 PCA/t-SNE는 시간이 남으면 깊이, 부족하면 개념만** — 학생들이 "본인이 시도해볼 도구"로 인식하면 충분하다.

## **자주 발생하는 시연 사고 대응**

| 사고 | 원인 | 즉시 대응 |
|---|---|---|
| 한글이 깨짐 | NanumGothic 미설치 | `!apt-get install fonts-nanum` 후 `fm.fontManager.addfont` |
| Plotly 안 보임 | 렌더러 미지정 | `pio.renderers.default = 'colab'` 또는 'notebook' |
| Pairplot이 멈춘 듯 | 정상 — 시간 소요 | 학생에게 "10초 정도 걸린다" 미리 안내 |
| GitHub URL 실패 | 네트워크 일시 장애 | 노트북에 폴백 코드가 자동 발동 — "걱정하지 마세요" |
| t-SNE 너무 느림 | 데이터 1000행 초과 | `n_iter=500` 또는 표본 추출 |

## **수업 후 학생 피드백 회수 항목**

본 차시 종료 후 학생들에게 다음을 묻는다:

1. 가장 인상 깊었던 시각화 도구 1개와 그 이유
2. 가장 어려웠던 개념 (PCA/t-SNE? 데이터 누수? 색맹 팔레트?)
3. 본인의 다음 분석에 적용해볼 것 1개

이 피드백은 다음 학기 강의 개선의 1차 자료가 된다.

> **본 차시의 진짜 목적**: 학생들이 "그래프를 예쁘게 그리는 기술"이 아니라 **"어떤 상황에서 어떤 그래프가 가장 적합한가"**를 판단할 수 있게 만드는 것이다. 도구는 시간이 지나면 잊혀지지만, 판단력은 평생 남는다.
